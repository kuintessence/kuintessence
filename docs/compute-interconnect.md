# 多算力中心互联仪表盘

入口：算力提供方 → 多算力中心互联（`/cp/interconnect`）；平台管理 → 多算力中心互联（`/interconnect`）。

提供者看当前授权组织的资源，组织管理员维护档案；平台运营者跨组织查看，平台管理员维护。
提供者写入必须选定一个有管理权限的组织。链路只有在两端中心均可访问时才展示，跨提供者链路由平台管理员维护。
接口同时遵守本地角色和已启用的 SpiceDB 组织／平台授权，不通过地图泄露其他组织的中心、集群或软件清单。

## 建立资源档案

1. 新增算力中心，选择所属组织，登记名称、国家、省／州、城市、经纬度和状态。标识由系统生成。
2. 在中心下新增集群，登记算力类型、CPU 核心、存储容量和类型；可登记应用软件，并绑定同组织的 Agent。
3. 新增互联链路，选择两端中心，填写实际可获取的网络指标、观测来源与观测时间。

经纬度可以同时留空；未定位中心仍进入统计和明细，通过地图下方“未定位”进入清单。
省级地图使用中国省级名称，如“北京”“广东”（也接受中心档案中的“北京市”“广东省”等后缀）。
中国视图支持国家值“中国”“China”“CN”；其他国家在世界视图展示。
存储表单使用 GiB，接口与数据库使用字节；CPU 数为逻辑集群核心总数，不是 Agent 宿主机核数。
未知容量留空，已知为零时填 0。共享存储应只登记一次，不将同一份物理容量重复填入多个集群。

一个 Agent 只能绑定一个档案集群；多个 Agent 可以属于同一集群，资源只计一次。
档案绑定不改写 Agent 注册信息中的 `siteId`、`clusterId`，不改变现有调度和安装环境。
中心不能跨组织转移，集群只允许在同组织中心之间移动。删除中心前须先移除下属集群和链路；
删除集群只解除档案绑定，不删除 Agent、软件或作业。所有档案写操作留下审计记录。

## 统计与明细

卡片、图表、地图及清单使用同一个事务快照；自动每 30 秒刷新，也可手动刷新。
点击卡片、图表分类或地图标记后，清单显示当前筛选条件。列表可进入中心下属集群、集群资源与 Agent、
软件关联、链路详情；全部地图对象也有列表入口，支持键盘查询。

| 指标 | 计数口径与来源 |
| --- | --- |
| 中心与状态 | 当前权限内登记的中心，按唯一标识计数；状态来自人工档案，更新时间可追溯 |
| CPU／存储 | 按唯一集群的登记容量求和，多个 Agent 不重复计数；缺失数单列，部分已知时总量为已知小计 |
| 算力／存储类型 | 按含该类型的集群数统计；多类型集群会出现在多个分类中，分类不能相加 |
| 应用软件 | 登记软件与绑定 Agent 的已安装软件清单合并，按软件名称去重，版本、多个 Agent 安装不重复计数 |
| 24 小时作业成功率 | 已绑定 Agent 在过去 24 小时内完成数 ÷（完成数＋失败数），取消和未结束作业不计入，无样本显示缺失 |
| Agent 在线健康率 | 已绑定 Agent 中状态为 online 且心跳在 5 分钟内的比例，无绑定显示缺失 |

软件明细按“软件—集群”列出关联，跨集群的同名软件会有多行，同时标注独立软件种数。
人工登记显示“安装状态未验证”；Agent 上报保留上报时间。Agent 改属其他组织后，旧中心不再读取其动态数据；新组织绑定时自动解除失效的旧归属。作业统计只计入作业记录中的提供者与 Agent 当前提供者一致的记录，不把原组织的历史作业带给新组织；历史提供者未知的作业不计入。
旧资源不会仅凭名称或地理位置猜测归属；尚未绑定的 Agent 在档案编辑器中可选，但不计入集群统计。

## 地图与网络状态

地图支持世界、中国、省级切换、拖动、滚轮和按钮缩放。相邻标记按屏幕距离聚合，环图表示中心状态分布，数字为中心数。
点击聚合标记进入同省视图或放大，并列出其中的中心；放大后标记分开，显示单中心及其互联链路。
完全重合的地理位置可能仍聚合，可通过对应清单逐一查询。缩小后的聚合节点不绘制内部或端点尚未展开的链路，链路清单始终可用。

“保存默认视图”将层级、区域、地图中心和缩放保存到服务端，按用户及提供者组织／平台视图隔离；重新进入页面恢复。
保存个人默认视图不需要档案管理权限。地图资源随 Web 离线提供，不向外部地图服务发送算力中心位置。
地图来源及许可见 [`public/maps/README.md`](../packages/web/public/maps/README.md)。省级视图显示省界，不包含市县行政区划。

网络指标支持带宽、吞吐量（Mbps）、时延（ms）、丢包率（%），未知显示“未采集”。
状态或任意指标有值时，必须提供观测时间和来源；不将 Agent 在线等同于链路连通。
超过 5 分钟的链路观测显示未知及虚线，详情保留上次状态和指标，避免把旧数据当作当前值。
当前没有内置跨中心网络探测器；使用者可通过表单登记实际观测，或由现有监控集成调用下列接口更新，系统不虚构网络指标。

## API 与数据库

所有接口要求登录。前缀为 `/api/interconnect/provider` 或 `/api/interconnect/operator`（公开入口沿用平台代理前缀）。
提供者组织选择沿用 `X-KQ-Active-Organization`。

| 方法与后缀 | 用途 |
| --- | --- |
| `GET /snapshot` | 授权范围内的完整快照、可选组织／Agent、个人默认视图及可写状态 |
| `POST /centers`、`PUT /centers/:id` | `{ orgId, metadata }` |
| `POST /clusters`、`PUT /clusters/:id` | `{ centerId, agentIds, metadata }` |
| `POST /links`、`PUT /links/:id` | `{ fromCenterId, toCenterId, metadata }` |
| `DELETE /centers/:id`、`/clusters/:id`、`/links/:id` | 删除档案，中心有依赖时返回 409 |
| `PUT /default-view` | `{ level, region, center: [longitude, latitude], zoom }` |

严格字段、枚举、范围与返回类型见 [共享契约](../packages/shared/src/interconnect.ts)。
网络更新的 PUT 为完整替换，需要保留两端中心及尚未更新的字段；没有提供新观测时，不修改 `observedAt`。

迁移 `0071_colorful_shadowcat` 新增五张表：`compute_centers`、`compute_clusters`、`compute_cluster_agents`、
`compute_interconnects`、`interconnect_map_views`。执行标准 `bun run db:migrate` 后使用；不修改或回填现有业务表。
旧版服务不读取这些表，可保留新表后回退应用版本；不要通过删表撤销已登记数据。

## 验证

- 共享契约：坐标、数值、观测来源、时间、去重与缺失值。
- 路由权限：普通用户拒绝、提供者组织隔离、运营者只读、SpiceDB 拒绝、管理员写入与非法输入。
- PostgreSQL：真实迁移和增删改、跨组织拒绝、并发绑定唯一性、失效归属过滤、个人默认视图。
- 浏览器：使用明确的测试数据验证两个入口、明细筛选、地图切换与默认视图恢复、元数据表单和窄屏布局。

数据库测试要求 `DATABASE_URL` 指向隔离测试库。浏览器测试在 Web 构建后执行
`bunx patchright test -c e2e/interconnect.config.ts`（工作目录 `packages/web`），通过浏览器请求拦截读取构建产物，
不启动应用服务，不访问实际集群。它验证交互与布局，不替代部署环境的真实数据验收。
