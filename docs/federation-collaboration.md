# 联邦协同使用指南

联邦协同（Federation Collaboration）用于独立平台之间的任务委派、资源合作、数据交付和商业对账。用户仍登录所属平台，执行机构保留本地授权和调度权。


## 进入与选择机构

从一级领域栏进入“联邦协同”（路径 `/federation#tasks`），先在页首选择当前机构。全部清单和操作均绑定该机构；同名机构会附带标识用于区分。切换机构或身份会清理当前页面草稿，请先保存需要保留的材料。

宽屏使用模块侧栏，手机从顶部按钮打开抽屉导航；合同子页按合同与履约、账务、争议与终止分组。可使用 Tab 聚焦控件、方向键切换导航。手机端部分商业和管理操作只读，需要在电脑端完成签署或确认。

| 入口 | 用途 |
|---|---|
| 联邦任务 | 提交委派，查询送达与执行状态，取消任务，取回结果 |
| 任务市场 | 查看公开需求、发布需求、按已有私有请求认领及查询交易 |
| 合作协议 | 查看和管理跨机构执行合作，核对双方批准与有效期 |
| 联邦资产 | 导入输入快照、环境锁，登记本地不可变资产映射 |
| 商业合同 | 管理条款、用量、账单、结算、付款、争议及授权政策 |
| 介质交付 | 跟踪加密数据包的交付、导入和回执 |
| 仲裁案件 | 仲裁机构 R 获取受权证据、核对事实、签发及送达裁决 |
| 介质运输 | 管理介质、运输批次与交接记录 |

## 合作模式

由双方协议和部署能力决定模式，不由用户在提交失败后随意切换。

| 模式 | 执行门槛 | 链故障时 |
|---|---|---|
| 直接合作（direct） | 双方有效授权、材料与本地执行条件 | 不依赖 Fabric |
| 异步存证 | 按双边授权执行，存证单独跟踪 | 在协议允许范围内继续执行，恢复后补交原证据 |
| 链上协调 | 按协议完成唯一认领、额度锁定等必要交易，确认 VALID 后执行 | 等待恢复，不降级为直接执行 |

链交易、任务送达、调度执行和财务入账分别记录。链上有凭证不能单独证明计算成功、结果正确或已经付款。

## 科研计算用户：提交与取回结果

提交前请管理员确认：双方执行合作已批准且生效，模板已获授权，输入快照、环境锁与本地映射齐全，目标机构具有可用执行身份、Agent 和调度资源。

1. 在“联邦任务”选择“提交任务”，核对当前机构及执行合作。
2. 选择模板、输入快照和软件环境锁，填写 CPU、内存、GPU、时限及费用上限；不得超过协议范围。
3. 核对确认摘要后提交，保留原任务编号。
4. 分别查看送达和执行状态，留意远端状态的观察时间；需要即时状态时选择“查询执行机构”。
5. 完成后查看授权范围内的结果清单，再确认“取回到云盘”。等待复制、校验和发布可用后下载，按需确认交付回执。

“取消任务”是请求对方永久停止计算，只有对端确认后才表示已停止；取消结果传输不会取消计算。提交或取消响应未知时，先查询原记录，按页面提示恢复原请求，不重新创建一份任务。

新任务表单创建网络交付、不附带仲裁政策的独立委派。需要工作流编排时，在工作流画布添加“联邦委派”，配置合同版本、模板引用、材料摘要、资源、交付方式及所需政策。占位引用必须替换为本站已导入且获授权的原件；复杂输入／输出映射使用连线或 YAML 编辑。其他交付和签名绑定以相应 API、工具及节点支持范围为准。

## 算力中心：准备资源与长期授权

1. 核对双方站点信任、执行合作、资源范围及受限执行身份；只开放约定的队列、额度和有效期。
2. 在“联邦资产 → 输入与环境”导入现有输入快照或环境锁 JSON。检查来源站点、SHA-256 和内容，独立确认后保存。
3. 在“资产映射”登记来源资产的不可变版本、摘要和本地不可变版本，核对实际数据或软件修订。不要使用 `latest`。
4. 在“商业合同”核对条款和双方签署；按授权处理用量报告、账单、结算及实际付款。
5. 长期合作可在合同允许的入口授予有期限、金额和次数上限的自动政策；双方分别授予，撤销只阻止新签署，不抹除历史义务。

材料导入只登记原件；不代表数据已经交付、软件已经安装或已取得使用许可。环境锁中的原生依赖锁必须来自实际环境，不能用模拟锁替代。执行准备仍需要完整 recipe、源码材料、目标 profile、依赖锁及相应执行能力。

任务市场只公开需求摘要和资源要求。价格、合同、材料及个人身份不进入公开目录。认领必须绑定已有私有请求及双方签署的协调合同；认领本身不授予预算或调度权。协调合同的“市场请求”和“自动授权”用于对应授权流程，不属于直接模式的必选步骤。

## 平台管理员：权限、争议与裁决

在“联邦协同 → 管理设置 → 联邦权限”按机构和职责显式授权。平台管理员、组织管理员或算力中心身份不自动取得业务签署权。

| 工作 | 主要权限要求 |
|---|---|
| 准备并提交任务 | `delegation.submit`、`agreement.read`、`asset.read` |
| 查看任务／结果 | `delegation.read`／`result.read` |
| 导入材料、登记或撤销映射 | `asset.map` |
| 发布／认领市场需求 | `market.publish`／`market.claim`；认领另需读取合同 |
| 批准合作或自动授权 | `agreement.approve`；财务批准需独立财务权限 |
| 发起争议／协商和解 | `dispute.open`／`dispute.resolve`；涉及金额另核对财务权限 |
| 批准本站执行裁决 | `arbitration.execute` |

读取的隐含授权、政策签署和 R 权限详见[页面操作与权限](design/federation/web-operations.md)，不能只按此简表推定全部权限。

商业争议从对应的用量、账单、结算、调整或付款原件发起，核对精确编号和摘要后确认。分别检查对方收件、冻结、裁决送达、本站执行和存证进度。收到 R 裁决后，由执行者审阅原裁决及精确金额，再批准本站执行；送达不等于执行，结算也不等于实际付款。

“商业合同 → 仲裁与披露”分别管理仲裁政策、披露政策、单次披露和案件存证授权。不同授权不能相互替代；R 使用独立机构身份，只读取双方批准的限定字段。R 签发裁决和双方执行裁决是独立动作，关闭案件也不会自动结清账目。

双方协商和解可沿用原争议记录办理；永久退出后仍按后台允许的范围结清既有义务。遇到未知响应、待复核或链存证失败，恢复原记录，不以新编号重复签发、扣款或结案。

## 运维：部署和故障分流

- `direct` 交付不依赖 Fabric；`fabric` 交付增加 Peer、Orderer、链码及 Adapter，支持异步存证和链上协调。
- 各站点独立保存身份、数据库、对象存储、软件仓库和密钥。人员会话与机构签名不能互相替代，私钥和密码不放入通用镜像包。
- 分别检查平台登录／授权、机构 Gateway／信任、链健康及交易有效性、Agent／调度执行能力；平台可登录或链正常均不代表作业可运行。
- 沿用离线交付清单核对提交、镜像身份及归档 SHA-256；启动不能临时拉取镜像或下载依赖。AIO 测试调度器是可选组件，不强制加入普通生产部署。

配置、备份与恢复步骤见[联邦部署](../deploy/federation/README.md)、[两种 Compose 交付](../deploy/federation/deployment.md)及[AIO 说明](../deploy/federation/aio/README.md)。协议、任务、交易、文件摘要与账目保留独立业务记录。

## 常见情况

| 情况 | 下一步 |
|---|---|
| 页面无权限或列表为空 | 先核对当前机构、筛选和显式授权，再确认本站是否已有记录 |
| DATA_WAITING | 核对所需数据版本、交付及导入回执、双方使用授权和本地策略；等待数据不计作计算失败 |
| 结果已生成但不能下载 | 检查结果取回是否完成复制、校验并发布可用 |
| 存证待重试 | 查看是否为异步模式，恢复既有存证记录，避免再次执行业务动作 |
| 协调任务等待链确认 | 排查必要交易和 VALID 结果，不切换模式绕过门槛 |
| 材料已导入但任务不能执行 | 检查实际文件、软件安装、目标锁、许可、执行账号及调度能力 |
| 手机没有写入按钮 | 使用电脑端完成受限商业或管理操作 |
