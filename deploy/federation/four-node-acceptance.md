## 修正与限制

试验脚本曾把链码命名为 `evidence`，而 Adapter 调用 `kq-evidence`。已按交付名称注册并保留原交易恢复检查点；错误命名的试验定义不视为验收成果。后续初始化必须核对 Adapter、生命周期命令和已提交定义中的名称一致。

试验签发的 Adapter 证书起始时间曾早于签发 CA，导致 Fabric MSP 验证失败。已保留原密钥及 CA 重签机构叶证书。制备材料应检查叶证书有效区间位于 CA 有效区间内，不能用关闭 MSP/TLS 验证绕过。

Fabric 3.1.5 原生 BFT 追平与双向 TLS 的兼容问题及 `simple` 的边界见[排序节点追平](fabric-evidence.md#fabric-315-排序节点追平)。本轮验证的是停机故障容忍，不包括恶意共识消息、审查攻击或跨地域容灾。

三台机构机仍为 4 GiB，保留内存总保护与单独容器限制。没有因平台启动成功而放宽完整托管配置的容量门槛。科研编译、真实软件安装、跨调度器 Workflow、完整商业与仲裁流程及容量验收仍按各自契约记录。

## 合并与升级

合并候选包含 main 的离线 Slurm 接入、持久作业恢复与输出发布，同时保留联邦执行围栏、软件兼容版本及 worker 停止证明。protobuf 延续 main 的 `total_bytes=6`、`expected_sha256=7`；联邦输入使用字段 8、9。

数据库保留 main 的 0000–0078 迁移，使用生成器从整合 schema 生成 0079；已验证全新建库、从 main 0078 升级、保留原用户记录与重复运行无重复迁移。该路径**不支持直接升级曾使用本分支旧 0073–0205 历史的试验数据库**。原试验库保持原镜像；升级这些库前必须单独核对 schema 和历史并制备基线，不能删库或直接重跑整合迁移。

PR #71 已通过最终静态检查、受影响测试与 CI，合并为 main `90a4eaa`；现有主平台已完成 platform-only 发布。三个 AIO 已完成[保留数据升级](aio/main-upgrade.md)，真实登录和联邦读取通过。main Adapter 的新存证在区块 38 获得原生 `VALID`，原区块 22 交易恢复保持同一 ID；结束时四 Orderer active、高度 39，三 Peer 同高度同摘要。此前的隐私、背书与停机故障证据继续关联原镜像，没有重复执行或扩写为新镜像完整业务验收。
