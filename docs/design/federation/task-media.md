# 任务私有输入与结果的介质交付

本文规定任务介质与现有工作流文件链路的接法。目标仍是来源机构创建加密包、接收机构校验导入、原任务自动恢复并完成结果交付；底层归档测试不能代替这条完整链路。

## 当前实现与缺口

已有网络任务输入来自 `federationWorkflowInputExports` 的不可变快照，绑定 Workflow invocation、文件所有人及对象版本；结果清单来自原执行绑定及已持久化产物。常规网络传输具有独立源授权、接收配额、Agent 复制/校验和原子发布。现有数据集介质导出则只读 `cp-local` 受管目录，任务介质不能伪装成临时公共数据集来绕过这个差异。迁移 0167 已将出口选择器区分为数据集版本/位置与原任务引用，任务源绑定只保存在本站。

2026-11-09 已实现：

- `FederationMediaObjectBindingSchema` 固定包、导出代次、清单摘要、文件序号/路径、大小、SHA-256 和非空、非 `null` 的对象版本。对象键与短期 URL 不进入可携带清单。
- `readFederationMediaObject` 在 Agent 读取获批 HTTPS 对象，使用现有严格 Range 读取器，每个窗口最多 1 MiB。每次响应核对版本，拒绝重定向、非准确范围、压缩响应、截断、额外字节和最终摘要不符。
- 短期 URL 只接受本机配置的存储 origin，许可最多 30 秒且不超过操作期限；临近到期重新领取，读取完强制重新核对授权。等待许可最多 10 秒，读取受许可到期和取消信号约束。空文件同样执行版本化 GET、确认零字节及重新授权，不能用预签名 GET URL 发 HEAD。
- 受管目录与对象流共用 `exportMediaArchiveFromFiles`。归档器只向读取器传递验签清单中的文件，核对准确大小和 SHA-256，保留许可证及完整 provenance；本地文件仍拒绝硬链接、目录内符号链接及读期间变化。

对象读取器仍是内部能力。Server 已接入下述任务包准备、密钥重新授权及 Agent 对象导出命令/下载许可；没有增加可由普通用户传 URL 或磁盘路径的接口。数据集的生产导出入口继续使用受管目录；任务输入/结果仅来源导出已接通，接收发布不能简单删除类型检查后宣称支持。

## 来源清单准备与密钥重新授权

`POST /api/federation/media/exports` 保留原数据集正文，另接受任务正文：

```json
{
  "packageId": "11111111-1111-4111-8111-111111111111",
  "agreementRevisionId": "22222222-2222-4222-8222-222222222222",
  "recipientSiteId": "33333333-3333-4333-8333-333333333333",
  "kind": "task-input",
  "operationId": "44444444-4444-4444-8444-444444444444",
  "agentId": "local-storage-node",
  "expiresAt": "2026-12-01T00:05:00.000Z"
}
```

`kind` 可为 `task-input` 或 `task-result`。字段只选择原任务和本站组织 Agent；不接收调用者提供的 taskId、attempt、文件列表、对象键、版本、下载地址或目标用户。缺少文件的任务不创建空介质包。

输入准备要求原 outbound 已签名接受、没有取消，并重新核对原工作流所有人、运行状态、delegation.submit、输入快照及双方协议；原请求和接单回执重新验签，不能仅信任数据库中的已接受状态。结果准备复用已有结果披露策略、原执行身份、完成工作流和持久产物检查。结果可在计算协议截止后、独立 resultPolicy 截止前交付。两类都要求当前人员 media.export 和当前 Agent 的组织归属。

准备事务先取快照，事务外生成实际 age 包身份并签名，提交事务再次检查；期间文件版本/归属或授权变化不能保存旧批准。存储选择器的互斥约束由 Drizzle 生成的 0167 迁移实现；同一包 ID 只重放原选择器、清单及版本，不能更改期限或换文件。人用 API 保留清单、签名和批准记录，不返回对象键、文件私有 ID、包私钥及其密文。

密钥响应先校验 mTLS 对端和签名查询，再在数据库锁外做需要的资产/链授权预读，事务内复查原批准、任务和文件绑定；重放也复查。批准期限最长七天且不超过业务交付期限；短期解密许可另受当前协议/请求签名密钥及协调模式确认期限限制，不把短期链确认当成整个物流包的有效期。直接合作无需 Fabric，协调模式缺少有效确认时不放行。

对象任务的 `/exports/:id/run` 现已接通下述来源导出。目标任务的对象上传/原子发布和交付方式绑定尚未接通，所以准备成功不等于已生成加密文件，来源导出成功也不等于已解除 DATA_WAITING。

## 必须保持的任务与授权绑定

| 方向 | 源端依据 | 接收端归属 |
| --- | --- | --- |
| 任务输入 | 本站原 outbound、双方协议、原委派请求及 requestDigest、对应 invocation 的输入快照；当前原文件所有权与版本 | 原接单 reservation 的执行身份及 input import；只供该 taskId/attempt |
| 任务结果 | 原 reservation / workflow binding、双方 resultPolicy、真实完成产物及其签名结果清单；当前可交付期限 | 原 outbound 的本地请求人、结果 import 与原 workflow invocation |

输入包的 `contentDigest` 必须等于原委派的 inputFilesDigest；结果包必须绑定接收方验签认可的原结果清单摘要，并核对 template、输入摘要和环境锁。两端机构随方向固定；输出不能被包装成新的输入授权，也不能换 taskId、attempt 或机构复用。包 ID 仍为随机值，不具备授权能力。

操作人员需要 `media.export` / `media.import`，但这些机构权限不隐含读取其他用户私有输入的能力。输入准备还需原文件所有人/原工作流授权；结果提供方需在原协议的明确结果披露范围内操作，结果接收对象从原 outbound 推导，不接受调用者指定任意目标用户。

每次准备、开读、续期、发放解密材料、导入发布都复查原归属与当前授权。接口只接收受控 ID，不接受调用者自报文件列表、摘要、绝对路径、对象键或下载 URL。原始文件已经不存在、版本改变、授权失效时拒绝；不回落到“最新版”或同名文件。

## 存储与数据流

任务成员按已验签清单的原数组顺序编号，以固定 `objects/000000` 等名称进入包，避免不同描述符/输出具有同名相对路径时互相覆盖。原 descriptor/outputId、路径和数组次序由原输入/结果清单恢复；接收方必须用同一清单重新计算成员映射，并逐项核对包内文件。不存在的许可证/provenance 显式保留为 null；已存在的来源元数据不能被丢弃或重新编造。

源 Agent 从本机构对象存储直接按版本读取并流式传入 age，密文写入本机介质 outbox。源端不增加明文整包暂存，也不让 Server 传文件内容。读取器授权回调现由机构内受认证 AgentStream 连接提供，固定原对象版本；普通 HTTP 不返回文件读取许可。

接收 Agent 完成 age 认证和全部文件校验后，文件仍在私有隔离目录。后续由 Agent 将其写入接收方受版本管理的对象存储，复用既有 multipart、代次隔离、容量预留和实际重读校验。导入所有成员完成并重新核对源端许可后，复用原输入/结果 import 的原子发布；不得逐个向用户或作业暴露已复制成员，也不能直接把隔离路径填成普通 netdrive file。

交付方式需持久绑定原任务，使用介质时保持 DATA_WAITING，输入复制 worker 不能同时偷偷启动网络复制，失败也不能自动改成网络交付。数据完成与授权有效同时满足，才解除等待。结果侧同样保留原 invocation 的等待和结果回执，避免“结果已产生”被误认为“结果已收到”。等待交付不是计算失败，也不增加计算用量。

物流、解密许可、任务使用权、结果回执和副本删除仍独立。运输“已收到”不解除等待；原导出批准撤销也不能被运输记录覆盖。真正的任务使用/执行检查沿原委派的持续授权机制处理。副本删除需等持久停止/收尾证据，不能因为介质返还就删除已使用数据。

## 仍需接通的系统组件

- 目标审批服务：来源审批与存储约束已接通；接收端仍需复用原输入/结果导入归属、交付方式和配额，核对任务介质清单。
- 接收侧对象上传/校验/发布：绑定完整任务包、原配额和原输入/结果 import，持久记录代次与方式，处理重复包、取消、撤权、重启和未完成存储清理。
- Web/CLI：在原任务中选择并查看交付，按原记录执行准备、导出、登记、批准、导入与查询；不增加可绕过业务归属的原始 URL 表单。

## Agent 实际来源导出

Server 配置 `FEDERATION_MEDIA_OBJECT_DOWNLOAD_ORIGINS`，源 Agent 在 `AGENT_FEDERATION_MEDIA_EXPORT` 中配置 `allowedSourceOrigins`。两边默认空，不继承网络输入/结果复制设置。生产初始化复用 NetDrive 的 MinIO 后端；Agent 与 Server 新增 `federation_media_object_export_v1` 协商，受管目录命令格式保持兼容。旧 Agent 不接对象任务；未配置允许来源的 Agent 不宣告对象能力。

`/exports/:id/run` 持久排队，沿原 generation、lease、report 通道派发。命令只含固定成员序号/路径、大小、SHA-256、对象版本，不携带源文件 ID 或对象键。Server 对每次逐文件请求复核原任务、当前操作人和 Agent、包/代次/清单/成员，在事务外按原键和版本 HEAD/presign，之后再复查；版本、大小、签名 URL 的版本参数、origin、真实 URL 到期与任务许可均须匹配。连接被替换后不向旧连接返回 URL。

Agent 验签清单后核对完整成员顺序和内容，直接按版本 HTTPS 读取并流式进入 age，源端不落整包明文。完成文件与目录同步后、原子发布前重新授权；错许可、取消或最终撤权不发布完成包。既有完成包的回执摘要额外固定对象版本，恢复或新导出代次复用原密文字节，仍需当前授权。读取实际遵守完整 TLS 信任链，不关闭证书验证。原容量检查、内核工作目录锁和遗留临时目录恢复逻辑继续共用。
