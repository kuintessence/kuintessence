# Kuintessence 算力提供方使用手册

本手册供算力提供方运营人员、管理员和集群管理员使用，说明站点资源管理、巡检、变更与交班操作。

## 1. 职责与权限

算力提供方（Compute Provider）负责将本单位的 HPC 集群、Kubernetes 集群、调度队列、软件环境和数据服务接入平台，并维护已发布资源的可用性。

### 1.1 角色分工

| 人员 | 主要职责 | 不应执行的操作 |
|---|---|---|
| 算力提供方运营人员 | 查看运营概览、用量计量、作业与告警，处理获授权的日常待办 | 修改平台级身份、安全和全局策略 |
| 算力提供方管理员 | 管理本组织用户、执行账号、队列、软件策略、接入代理和数据 | 读取其他算力提供方的业务数据 |
| 集群管理员 | 维护本地调度系统、登录节点、共享存储和接入代理进程 | 绕过平台审批直接扩展用户权限 |

### 1.2 数据范围

算力提供方页面只显示“当前算力组织”的资源。属于多个组织的人员执行审批、策略变更或节点操作前，必须先确认当前组织。

具有 `org_admin` 技术角色的用户，还需具备对应组织的管理成员关系，才能管理该组织。只读运营权限不包含策略修改权限。

## 2. 登录与工作区

1. 使用单位统一身份认证登录平台。
2. 在左侧一级导航选择“算力提供方”。
3. 在当前组织选择器中确认需要管理的算力组织。
4. 根据任务进入“业务运营”或“技术运维”分组。

算力提供方工作区主要包括：

- 业务运营：概览、用量计量、数据、软件、用户、集群账号和审计日志。
- 技术运维：基础设施、接入代理、节点注册和调度队列。

页面提示权限不足时，先检查当前组织和角色；仍无法访问时，请平台管理员核对组织成员关系。

## 3. 运营概览

运营概览每 30 秒更新一次，集中显示最近 24 小时的作业、传输和节点状态。

### 3.1 指标说明

| 指标 | 说明 | 处置建议 |
|---|---|---|
| 已完成作业 | 最近 24 小时正常完成的作业数 | 与业务高峰和历史趋势对照 |
| 失败作业 | 最近 24 小时进入失败终态的作业数 | 进入作业详情查看首个明确错误 |
| 传输量 | 平台文件空间与集群之间的累计传输量 | 异常增长时检查大文件任务和重试 |
| 队列深度峰值 | 统计窗口内观测到的最高排队量 | 结合本地调度系统负载判断是否扩容 |
| 健康节点 | 在线且计算健康状态正常的接入代理数 | 关注持续下降趋势 |
| 异常节点 | 存在计算健康或能力缺项的节点数 | 进入节点页定位原因 |
| 离线节点 | 控制通道超过心跳窗口的节点数 | 检查接入代理服务和网络 |

### 3.2 每日巡检流程

巡检前确认算力组织和当班时段，准备节点与队列清单、最近 24 小时失败作业和传输记录、账号与软件待办，以及正在执行的变更单。确认能访问审计日志。站点命令只在授权终端执行，主机和路径取自站点登记记录。

1. 进入“算力提供方 → 运营概览”，确认组织选择器、时间范围和值班人。
2. 检查离线节点、异常节点和隔离运行环境告警，分别核对控制通道与计算健康。
3. 查看最近 24 小时失败作业、文件传输和未处理操作，按首个明确原因分组。
4. 处理执行账号、预装软件和数据访问待办；审批前核对申请人、组织、用途和有效期。
5. 检查队列状态与深度、软件策略、文件根目录及高频用户/应用用量。
6. 抽查关键变更的审计记录，登记未解决问题、责任人和下一次检查时间。

部分数据源不可用时，页面会保留已获取的数据并显示提示。缺失值不按零统计；请进入对应功能页检查数据源。

记录数据更新时间、节点控制通道与计算健康状态、失败对象编号和首个错误、待办状态及有效期。涉及变更的记录需关联审计编号和变更单。

<a id="failure-handling"></a>

### 3.3 失败、停止与升级

以下为默认阈值；更严格的单位值班制度或服务级别协议优先。

| 情况 | 处理 |
|---|---|
| 心跳超过 5 分钟 | 建立事件工单，检查服务和控制通道；即使页面仍显示在线，也需完成检查后再继续操作 |
| 节点持续异常超过 10 分钟，或 10 分钟内无法确认原因 | 保留节点 ID、心跳和调度器原始状态，升级算力提供方负责人 |
| 申请或未解决问题超过 30 分钟无人接手 | 建立工单并指定责任人；仍在观察的项目 30 分钟后复查 |
| 账号、软件或数据审批异常 | 交资源所有方处理；无法读取申请时，先核对权限 |
| 队列、软件策略或文件根目录变更失败 | 停止继续修改，保留前后值和审计 ID，交算力提供方负责人 |
| 多站点或控制面同时异常 | 通过事件工单和当班值班渠道升级系统运维负责人 |

遇到以下情况应停止操作：无法确认所属组织、审计不可用、数据源失败但页面未标注、生产变更没有审批单，或平台节点及队列状态无法与原生调度系统核对、核对结果不一致。不得手工标记节点“就绪”或直接删除来源不明的原生作业。

## 4. 用量计量

进入“算力提供方 → 用量计量”，查询本组织范围内的资源使用情况。

### 4.1 查询流程

1. 确认当前算力组织。
2. 选择统计周期：原始、按小时、按天或按月。
3. 选择分组维度：用户、组织、集群或应用。
4. 设置起止时间并执行查询。
5. 查看 CPU 核·小时、GPU 小时、内存 MB·小时和作业数。
6. 需要归档或线下分析时，单击“导出 CSV”。

用量计量记录资源使用量，不直接生成财务账单。存储和网络用量以已采集字段为准，不能用未采集字段推算费用。

### 4.2 回调订阅

回调订阅（Webhook）用于向单位内部计费或报表系统发送日汇总、月汇总事件。

1. 填写单位批准的接收地址。
2. 设置签名密钥并选择订阅事件。
3. 创建后在外部系统验证首个测试事件。
4. 连续失败时先停用订阅，排查接收端后再恢复。
5. 不再使用时删除订阅，避免产生无效重试。

## 5. 用户与执行账号

### 5.1 用户管理

“用户”页面用于查看组织成员、状态、配额和可用能力。日常操作遵循以下顺序：

1. 核对用户所属组织和业务身份。
2. 确认用户状态为正常，未处于暂停或过期状态。
3. 按单位制度调整可逆配额或状态。
4. 通过审计日志确认操作结果。

配额、暂停和恢复操作需保留审计记录；使用临时账号验证时，结束后恢复原状态。

### 5.2 集群账号目录

集群账号目录登记可供平台映射的 Unix 或 Kubernetes 执行账号。发布账号前应确认：

- 账号存在于目标集群，且归属用户组正确。
- 账号允许使用的调度队列与平台配置一致。
- 家目录、共享目录和软件环境具备所需权限。
- 账号用途、有效期和是否允许隔离运行环境执行已明确。

已登记账号的调度队列范围通过 `PATCH /api/sandbox/accounts/:id/allowed-queues` 修改，请求体只包含 `allowedQueues`。该操作仅允许账号所属算力组织的管理员执行；平台管理员只有在算力组织已显式 delegation 时才可代管。每次变更都会以 `sandbox.execution-account.allowed-queues.update` 记录变更前后的队列列表。空数组表示不允许提交到任何具名队列，生产账号应显式列出业务队列。

### 5.3 账号映射审批

1. 打开“集群账号”中的待审批映射。
2. 核对申请人、目标接入代理、执行账号和用途。
3. 检查账号的调度队列资格和有效期。
4. 批准或拒绝，并填写可理解的原因。
5. 批准后确认映射状态已生效。

作业提示“没有可用的执行账号映射”时，依次检查映射是否已批准、是否过期、目标节点是否一致、队列是否允许该账号。

## 6. 软件治理

软件策略按算力提供方、集群、接入代理三个层级生效。下级配置可进一步限制软件使用，不能解除上级禁用规则。

### 6.1 策略管理

1. 进入“算力提供方 → 软件”。
2. 选择算力提供方、集群或接入代理层级。
3. 配置安装模式、允许/禁止列表、镜像源和预装软件规则。
4. 使用“可用性预览”查看受影响的软件、用例和节点。
5. 保存后检查页面反馈和操作历史。

### 6.2 软件操作

平台可向在线接入代理下发安装、卸载、加载和导入预装软件等操作。执行前确认控制通道在线；通道断开时，界面会禁用依赖该通道的操作。

批量导入预装软件时，接入代理会逐项检查软件是否存在于本地。管理员确认识别结果后，平台才将其纳入可用性判断。

### 6.3 软件用例准入

软件用例定义软件版本、运行命令、输入输出和资源要求。开放用例前，算力提供方应核对：

- 目标软件在至少一个获准节点上可用。
- 命令模板不依赖未登记的绝对路径。
- 输入输出说明与文件归集规则一致。
- 商业软件许可证和受限材料只保留站点侧引用，不上传正文。

## 7. 数据治理

“数据”页面用于维护算力提供方数据、数据版本和访问申请。

1. 创建数据资产时明确所有者、可见性和用途。
2. 为数据版本填写来源、说明和适用范围。
3. 处理访问申请时核对申请组织、使用目的和有效期。
4. 撤销授权后确认后续新任务不能继续引用该数据。
5. 删除数据前确认归属和引用范围，不连带删除无关资产与文件。

标为 `UNAVAILABLE` 的导入方式尚未接入后端，暂时不能使用。

## 8. 基础设施与接入代理

### 8.1 基础设施总览

“基础设施”汇总接入代理、调度队列、Spack 软件环境、隔离运行环境的安全限制和集群执行账号。进入具体配置前，先从总览确认当前组织和异常数量。

### 8.2 接入代理状态

| 状态 | 含义 | 处理方法 |
|---|---|---|
| 在线 | Server 与接入代理控制通道正常 | 继续检查计算健康状态 |
| 离线 | 心跳超过有效窗口 | 检查服务、证书、网络和 Server 地址 |
| 计算就绪 | 本地调度系统存在可运行资源 | 可继续检查队列和软件 |
| 计算不可用 | 本地调度系统没有可运行资源 | 检查控制节点和计算节点状态 |
| 隔离运行环境严重异常 | 必要隔离条件不满足 | 修复条件前不得开放该能力 |

接入代理在线后，还需依次检查计算健康、队列、执行账号和软件可用性，才能判断集群是否可提交作业。

### 8.3 节点注册

1. 进入“算力提供方 → 节点注册”。
2. 选择当前算力组织，填写接入代理标识、站点名称和调度系统。
3. 核对页面识别的 Server HTTP/gRPC 地址。
4. 签发一次性接入凭证。
5. 在目标登录节点执行页面生成的注册命令。
6. 返回平台确认接入代理出现、证书台账已建立且状态在线。
7. 删除本地命令历史中不再需要的临时凭证信息。

一次性接入凭证只在本次签发面板显示。未使用且不再需要的凭证应及时撤销。

### 8.4 调度队列

调度队列配置把原生调度系统队列映射为平台可调度资源。

1. 选择已注册的接入代理和原生队列。
2. 设置对外名称、可见组织和能力标签。
3. 核对状态、资源限制和执行账号资格。
4. 保存后使用调度选址预览确认候选结果。
5. 禁用队列前检查运行中、已排队和计划任务。

## 9. 文件根目录与 SSH

集群文件根目录限定平台允许浏览和传输的目录。配置时必须使用已存在的绝对目录，并确认接入代理运行用户具备所需读写权限。

SSH 凭据由平台凭据保管库管理。算力提供方只能维护本组织授权节点的凭据，不在页面、工单或脚本中传播密码和私钥。更新凭据后应进行一次短会话验证，并及时退出。

<a id="changes"></a>

## 10. 资源变更、审计与交接

### 10.1 节点、队列和软件变更

1. 在变更单填写目标 Agent、队列、执行账号、软件策略、影响范围、窗口、回滚版本/动作和负责人，由算力提供方负责人批准。
2. 保存策略前运行可用性预览；禁用队列或调整策略前检查运行中、排队中及计划中的任务。
3. 在授权范围内执行变更，保留变更前后配置和审计编号。
4. 依次确认 Agent 在线、计算健康、队列可见性和软件可用性，再验证一项受影响的业务操作。
5. 任一验证失败时暂停后续变更，按批准的恢复方案处理并通知负责人；跨组件发布按[系统运维发布流程](system-operations-manual.md#release)执行。

<a id="handover"></a>

### 10.2 审计与交班

“审计日志”用于查询本组织范围内的管理操作。重要变更至少记录：

- 开始/结束时间及其时区、执行人、当前组织和目标资源。
- 变更前后状态、具体动作、结果、审计 ID、工单和维护窗口。
- 巡检的在线/异常节点数、队列趋势、失败作业/传输编号和审批待办。
- 当前结论、恢复动作、未解决问题、责任人、下一次检查时间和升级渠道。

所有问题处理完毕后标记“巡检完成”；仍有问题时标记“仍在观察”，并向下一班提供编号、操作入口和复查时间。交班时重点说明离线节点、未处理审批、失败软件操作、队列维护和用量异常。记录不得包含密码、Cookie、Bearer token、私钥、完整生产配置或受限数据正文。

## 11. 常见问题

### 11.1 用户能看到节点但不能提交作业

依次检查计算健康状态、调度队列开放范围、执行账号映射、软件可用性和用户组织。不要仅根据“在线”状态判断。

### 11.2 软件操作一直没有结果

检查接入代理控制通道。若操作已创建但连接在派发后断开，先恢复连接并刷新操作历史，再决定是否重试，避免重复执行非幂等操作。

### 11.3 队列有空闲资源但平台未选中

查看作业详情中的调度选址说明。权限、账号、软件、计量或策略阶段均可能在负载判断之前排除该节点。

### 11.4 页面数据突然为空

先确认当前算力组织，再检查页面是否提示部分数据源不可用。空列表不一定表示业务数据为零。

## 12. 推荐工作节奏

### 每周

用量趋势 → 高峰队列 → 软件操作历史 → 执行账号有效期 → 数据授权 → 接入代理版本

### 维护窗口

确认影响范围 → 暂停相关入口 → 执行集群变更 → 验证调度系统 → 验证接入代理 → 最小作业验证 → 恢复入口 → 记录结果
