# OCI内容寻址与仓库隔离

OCI字节和manifest仍按digest去重，但全局digest存在不再代表任意repository可以读取。HEAD/GET blob和按tag/digest读取manifest都必须有持久的仓库归属；授权仍由路由的namespace RBAC执行。

迁移0078通过官方`bun run db:generate`生成三张表：`oci_repository_blob`、`oci_repository_manifest`和一次性回填标记`oci_repository_scope`。应用新代码前必须部署结构迁移；生成命令不执行数据库迁移。

每个repository首次访问在事务内锁repository行、复查持久标记，回填现存tag对应manifest，以及有成功digest-only发布审计且未被后续delete撤销的manifest。只从这些manifest的实际config/layer描述符及在manifest创建前已存在的`oci_blob`元数据回填blob。全局digest、没有来源的孤立blob和旧全局mount日志均不授予权限。事务同时写标记；以后的访问不会因历史tag/audit再次建立已经撤销的归属。无法证明来源的旧孤立内容须在正确仓库重新上传。

新blob上传的元数据、仓库归属及session删除在同一事务提交；PATCH/PUT/DELETE都必须匹配session.repositoryId，错误仓库路径返回BLOB_UPLOAD_UNKNOWN，不能修改原session。存储层在数据库事务之前完成字节promote；数据库事务失败不会授予新归属，保留session供诊断，此时若原存储已移除upload staging，客户端需要重新上传。

新manifest先验证所有blob描述符及子manifest均属于目标仓库，再在一个事务里发布manifest、仓库归属和tag；不可变tag检查在该仓库行锁内进行。显式digest-only发布保存独立归属，不会因没有tag而立即丢失。按digest删除只移除该仓库的tag和manifest归属；其他仓库的引用受保护。

跨仓库mount必须提供可读的source仓库，且source真正拥有该digest。没有from或source不拥有blob时回退普通上传，不允许根据全局存在直接mount；成功后持久记录destination归属。

尚有未回填的旧仓库时，物理prune采取保守保留，避免移除旧digest-only发行。已上传但没有tag引用的blob仍保留其仓库归属，不把“没有tag”当作“没有所有者”。独立Spack材料store仍通过自己的binding/manifest及namespace鉴权读取共享BlobStore；其接口没有改成全局OCI读取，也不据此增加OCI仓库权限。
