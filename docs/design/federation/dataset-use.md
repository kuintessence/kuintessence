# 跨机构数据集使用许可

来源机构现可独立批准某个不可变数据集版本供合作机构计算，并经 mTLS 发放有期限的签名使用凭证。许可与具体介质包分开，因此同一版本重制介质不必复用旧包密钥，也不必把导入批准当成使用批准。直接合作和异步存证都不需要等待 Fabric 才能检查这份许可。

**当前接通来源审批和发放端；接收方续租、Data Market 副本发布、作业使用入口与运行中撤权尚未接通。** 新许可不会自行创建副本、解除 DATA_WAITING、发放下载凭据或启动作业。完整数据交付仍须满足来源使用许可和接收方本地策略两者，详见[介质导入](media-package.md)。

## 来源审批

在既有联邦权限管理中，向本机构真人成员授予独立 `dataset.use.approve`。导出、导入、资产映射和平台管理角色都不隐含这项权限；中英文权限名称和说明已接入现有选择器。

审批人同时必须是版本当前的资产所有者，或资产所属机构的管理者，并通过既有 Data Market `manage` 检查（包括启用 enforce 时的外部鉴权）。通用 manage 授权不能替代资产归属。离开机构、停用账号、撤销能力或失去资产管理权后，原审批不能继续签发使用凭证。机构有该独立能力的其他成员仍能撤销历史审批，避免原审批人离开后无法收回授权。

以下 API 沿用当前组织的人工会话，以 `/api/federation/media` 开头：

| 方法与路径 | 作用 |
| --- | --- |
| `POST /dataset-use-policies` | 明确批准数据版本供指定合作机构使用；要求 `dataset.use.approve` |
| `GET /dataset-use-policies?limit=50&offset=0` | 以 `asset.read` 分页读取本组织审批及撤销历史 |
| `POST /dataset-use-policies/:id/revoke` | 撤销本组织审批；正文为 `reason` |

批准正文示例：

```json
{
  "policyId": "00000000-0000-4000-8000-000000000001",
  "versionId": "00000000-0000-4000-8000-000000000002",
  "recipientSiteId": "00000000-0000-4000-8000-000000000003",
  "agreementRevisionId": "00000000-0000-4000-8000-000000000004",
  "expiresAt": "2027-01-01T00:00:00.000Z",
  "reason": "授权合作机构进行约定科研计算"
}
```

来源站点和组织从本站配置及当前会话确定；数据资产 ID、版本名称和摘要从当前不可变版本读取，不接受调用者自报摘要。协议必须属于当前组织，双方站点必须匹配且处于 active，版本须 published/ready/immutable。许可有效期不超过协议期限；没有额外七天限制，长期合作可明确批准较长期限。

同 policyId 只能重复同一审批人、范围、期限和原因；不会通过重试续期或修改。续期/改变范围须生成新 policyId，并按需要撤销旧许可。撤销保留原始记录，不能重新启用。批准和撤销与审计同事务；审计写入失败不留半成品。

使用许可只针对计算使用，不授予下载、转交或第三方再分发权。受许可材料保留原 entitlement 检查：资产所有权不代替有效使用授权，签发期限也不超过现有 entitlement 期限；撤销 entitlement 后原请求亦拒绝重放。审批不要求重新批准导出；当前适用的 use/download/derive/manage 禁止策略仍会阻止签发。文件披露和每次导入继续走各自独立的授权，不能相互代替。当前只接受有明确用户/机构归属的资产；平台公共资产没有因平台角色而获得隐式跨机构授权。

## 机构间短期使用凭证

来源 Server 在既有专用网关提供 `POST /federation/v1/dataset-use`，请求与响应为 `application/jose`，只经验证的 mTLS 通道接入，不在普通公网用户 API 提供签发入口。启用联邦和本站签名后接通，不需要 age 或 wrapping key。

在两端信任配置中分别明确授权：

- 接收机构签名密钥：`dataset-use-query`。
- 来源机构签名密钥：`dataset-use-grant`。

原 `media-key-query`、`media-key-grant` 或清单签署用途不隐含以上用途。查询绑定双方站点、policyId、协议版本、不可变资产引用，以及接收方 replicaId、Agent 和受管根目录。请求不含真实用户姓名、邮箱或原平台账号；来源依赖对方机构的签名声明，不直接读取对方私有数据库。

来源在发放和原请求重试时复查当前审批、原审批人权限、资产归属、版本摘要、禁止策略、合作协议和签名信任。响应最多 60 秒，同时受查询、政策、协议和双方签名密钥有效期限制。相同 queryId 必须保持同一请求摘要及副本范围，返回原签名且只记一次审计；变更副本、目录、摘要或过期请求被拒绝。收短密钥有效期后，不能通过原响应重放继续使用更长窗口。

短期凭证不是永久许可，也不意味着撤销能瞬时召回已经复制的文件。接收端后续必须将这份许可的截止时间纳入实际数据访问/派发租约；拒绝或不能续期后停止受管使用，并与已有任务终止机制配合。该执行接线仍待完成，当前没有声称能停止运行中的作业。

## 数据与验证

Drizzle 生成迁移 `0161_silly_living_mummy.sql`：保存来源审批和按查询编号固定的签名发放回执，保留组织归属及审计。审批人账号和原因只在来源管理 API/数据库中，不写入对机构签发的使用凭证。当前无历史凭证自动清理；归档/保留期管理仍需随完整联邦治理实现。

隔离 PostgreSQL 测试覆盖独立审批、HTTP 权限/严格正文、重复签名、作用域、撤销、权限变化、资产归属变化、禁止策略、密钥用途/期限、外部鉴权、审计回滚、密钥寿命上限和受许可材料 entitlement。提取了与数据披露共用的资产归属检查，并对原披露管理约束做针对性回归。真实 Node TLS 验证新路径、客户端证书及查询参数拒绝；共享 schema 验证凭证字段绑定。接收方真实作业和完整跨机构数据集使用尚未验收。
