## 1. 系统概述

### 1.1 建设目标

Kuintessence 将 Slurm、OpenPBS、Torque、Kubernetes 等计算资源接入同一平台。科研计算用户可通过 Web、命令行界面（CLI）、终端用户界面（TUI）或本地图形界面（GUI）提交作业、编排工作流、传输文件、选择软件和查看运行状态。

算力提供方负责管理接入代理、调度队列、集群账号、软件策略和用量数据。平台运营人员查看授权、审计和运行告警，协调处理异常。

### 1.2 主要功能

| 功能域 | 主要能力 |
|---|---|
| 计算与编排 | 算力节点浏览、作业提交、状态跟踪、日志查看、取消、工作流编排 |
| 数据与文件 | 平台文件空间（NetDrive）、集群目录浏览、双向传输、配额申请、作业文件 |
| 数据市场 | 数据目录、私有数据、受限数据访问申请与授权状态 |
| 软件生态 | 工作流模板、软件用例、Spack 软件、受管数据处理脚本 |
| 多端访问 | Web、`kq` CLI、OpenTUI、免 Server 本地 GUI、外部接入代理模式 |

### 1.3 使用边界

- 平台只展示当前用户有权访问的资源；菜单不可见通常表示尚未获得对应角色或组织授权。
- 作业是否能够运行取决于软件可用性、队列授权、集群账号映射、资源余量和算力提供方策略。
- 隔离运行环境（Sandbox）仅开放已验证的调度系统与执行模式组合，尚未作为正式可用（GA）能力提供。
- Parquet 导出、完整源码镜像任务和离线包执行器仍在规划中，当前不可用。

## 2. 角色与权限

平台同时使用技术角色和组织业务身份。技术角色决定平台级权限，组织身份决定用户在具体算力组织中的职责。

- 访客可浏览公开软件和数据目录；已授权用户可使用作业、工作流、文件及个人设置。
- 同一用户可以属于多个组织，操作前确认当前组织和资源可见范围。
- 软件发布、组织管理和平台管理需要单独授权。
- `operator` 与 `org_admin` 是并行授权分支，不互相继承；访问资源时还会由后端校验权限。

管理侧职责见[算力提供方手册](compute-provider-manual.md)、
[平台运营手册](platform-operator-manual.md)和[系统运维手册](system-operations-manual.md)。

## 3. 访问平台

### 3.1 浏览器要求

建议使用近两个主要版本的 Chrome、Edge 或 Firefox，桌面分辨率建议不低于 1366×768。浏览器需要允许同站 Cookie、JavaScript 和 WebSocket。使用单位代理或堡垒机时，应确保平台入口、OIDC 回调和文件下载地址可达。

### 3.2 登录流程

1. 在浏览器中打开管理员提供的平台地址。
2. 在登录页单击“使用统一身份认证登录”。
3. 在统一身份认证页面输入单位账号和密码。
4. 认证成功后，浏览器返回 Kuintessence 工作台。
5. 首次登录若没有组织或角色，请联系组织管理员完成授权。

> 不要在共享终端或脚本中保存 Web 登录密码。CLI 登录使用浏览器 OIDC 流程，配置文件由客户端以仅当前用户可读的权限保存。

### 3.3 退出登录

1. 单击页面右上角用户头像。
2. 进入“个人中心 → 账户与会话”，或直接选择退出入口。
3. 单击“退出登录”。
4. 在公共计算机上使用时，建议同时关闭浏览器窗口。

退出后，原会话不能继续访问受保护页面。若浏览器仍显示旧页面，刷新后应返回登录页。

## 4. 工作台与全局导航

### 4.1 页面组成

Web 页面主要分为三部分：

1. 左侧一级导航：我的工作台、算力提供方、平台管理、软件生态、个人中心。
2. 左侧二级导航：随一级工作区变化，显示当前角色可用的具体功能。
3. 主工作区：显示列表、表单、图表、详情和操作反馈。

顶部“提交”按钮提供常用提交入口；右上角用户区域用于查看身份和退出登录。

### 4.2 工作台概览

工作台展示当前可见范围内的活跃作业、运行中工作流、在线算力节点、24 小时提交趋势和最近动态。页面默认定时刷新，用户也可以手动刷新。

各项指标含义如下：

- 活跃作业：处于待处理、已排队或运行中状态的作业数。
- 运行中工作流：尚未进入终态的工作流数量。
- 在线节点：已注册且心跳正常的接入代理数量。
- 提交量 / 24h：统计最近 24 小时的提交次数。
- 最近动态：当前角色有权限查看的审计与业务事件。

## 5. 查看算力节点

进入“我的工作台 → 节点”，可以查看当前可见的算力节点。每张节点卡片显示调度系统类型和版本、CPU/内存、计算健康状态、队列深度和最近心跳时间。

### 5.1 状态判断

| 字段 | 说明 |
|---|---|
| 在线 | Server 与接入代理控制通道正常，最近心跳在有效窗口内 |
| 计算健康状态 | 调度系统是否具备可用执行资源，显示就绪数量 |
| 队列深度 | 接入代理当前观测到的待执行或运行任务数量 |
| CPU/内存 | 接入代理最近一次资源监控数据 |

“在线”只表示控制通道正常；提交前仍应检查“计算健康状态”和调度队列。如果节点在线但计算健康状态为严重异常，作业可能无法完成调度选址。

### 5.2 常用操作

- 单击“查看此节点上的作业”筛选该节点上的作业。
- 有 `terminal.open` 权限时，可单击“打开 SSH”进入受控终端。
- SSH 入口不可见时，表示当前身份或组织没有该节点的终端权限。

## 6. 作业管理

### 6.1 作业列表

进入“我的工作台 → 作业”。列表支持按名称或 ID 搜索，并按状态筛选。平台管理员可根据授权切换可见范围；普通用户只看到本人或授权范围内的作业。

常见状态如下：

| 状态 | 含义 |
|---|---|
| 待处理（Pending） | 已接收，正在校验、选址或等待派发 |
| 已排队（Queued） | 调度系统已接收，正在排队 |
| 运行中（Running） | 已在计算节点运行 |
| 已完成（Completed） | 正常完成 |
| 已失败（Failed） | 校验、选址、派发、调度系统或程序执行失败 |
| 已取消（Cancelled） | 用户或管理员已取消 |

### 6.2 提交作业

1. 单击“提交作业”。
2. 选择提交方式：
   - `Usecase`（软件用例）：从软件生态选择受管软件用例，适合常规科研任务。
   - `Command`（直接命令）：直接填写命令，适合熟悉运行环境的用户。
3. 填写作业名称、CPU 数和内存。
4. 选择队列。使用“自动选址”时，平台根据权限、软件、资源和策略选择节点。
5. 展开“选址预览”，检查可选节点和被排除原因。
6. 确认配置后单击“提交”。

提交前建议：

- 作业名称应能反映课题、数据批次或计算阶段。
- CPU、内存和最长运行时间（walltime）不应明显超过实际需要。
- 使用软件用例时先确认软件授权与可用节点。
- 对输入输出文件较多的任务，优先使用工作流管理文件和依赖关系。

### 6.3 查看详情

单击作业名称进入详情页。详情通常包括：

- 提交人、组织、接入代理、调度系统作业编号和调度选址结果。
- 命令、资源请求、队列、节点、起止时间和退出码。
- 实时状态、日志、输出文件和最终结果。
- 选址过程中每个阶段的通过或拒绝原因。

作业概览显示调度器分配的执行节点和调度原因，可用于判断作业在等待资源、运行中还是被拒绝。失败时，查看异常详情、可用的 exit code 和日志排查建议。历史作业未保存失败原因时，会在 `Failed` 状态旁注明“未记录具体原因”。

日志显示“不可用”时，先确认调度系统是否仍保留历史输出。日志读取失败会单独提示，不显示为空日志。

### 6.4 取消作业

1. 打开待处理、已排队或运行中的作业详情。
2. 单击“取消”。
3. 确认后等待状态变为“已取消”。

取消请求需要经过 Server、接入代理和调度系统。界面显示“取消中”时不要重复提交；若长时间没有变化，请记录作业编号，联系运营人员检查取消请求。

## 7. 工作流管理

### 7.1 工作流列表

进入“我的工作台 → 工作流”。页面汇总活跃、完成、失败和已取消数量，并支持搜索和状态筛选。

单击记录可查看执行图、节点状态、输出值和关联作业。工作流失败时，页面列出失败节点、原因、exit code 和关联作业入口；ForEach/While 标出失败的迭代与内部节点，SubWorkflow 标出失败的内部节点。先定位第一个失败节点，再查看关联作业日志或输入文件状态。

### 7.2 新建工作流

单击“新建工作流”，系统提供两种起点：

- 从头构建：自定义流程。
- 选择模板：选择软件生态中的工作流模板，再调整节点与参数。

### 7.3 四步配置流程

#### 第一步：工作流编辑

从左侧节点面板拖拽节点到画布，并通过端口连接依赖关系。常用节点包括：

| 节点 | 用途 |
|---|---|
| 用例计算 | 运行受管软件用例 |
| 数据转换脚本 | 执行受管的数据预处理或后处理脚本 |
| 空节点 | 透传、汇聚或表达依赖关系 |
| 分支 | 根据 CEL 表达式选择后续路径 |
| 循环 | 有界 While 或 ForEach 循环 |
| 里程碑 | 通知或检查点 |
| 子工作流 | 复用内联或引用的工作流 |

选中节点后，在右侧“节点属性”中配置参数。使用“格式美化”整理布局，也可导入或复制 YAML 检查配置。不要在 YAML 中写入密码或访问凭据。

#### 第二步：输入文件和参数

集中填写工作流所需的文件、参数、数组或批量扫描值。文件应选择已有平台文件空间对象、数据市场授权数据或明确允许的集群路径。

#### 第三步：算力资源

为计算节点设置 CPU、内存、最长运行时间（walltime）、队列和调度偏好。跨调度系统运行时，逐个检查节点所需的软件是否可用、数据是否可访问。

#### 第四步：预览并提交

检查节点数量、连线、输入、资源和选址提示。提交后进入运行详情，页面根据持久化执行图显示每个节点的实时状态。

### 7.4 失败处理

1. 查看失败节点及其错误信息。
2. 打开关联作业，检查调度选址、调度系统状态和日志。
3. 检查输入文件是否存在、授权是否有效、软件是否可用。
4. 修正工作流后重新提交，不要直接修改已结束的运行记录。

## 8. 文件与平台文件空间（NetDrive）

### 8.1 页面说明

进入“我的工作台 → 文件”。左侧是平台文件空间（NetDrive），右侧是当前选择的集群文件根目录，下方是传输记录。

### 8.2 上传到平台文件空间

1. 在左侧确认上传前缀。
2. 单击上传图标并选择本地文件。
3. 大文件由浏览器使用分段上传。
4. 上传完成后，文件会出现在当前平台文件空间目录中。

上传前应检查存储配额。配额不足时，单击“申请配额”，填写用途和期限，由管理员审批。

### 8.3 平台文件空间与集群双向传输

单击“新建传输”，选择方向：

- 平台文件空间 → 集群：将平台文件传入集群目录。
- 集群 → 平台文件空间：将集群文件归集到平台文件空间。

操作步骤：

1. 选择方向。
2. 选择源文件。
3. 选择执行集群。
4. 通过路径选择器选择目标目录，目标必须位于管理员配置的授权根目录内。
5. 检查“提交前确认”中的方向、源文件、集群和最终路径。
6. 单击“开始传输”。

传输由接入代理执行，刷新页面不会中断传输。在“最近传输”中可查看已排队、运行中、已完成、已失败或已取消状态。失败时按记录中的建议处理；确认源和目标仍可用后再重试。需要进一步排查时，请管理员查看平台日志和审计中的原始诊断。

### 8.4 使用注意事项

- 不要手工输入未授权的顶层路径，优先使用路径选择器。
- 从平台文件空间传入集群时，目标目录必须可写。
- 从集群归集到平台文件空间时，源必须是当前可读的普通文件。
- 删除平台文件前，应确认没有工作流、数据资产或下载任务继续引用该文件。
- 作业文件中“未归集到输出”和“文件接口失败”是不同状态，应按页面提示处理。

## 9. 数据市场

进入“我的工作台 → 数据市场”。页面分为数据目录、我的私有数据和数据来源选择区。

### 9.1 浏览和申请数据

1. 在“数据目录”按名称或标签搜索。
2. 打开数据详情，查看版本、用途、授权要求和访问状态。
3. 对受限数据单击“申请访问”，填写用途。
4. 等待数据所有者或平台管理员审批。
5. 授权生效后，在工作流或数据来源选择器中使用该版本。

状态为“待审批”表示等待处理，“有效”表示授权可用，“无效”表示已撤销或到期。API 中分别对应 `pending`、`active` 和 `inactive`。授权失效后，平台不会继续把该数据显示为可用输入。

### 9.2 创建私有数据

1. 切换到“我的私有数据”。
2. 填写数据名称和版本。
3. 选择科学数据集或受限材料类型。
4. 从本地、平台文件空间或数据市场选择来源。
5. 上传并等待版本创建完成。

私有数据默认归当前用户所有。组织共享或发布需按单位数据治理流程获得授权，不得通过修改 URL 或跨组织引用使用未授权数据。

## 10. 软件生态

进入“软件生态”，选择工作流模板、软件用例、Spack 软件或数据处理脚本。左侧导航与页面标签页同步切换，并在 URL 中保留当前栏目。打开详情、新建或权限提示页后，左侧仍显示当前资产类别；返回时回到对应目录。

### 10.1 工作流模板

工作流模板可复用已有流程。打开模板详情，检查节点、输入和适用环境，再单击使用入口，进入工作流编辑器填写本次运行参数。

已发布模板不可修改或删除。发布者编辑模板时需使用新版本号；旧版本保留，供已有子工作流和历史运行继续引用。

### 10.2 软件用例

软件用例定义软件版本、运行命令、参数、输入输出和资源要求。提交作业或编排工作流时，优先选择已发布且当前用户可用的用例。

### 10.3 Spack 软件

Spack 目录用于查询软件配方（recipe）、版本和变体（variant）。目录中“可发现”不等于已经在目标节点安装。使用前查看可用性：

- 已安装（Installed）：目标节点已安装。
- 可安装（Installable）：符合策略，可以申请或执行安装。
- 已阻止（Blocked）：被授权、软件策略、节点在线状态或安装模式阻止。

需要安装时单击“申请安装”，由算力提供方按策略处理。

### 10.4 数据处理脚本

受管脚本用于工作流中的数据转换。目标算力提供方绑定获批运行环境后，才能提交脚本；未绑定时仅可浏览。

### 10.5 软件发布人员

具有发布权限的用户可以提交草稿、发起审核、查看审批状态并发布新版本。发布时应填写清晰的名称、版本、说明、输入输出和适用调度系统，不要上传许可证文件、商业软件包或受限材料正文。

## 11. 个人中心

### 11.1 账户与会话

“个人中心 → 账户与会话”显示当前登录身份、技术角色和会话剩余时间。

角色与预期不一致时，先退出并重新登录；若仍不一致，请联系管理员检查身份提供方用户组映射和平台用户状态。

### 11.2 执行账号

“执行账号”显示当前用户可使用的集群 Unix/Kubernetes 身份、映射状态和队列资格。选择站点和已发布账号后提交映射申请，批准后可使用；有多个已批准映射时可设置默认项。仅已发布的账号可申请映射，候选为空时请联系算力提供方。

### 11.3 外观与界面

用户可以设置语言、主题和显示偏好。外观设置不会改变权限或数据范围。

## 12. 客户端入口

Web 适合可视化管理和复杂表单；CLI 适合脚本化；TUI 适合 SSH 登录节点；免 Server 本地 GUI 适合不接入中央 Server 的本地调度系统场景。

<a id="cli"></a>

### 12.1 CLI 基本流程

```bash
kq login --server https://<平台地址>
kq agent list
kq list
kq submit docs/manuals/examples/job-smoke.json
kq status <job-id>
kq logs <job-id>
kq cancel <job-id>
```

远程 `kq submit` 的参数是一个 JSON spec 文件，不接受 `--agent` 或 `--command` 选项。上例从仓库根目录执行，使用[最小作业 spec](examples/job-smoke.json)；提交成功时输出 `Job submitted: <唯一的 Job ID>`，再把该 ID 交给 `kq status` 和 `kq logs`。只在确需取消时执行 `kq cancel`。CLI 配置默认位于 `~/.kq/config.json`，权限应为 `0600`。正式环境优先使用 `kq login` 的 OIDC 流程，不在命令行历史中填写 token。

常用命令族：

| 命令 | 用途 |
|---|---|
| `kq workflow` | 工作流提交、列表和状态 |
| `kq software` | 软件目录和可用性 |
| `kq metering` | 计量查询与导出 |
| `kq dsl` | 工作流 schema 和校验 |
| `kq agent` | 接入代理查询和外部接入代理服务 |
| `kq ssh` | 通过 Server SSH 网关打开会话 |

### 12.2 TUI 与本地 GUI

- [TUI](../clients.md#tui)：远程 Server、本地调度器、外部 Agent、键位和日志。
- [GUI](../clients.md#gui)：浏览器 SPA、内嵌 SPA 与 Tauri 桌面壳。
- [本地工作流](../clients.md#local-workflows)：数据目录、示例、文件暂存和执行限制。

本地模式沿用登录节点 shell 权限，不获得 Server 的组织治理、NetDrive 或 Web 终端能力。

## 13. 状态说明与常见问题

### 13.1 页面显示空数据

先区分以下情况：

- 页面明确显示“0 项”或“暂无数据”：请求成功，当前范围确实为空。
- 页面显示权限不足：当前角色或组织不具备读取权限。
- 页面显示加载失败或重试：接口、网络或上游服务异常，不应按空数据处理。

### 13.2 页面显示权限或服务提示

页面保留当前作业的科学程序错误、scheduler 拒绝原因和 exit code，供用户修正输入或资源配置。后端错误代码、内部异常、HTTP 细节和 stack 不直接显示。常见提示的处理方式如下：

- 登录状态已失效：重新登录后回到原操作。
- 当前账号没有权限：确认当前组织是否正确；仍无法操作时联系组织管理员申请相应角色、资源或软件权限。
- 资源不存在、已删除或当前不可见：刷新列表并从可见目录重新进入，避免继续使用旧链接。
- 资源状态已变化：刷新详情后重新确认当前状态，再执行操作。
- 平台服务暂时不可用或操作过于频繁：稍后重试；持续出现时向管理员说明操作时间、页面和资源名称。

YAML、JSON、参数和表单校验会指出错误字段或位置。程序执行失败时，结合退出码、作业日志和输出状态排查；平台服务异常则按服务提示处理。

### 13.3 登录后菜单缺失

1. 打开“个人中心 → 账户与会话”确认角色。
2. 退出后重新登录，确保身份提供方用户组已刷新。
3. 多组织用户确认当前组织。
4. 联系管理员检查组织成员关系和 `/me/capabilities`。

### 13.4 作业一直处于待处理状态

检查：

- 是否有满足要求的在线且计算就绪节点。
- 软件或软件用例是否在目标节点可用。
- 是否具备队列和集群账号映射。
- CPU、内存、最长运行时间是否超过队列或平台上限。
- 调度选址详情是否给出明确拒绝原因。

### 13.5 作业已完成但没有输出

1. 检查作业日志和退出码。
2. 检查工作流或软件用例的输出描述。
3. 确认输出路径位于允许收集的工作目录。
4. 检查平台文件空间和对象存储是否可用。
5. 区分“程序没有生成匹配文件”和“输出收集失败”。

### 13.6 文件传输失败

- 源文件不存在：刷新目录并重新选择。
- 目标目录不可写：选择授权根目录下的可写目录。
- 平台文件不可用：确认对象未删除且属于当前用户。
- Server 重启中断：源和目标仍可用时按页面提示重试。
- 配额不足：申请临时或长期配额。

### 13.7 节点在线但不能提交

在线只表示接入代理控制通道正常。继续检查计算健康状态、调度队列、软件可用性、账号映射和隔离运行环境就绪状态。

### 13.8 问题反馈信息

提交工单时建议提供：

- 操作时间和所在时区。
- 当前页面和操作步骤。
- 作业编号、工作流运行编号、接入代理编号或传输编号。
- 页面提示或错误信息。
- 是否可以稳定复现。

不要在工单中提供密码、Cookie、Bearer token、私钥、受限材料正文或完整生产配置。

## 14. 提交与结果确认流程

### 14.1 前置条件与执行

提交前确认账号和组织授权、目标节点/队列、软件用例或命令、输入版本、CPU/内存/walltime 和输出路径。按任务要求检查数据授权、许可证和 Sandbox 状态；配置或授权信息不全时，先补齐再提交。

1. 在“个人中心 → 账户与会话”确认角色、组织和会话。
2. 检查节点心跳、计算健康和队列；核对软件版本、授权、工作目录及输入来源。
3. 从“我的工作台 → 作业 → 提交作业”或“工作流 → 新建工作流”进入，预览权限、执行账号与选址；至少有一个允许的候选才能提交。
4. 提交一次，记录返回的唯一作业 ID 或工作流运行 ID，并用该 ID 查询结果。CLI 按第 12.1 节提交 JSON spec；刷新页面不会确认是否已重复提交。
5. 每 5 分钟查看状态、日志和输出，直到明确终态或达到停止条件。
6. 完成后核对退出码、输出描述、路径和文件完整性，再归档结果或交接。

<a id="failure-handling"></a>

### 14.2 失败、停止与升级

按以下默认阈值安排排查；单位制度或服务级别协议更严格时，按其执行。

| 情况 | 处理 |
|---|---|
| 预览 60 秒仍无结果，或预检查失败 | 停止提交；按权限、队列、软件、数据或资源原因修正后重新预览 |
| 提交返回非零、HTTP 4xx/5xx、校验错误或无唯一 ID | 停止重试，保留返回码、首个错误和 spec 版本 |
| 提交后 5 分钟无状态变化，或待处理超过 15 分钟 | 保留已有编号和选址详情，交算力提供方值班人员核对；不重复提交 |
| 已完成但输出缺失或不完整 | 停止归档，核对输出描述、路径、文件传输和对象存储，先建工单 |
| 日志读取失败 | 记录为读取异常，不记为“空日志” |

没有候选节点、授权范围不明、输入版本无法确认，或诊断中含有凭据或受限数据时，停止操作并联系责任方。不得用普通命令绕过 Sandbox、队列或组织权限。作业、选址、队列和执行账号问题交算力提供方；认证、授权或 API 问题交平台运营人员分派。后续通过事件工单和当班值班渠道跟进。

<a id="handover"></a>

### 14.3 结果与交接

在任务记录或工单中写明组织、节点/队列、作业或运行 ID、提交时间及时区、输入/spec 版本、预览结果、最终状态、退出码和输出完整性检查结果。失败时补充首个错误及修正动作；尚未结束时，写明责任人、下次检查时间、工单编号和所需权限。只附排查所需的诊断信息，不附密码、Cookie、token、私钥、完整生产配置或受限数据正文。
