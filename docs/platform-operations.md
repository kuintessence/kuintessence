# 平台运营与算力中心

平台运营者在平台工作区统一处理各算力中心的资源；算力中心在本单位工作区处理所属资源。两者复用相同的执行账号、队列和软件管理组件与服务，权限由服务端判定。

| 工作 | 平台运营者 | 算力中心 | 平台管理员 |
| --- | --- | --- | --- |
| 运营资料、算力中心和集群元数据 | 全局维护 | 所属资源；运营资料仅修改自身 | 全局维护 |
| 接入代理注册、证书和队列 | 跨算力中心管理 | 所属算力中心 | 全局管理 |
| 执行账号、允许队列、启停、映射审批 | 跨算力中心管理，无需算力中心委托 | 所属算力中心 | 全局管理 |
| 软件安装策略、软件操作、运行时与材料绑定 | 跨算力中心管理，遵守软件及材料策略 | 所属算力中心 | 全局管理 |
| 平台用户 | 查询、按算力中心筛选，启停较低权限账号 | 保持成员查询；不能停用全局用户 | 启停较低权限账号 |
| 系统认证、SSO、安全策略、管理员角色 | 不授予 | 不授予 | 保持原权限 |
| 算力中心数据资产 | 仍需算力中心成员权限 | 所属算力中心 | 保持原权限 |

## 页面与范围

平台运营侧使用 `/operations` 的总览及 `#clusters`、`#queues`、`#accounts`、`#software`、`#users`。资源归属和算力中心筛选在页面内可见，选择“全部可用组织”时汇总全局；算力中心和集群元数据继续在“算网一览”编辑。代理数按接入代理记录计数，不能等同于物理集群数量。

新建执行账号需先选定算力中心；已有账号可直接从全局列表修改允许队列或启停。停用执行账号阻止后续使用该身份，不宣称终止已经运行的集群作业。移动端保留查看和审批，沿用高风险修改需桌面端的限制。

平台用户的停用和启用必须填写原因并记录审计。停用时撤销现有浏览器/CLI 会话，已有访问令牌和新会话也检查停用状态；恢复账号不会恢复已撤销会话，用户需重新登录。不能操作自身、同级或更高权限账号；角色提权和身份源用户创建仍由原系统管理入口负责。旧 `/cp/users/*` 全局停用/配额写入接口继续关闭。

VASP POTCAR 本地材料登记需从已发布软件中选择关联资产；未导入相应软件发布包时不可登记。页面传递资产标识，由 Registry 校验当前生效发布包及许可证。

## 权限实施

- 运营权限 `workspace.platform.operate` 面向 `operator`、`platform_admin`、`super_admin`；系统管理仍使用 `workspace.platform.manage`，不修改角色继承关系。
- 本地、shadow、enforce 模式同时支持运营权限。enforce 使用 `platform:root#operate` 及具体资源权限；运营者不享有授权服务异常时的管理员降级放行。
- SpiceDB 的代理、队列和软件资源支持平台运营。`provider.manage` 与组织成员关系不扩大，防止把运维权限传播为算力中心数据资产权限。
- 旧执行账号委托记录保留兼容，但平台运营权限不再依赖该记录。算力中心自身仍需 owner/admin 身份。
- 部署需同步更新 Server、Web、Registry 和 `authz/schema.zed`。
