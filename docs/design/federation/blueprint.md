# KQ 算力联邦完整方案 V2：双边直连、异步存证与链上协调

日期：2026-11-06。设计目标，尚未实现或部署。本文定义完整业务范围，不按阶段拆分；具体代码接入与修正见 [实现方案](implementation.md)，可行性与风险见 [评估](assessment.md)，发布门槛见 [验收契约](acceptance.md)。

## 1. 核心决策

**一个联邦执行体系，三种协议模式；Fabric 是可选的共同账本能力，长期合作不必逐任务等待链。**

1. `bilateral_direct`：双边直接协作。双方通过机构认证、长期授权、私有额度账本和签名回执自动委派；不要求部署 Peer，不产生上链任务。
2. `bilateral_attested`：双边协作＋异步上链存证。任务执行与业务对账按双边协议完成，证据可靠保存后排队，独立提交 Fabric；链故障不成为正常执行路径上的等待条件。
3. `ledger_coordinated`：链上协调。适用于联盟任务市场、共同认领、以链上额度为权威的业务；认领、私有锁额和激活取得有效提交后才能执行。

模式由双方签署的合作协议明确约定，不能由单方在故障时切换。原有私有字段约束保留：价格、用量、合同及余额只交给指定机构；凡进入 Fabric 的商业记录均使用 PDC 和机构背书策略。双边模式以双方签名和各自存储保证，不冒充已经完成 Fabric 背书验证。

## 2. 三种模式的权威与故障边界

| 事项 | 双边直接 | 双边＋异步存证 | 链上协调 |
| --- | --- | --- | --- |
| 接单依据 | 有效长期授权＋B 签名接单回执 | 同直接模式 | 公共认领、私有锁额/许可、公共激活 VALID |
| 业务额度权威 | 协议指定的双边额度账本 | 双边额度账本；链只记录凭证 | 对应合作域的 Fabric 私有额度账本 |
| 机构一致性依据 | 双方版本化协议、签名请求与回执 | 双方签名；有效上链后增加共同存证 | 原生背书及提交验证，另有业务批准 |
| 任务是否等待链 | 不等待，不调用链 | 不等待；本地证据必须持久化 | 等待必要的 VALID 提交 |
| 链断开时 | 不受影响 | 继续执行，存证排队重试 | 暂停新的链依赖激活/结算；既有授权内任务可继续 |
| 账单已双方接受但链未恢复 | 双边账单已确认 | 双边账单已确认，显示“待存证” | 按链上商业状态处理，不能假报链上结算完成 |
| 存证积压 | 不适用 | 有限容量、告警、补交和人工核对 | 交易/事件待核对，不直接重派 |
| 公开市场唯一认领 | 不提供联盟全局保证 | 不提供联盟全局保证 | 由共同账本和状态机保证 |
| 科研结果正确性 | 由约定验收检查 | 同左；上链不改变这一点 | 同左；背书不证明科学正确性 |

双边模式中的执行方 B 可以可靠防止同一请求在 B 重复执行；它不能阻止恶意需求方 A 把不同请求同时交给不知情的 C。若业务需要跨机构共同认领和全局额度约束，应明确选择链上协调，不能依赖异步存证事后追溯来替代事前控制。

## 3. 总体架构与技术栈

用户 → 所属机构 KQ → 联邦策略与协议引擎 → 机构间 HTTPS/mTLS → 执行机构 KQ → Agent → Slurm/PBS/Torque/Kubernetes。

这条任务通道三种模式共用。模式影响授权与账本门槛，不复制三套调度器、工作流或文件系统。

异步存证旁路：本地签名证据＋outbox → 周期性证据批次 → Node Fabric Adapter → 本机构 Peer Gateway → 指定成员 PDC → VALID 回执。

链上协调路径：Fabric 公共需求/认领＋私有许可/额度 → 有效激活 → 共用的联邦任务通道。

数据通道独立：源端云盘/Agent → 网络或加密介质 → 目标云盘/Agent。大文件不经链或 Server 中转。

| 组件 | 技术选择与职责 |
| --- | --- |
| KQ 主体 | 现有 Bun/Hono/Zod/PostgreSQL/Drizzle，管理协议、审批、执行、投影及可靠队列 |
| 联邦认证 | 机构独立 X.509 信任、mTLS；请求与回执使用 JWS/RS256，复用现有 jose 能力 |
| 链 | Fabric 3.x、MSP、显式 PDC、组织背书；仅启用链能力的机构参与 |
| 链接入 | 独立 Node.js 22 LTS 适配进程，官方 `@hyperledger/fabric-gateway`；不要求 Bun 承担 SDK/gRPC 兼容 |
| 链码 | TypeScript/Node.js，Chaincode as a Service，避免挂载 Docker socket |
| 共识 | 参考联盟四个独立管理的 SmartBFT orderer；共识与业务背书分开 |
| 数据与软件 | 复用 Registry、Data Market、S3 兼容存储、Spack、Agent 和调度器 |
| 加密介质 | 受限 tar、age、逐文件 SHA-256、签名清单和逐包独立密钥交付 |
| 可靠事件 | PostgreSQL 事务 outbox/inbox、唯一请求键、状态版本、持久化游标；不增加独立消息集群 |

上轮查询的 Fabric `3.1.5`、CA `1.5.22`、Gateway `1.13.0`、fabric-shim `2.5.8` 仍是候选兼容组合，不是已验收的生产锁定。直接模式可以使用既有机构 PKI，完全不要求 Fabric MSP/CA；上链机构另配置 MSP，业务签名与 Fabric 身份明确绑定，密钥分用途管理。

## 4. 长期协议与无人值守授权

`CooperationAgreement` 由双方授权人员一次批准，产生不可变 revision。协议至少包含：

| 范围 | 必填内容 |
| --- | --- |
| 双方与模式 | 机构、合作域、mode、revision、签署人角色、有效期 |
| 资源 | 集群/队列、算力类型、CPU/GPU/内存/时长上限、并发、排队规则 |
| 软件与脚本 | 批准的工作流/用例修订、可自动安装范围、依赖锁和许可证约束 |
| 数据 | 输入/输出用途、可见机构、跨机构复制/派生权限、保留与删除规则 |
| 商业 | 慈善/置换/收费、价格版本、计量单位、额度、单任务最大承担金额、对账周期 |
| 自动批准 | 可由机构机器身份批准的操作、验收判据、重试次数、超限转人工条件 |
| 身份与撤销 | 允许的机构服务身份、授权租期、撤销传播、断联处理和在途任务规则 |
| 证据 | 必须留存的记录、原始证据位置、保留期；存证模式另含提交周期和积压上限 |
| 争议与退出 | 争议状态、指定审计/仲裁、可披露字段、退出与未结任务处置 |

机器身份的权限只覆盖上述范围；修改协议、扩大额度、转交第三方、放宽数据许可或改变模式仍需双方重新批准。普通用户继续使用所属机构账号，外部机构只得到受限联邦主体，不获得姓名、邮箱或原平台登录权限。

无人值守意味着授权范围内自动决策，不意味着无限资源、任意脚本或无条件接受结果。自动验收可以依据输出清单、退出码、确定性校验或双方批准的检查程序；无法判定科学正确性的结果应明确保持待验收，不能把“作业成功退出”自动写成科研结论正确。

## 5. 双边执行与本地额度：不靠链也不重复扣减

### 5.1 接单协议

1. A 验证当前用户和长期协议，将 `DelegationRequest`、本地预算预留、请求唯一 ID 与发送 outbox 在一个数据库事务内持久化。
2. 请求绑定源/目标机构、协议 revision、工作流节点、任务 attempt、参数摘要、数据/软件版本、资源上限和授权期限，并由 A 签名。
3. B 验证机构证书、签名、当前有效协议、请求期限和本地策略。按协议账户对额度执行原子检查/预留，并持久化唯一任务与接单回执。
4. B 返回签名 `AcceptanceReceipt`。请求已获 A 授权，B 可按协议进入准备，不依赖 A 再额外确认一次收到了回执。
5. A 收据丢失时查询或重发相同请求；B 返回原接单结果，不再创建任务。相同 ID 但不同内容摘要直接拒绝。
6. 完成、失败或取消后，B 按协议报告实际用量及预留差额，A 自动或人工验收，双方形成对账记录。

### 5.2 额度权威与不确定状态

每个双边合作域明确指定执行方 B 的接单账本为资源准入与已承诺额度的权威，A 的本地账本负责自身用户/课题组预算与对账。双方记录的不是两个可独立花费的钱包。

请求发出后无响应，A 不能假设 B 未接单并释放全部预留再向 C 派发；先查询 B 的签名状态。双方冲突或 B 失联时保留待核对状态。B 的持久化状态恢复不确定时停止该合作域接单，不用陈旧备份重置已消费额度。

不同合作域使用独立 budgetDomain/epoch，不让 AB、AC 和链上钱包无约束共用一个余额。需要分配同一机构总预算时，A 先原子划分不重叠的子额度；双边模式仍依赖 A 对自身预算诚实管理，不能声称具备全联盟防双花保证。

本地额度预留与任务映射可在单库事务内原子完成，A/B 两个数据库及外部调度器之间没有一个全局事务。恢复协议和保留不确定预留是必要机制。

### 5.3 撤销和失联

双边授权有有限租期。撤销指令带协议 epoch 和签名，B 持久化新状态并回复生效回执；A 区分“已申请撤销”和“对方已确认”。无法送达撤销时，依靠已约定租期限制后续使用，不宣称即时远程撤销。

B 在入队和实际提交调度器前检查授权、许可与有效 epoch。协议到期后新任务不得启动；运行中任务按原协议停止、完成或等待处置，不因链是否在线改变规则。取消必须得到实际调度器确认才能断言任务已停止。

## 6. 异步存证：链不在执行关键路径上

`bilateral_attested` 完整复用上述接单与额度机制。KQ 产生业务证据时，在同一数据库事务保存证据正文或可靠对象引用、SHA-256、签名和存证 outbox。

作业启动条件只包含双边有效授权、B 已接单、本地额度、数据/软件与执行安全条件，**不查询链是否出块，不等待 Peer 背书，不等待提交状态**。

证据写入和签名必须可靠完成；大对象先完成持久化与摘要，再提交其引用。不能仅向内存队列发送一次就开始任务，更不能在磁盘已满时丢弃回执以维持所谓“不阻塞”。

### 6.1 三条独立状态

| 维度 | 示例状态 |
| --- | --- |
| 执行 | ACCEPTED / DATA_WAITING / READY / RUNNING / SUCCEEDED / FAILED / CANCELED |
| 业务对账 | REPORTED / AWAITING_ACCEPTANCE / AGREED / DISPUTED / ADJUSTED |
| 存证 | NOT_REQUIRED / PENDING / BATCHED / SUBMITTED / ANCHORED / RETRYING / NEEDS_REVIEW |

例如“执行成功，双方账单已确认，存证待补交”是合法且明确的组合。上链失败不能把已运行任务改成计算失败，也不能据此重复运行。存证成功不等于账单被接受或现实款项已到账。

### 6.2 证据与批次

证据类型包括协议批准、委派请求、接单、执行起止、数据导入、用量报告、验收、账单、更正、取消和争议处置。记录包含：

- evidenceId、agreementId/revision、mode、budgetDomain/epoch、task/attempt、producerOrg、记录类型和 schemaVersion。
- 各生产方在该合作域的持久化 sequence、前一记录摘要、payloadDigest、keyId、签名、所引用的业务决定。
- 源方声明发生时间、对方收到时间以及后续链提交时间分别保存；补交不能伪装成事发时已上链。

原始价格、用量与条款仅保留在双方受控存储及授权 PDC，不写入公共交易参数。报告方声明与双方确认是不同类型；更正追加引用原记录，不覆盖历史。

按“相同机构范围、用途、协议/额度 epoch、证据规则”形成批次，不把 AB 与 AC 的私有证据混进同一批次。批次可按小时、天、记录条数或体积触发，由协议配置。

批次使用有明确编码的有序记录摘要清单及整体 SHA-256，双方签名确认批次清单。清单签署表示同意所列记录及其类型、范围与序列，不把单方报告升级为共同认可的科学或计费事实。原始记录和私有清单保留，详细日志不逐行上链。

链上存证保存批次 ID、协议版本、序列范围、记录数、摘要、签署身份和必要状态，商业内容在 PDC；采用随机业务标识及带盐承诺，避免低熵金额被公开哈希枚举。未获对方确认的记录继续保留并显示待确认/争议，不伪造成完整双签批次。

### 6.3 独立存证链码与双重去重

新增 `kq-evidence` 链码，与 `kq-market`/`kq-commercial` 分开。其职责是验证允许的机构身份、签名、序列、版本与重复提交，追加证据承诺；**不扣减实时链上余额，不重新批准已执行的任务**。

AB 存证集合由 A/B 分发，集合写入策略为 AND(A,B)。Peer 自动背书与双方业务签名分开验证。记录被 ANCHORED 仅表示该批次通过链上规则且提交为 VALID。

数据库唯一键与链上业务键共同去重：相同 batchId/epoch 且摘要一致则返回既有记录；相同标识但摘要不同进入冲突处理。重试先查询原 txId 和业务 ID；记录 ANCHORED 后仍保留可重建回执，链事件重放不重复归档或记账。

### 6.4 故障行为

| 故障 | 执行侧 | 存证侧 |
| --- | --- | --- |
| 链或适配器不可用 | 按有效双边协议继续 | 保留持久化队列，退避重试 |
| B Peer 离线但 B 的 KQ 可接单 | 按双边协议继续 | 等待所需背书机构恢复，不改投非成员 |
| 集合未就绪/证书不匹配 | 不影响已有有效双边授权；新授权仍按双方规则 | NEEDS_REVIEW，不能写入公共集合或降低策略 |
| 某条记录无效 | 不重跑已完成任务 | 隔离记录与相关批次，保留原证据，不无限重试 |
| 积压接近协议上限 | 告警并处置；不以短暂链超时直接阻塞 | 继续补交，可按双方批准调整后续策略 |
| 已达未存证风险上限或无法持久化 | 停止新增接单；保护已接任务及结束回执空间 | 扩容/归档/恢复；禁止静默丢证据 |

“不阻塞”指链请求不在任务同步调用路径内，且链故障本身不终止授权范围内运行。它不承诺无限积压、无限信用或证据存储失效时仍接新任务。若协议设置最长未存证期限或累计金额上限，平台按事先约定的业务风险边界处置，界面明确原因。

## 7. 链上协调模式继续保留严格门槛

开放需求市场或以链上余额为权威的协议使用 `ledger_coordinated`：

1. 公开需求只发布获准公开的摘要；B/C 报价分别留在 AB/AC 私有域。
2. 公共任务通过 CAS/MVCC 唯一预留执行方和 attempt。
3. 商业链码核对公共预留版本、双方条款批准及私有余额，锁额并生成执行许可。
4. 公共激活核对许可对应当前 `executionGate` 的哈希、READY 状态和版本；取得 VALID 后才允许执行准备。
5. 数据、软件和本地授权满足后，复用同一 Agent 执行路径；用量、验收、结算进入相应 PDC。

公共预留、私有锁额和公开激活是可恢复的状态机，不宣称一个跨系统大事务。退款/撤销必须更新 gate，防止旧许可重新激活；释放锁额前读取公共任务状态，ACTIVE 任务须先完成取消/终态确认。重新开放旧预留前检查释放证明，禁止在旧锁额尚有效时创建第二个 attempt。

链不可用时不能自动切成双边直接或异步存证来花同一个余额。已有有效许可的任务可在原授权期限内继续执行，但新认领、激活和需要链确认的结算等待恢复。

## 8. 一致的隐私与机构背书

### 不同模式的隐私载体

- 直接模式：机构间 mTLS、签名信封、各自权限控制及加密存储；明文只传给指定合作方，不进入联盟公共数据库。
- 异步存证：执行侧同直接模式；上链批次只进入对应机构的 PDC，链外原始证据也受相同机构范围限制。
- 链上协调：商业条款、用量、额度和金额均在 PDC；公共通道仅处理经过允许的状态与承诺。

机构级私有字段隔离不等于交易关系匿名。通道成员仍可能看到 MSP、集合名称、时间、交易数量和哈希。合法接收方的管理员能接触本机构私有存储，平台无法保证其不私自复制。

### 原生 PDC 配置模板

```json
{
  "name": "evidence_AB_v1",
  "policy": "OR('AMSP.member','BMSP.member')",
  "requiredPeerCount": 1,
  "maxPeerCount": 3,
  "blockToLive": 0,
  "memberOnlyRead": true,
  "memberOnlyWrite": true,
  "endorsementPolicy": {
    "signaturePolicy": "AND('AMSP.peer','BMSP.peer')"
  }
}
```

同样的机构策略用于 `commercial_AB_v1`。两台 B Peer 不等于两家机构；缺 A 背书不能通过 AB 写入。集合成员配置、背书与客户端角色要兼容；新建键的初始写入仍受现有策略约束，不能靠新 SBE 绕过。

敏感输入仅放 `transient`，Adapter 显式限制 `endorsingOrganizations`。普通参数、响应 payload、事件、日志、监控标签和导出不得携带越权商业字段。私有详情通过指定成员 Peer 的受控 Evaluate 查询。

Peer 背书证明链码执行满足规则，不代表业务验收；协议范围内的机器身份可以自动批准，但超范围或改变规则仍需有权人员批准。

链参与机构的关键配置/链码/集合变更采用 ALL 机构批准；公共市场交易采用 MAJORITY；私有商业和存证写入采用对应机构 AND。治理 G 默认没有私有商业字段访问权。

## 9. 慈善、资源置换、收费与争议

三种商业方式与三种协作模式是两个维度，不把“收费”强行等同于“必须上链协调”。双方可以在长期协议中约定自动计量及周期性账单，直接履约或异步存证。

- 慈善：按协议无偿执行，贡献回执是否公开由双方决定；不自动增发积分。
- 资源置换：合作协议域内的私有额度，单位、固定总额/信用上限、有效期、分配和退出规则双方批准；提供方单方用量不能增发。
- 有偿共享：费率版本、封顶预算、用量、账单确认、减免、退款和支付回执分别保存。整数定点金额绑定币种与单位。

直接和异步模式的本地余额，不与链上协调钱包自动互通。不同合作域也不默认通兑，不发行公开的全联盟余额或自由转账代币。

原始报告、技术更正、商务减免、验收和支付分别建模，追加记录，不覆盖原始证据。双方账单已确认、链上已存证、链上额度已结算、银行已付款是不同事实。

指定审计/仲裁 R 必须预先约定字段范围。AB 原始价格/用量/合同可继续限于 AB，R 仅访问单独授权的结算和案件证据。链上仲裁集合可配置 OutOf(2,A,B,R)，其正常业务仍要求应有审批；这表示接受该信任模型，不抵御任意两家串通。

未指定仲裁或必要证据未授权时，维持争议冻结；治理管理员无权直接覆盖余额。直接/异步合作遵循协议中的双边仲裁授权，不能借链存证补交追认一个原本未经授权的扣款。

## 10. 数据、软件环境与 Workflow

三种模式共用数据交付和执行约束：

- 工作流节点声明软件修订、recipe、目标平台依赖锁、材料摘要及数据版本。资源方重新检查许可和本地约束，按策略使用 Spack 准备环境。
- 共享数据集、任务私有输入及结果可通过网络或加密介质交付；在数据所在云盘/Agent 读写，避免 Server 中转。
- 介质包含随机 packageId、加密签名清单、每文件 SHA-256、许可证和 provenance；逐包独立密钥通过独立授权通道交付。
- 先写隔离区，流式校验路径、文件类型、大小、空间、加密认证和摘要；完整成功才原子发布副本。
- 导入成功不等于可使用。源机构许可和目标本地策略均有效后解除 DATA_WAITING；等待不提交计算作业、不计计算用量。
- 同版本副本可复用，新任务重新检查授权。丢包/损坏完整重制新 packageId，介质返还、销毁、目标副本删除分别记录。

一个 Workflow 可含使用不同协议模式的节点，每个节点在创建时固定自己的 agreement revision、mode、budgetDomain 和 attempt。链上节点等待只阻塞其依赖路径，不应阻塞无关的双边节点；父工作流不能把各节点的存证状态混成一个“全部已上链”。

## 11. 模式变更与协议续期

模式是不可变协议 revision 的组成部分。双方签署新 revision 后仅影响新任务；旧任务、旧额度、旧证据队列仍按原规则完成。

- 异步存证 → 直接：不能删除原有待存证义务，也不能将旧 PENDING 改成 NOT_REQUIRED。
- 直接 → 异步存证：是否补交旧记录须另行批准；标注原业务时间与实际首次上链时间，不伪装实时存证。
- 双边 → 链上协调：新 budgetDomain/epoch 以双方核对后的额度开立；旧在途预留先结清或明确隔离，不能把同一笔可用额度复制成两个钱包。
- 链上协调 → 双边：必须按协议正式关闭/划转旧链上额度并形成新授权，链故障不构成自动切换许可。
- 机构退出：处理旧任务、预留、存证欠账、数据保留与争议；证书撤销不消除历史证据义务。

模式修改、暂停自动接单、扩大限额、重新授权证据可见范围必须有双方审批和审计。链恢复后的补交不改变任务最初所属模式。

## 12. 长期存储：先控制增长来源

账本不是科学文件仓库或逐秒监控库。容量策略以数据类别区分：

| 数据 | 位置与控制 |
| --- | --- |
| 输入、输出、日志、合同附件 | 机构对象存储/Agent；版本、配额、保留与授权删除 |
| 高频监控与逐秒用量 | 本地计量库；形成签名汇总，不逐样本上链 |
| 双边原始回执 | 双方私有证据库；可按协议归档，保留可验证的原始内容 |
| 异步批次 | PDC 保存必要承诺和清单信息；按时间/数量/大小聚合，减少交易数 |
| 当前额度、冻结额、有效协议 | 保持可读；未完成业务不能被过期清理 |
| 已结束私有记录 | 满足审计/争议保留要求后执行明确 purge/保留规则 |
| 公共区块、交易索引与历史 | 持续增长；配置归档、扩容与运行 Peer 替换 |

精确容量通过“每天实际交易量 × 实际编码大小＋索引/私有数据/状态增长”测算，并计入每个副本和备份。批量存证减少交易数，不意味着历史能永远保持固定大小。

`blockToLive` 按区块计数而非自然日；不能用固定区块数直接承诺若干年的法规保留。使用 `PurgePrivateData` 等明确处理已到期私有数据；普通 Delete、删除当前状态或 PDC purge 都不删除公共历史区块和哈希。

活跃余额、预留、未完成协议和仍需仲裁的证据不得因保留策略自动消失。集合配置在创建时确定适用范围，新增读取机构采用新的集合版本，不将旧明文自动扩散。

## 13. 运行 Peer、历史归档与快照替换

链参与机构按可用性要求部署运行 Peer；不要求每个小机构永久保存全部公共历史。联盟明确至少两个独立故障域的公共历史保存责任，可采用完整历史 Peer 加经过恢复验证的独立备份。私有证据和数据库备份仍按原授权范围保存，归档职责不授予全联盟明文读取权。

运行 Peer 保留当前状态、必要私有数据、交易去重信息及加入后的区块。历史查询路由到持有相关历史的 Peer/经校验的归档查询服务；不能让运行节点默默返回空历史冒充“没有记录”。

空间增长需要替换运行 Peer 时采用以下受控运维流程：

1. 保留可用的现存 Peer 与私有数据来源，安排不同机构在同一高度生成快照，并核对文件摘要和元数据签署。
2. 在独立卷/节点上使用可信快照加入新 Peer，安装相容链码并追赶区块。
3. 从获授权的集合成员补齐私有数据，确认余额、许可、商业状态、背书与查询可用。
4. 验证历史查询路由、KQ 事件游标与恢复能力后，逐个切换服务；不同时替换承担同一必要机构背书的全部节点。
5. 在历史和私有备份责任已满足后退役旧运行 Peer、释放其独立卷，而不是手工删除运行中的 blockfile。

必须保留以下限制：

- 生成快照不会裁剪已经加入通道的旧 Peer。
- 快照不含私有明文、完整配置/密钥，不能替代完整备份；私有源丢失时不能凭哈希重建数据。
- 从快照加入的 Peer 不能查询快照之前的完整区块和键历史。
- 快照仍包含当前状态、既有交易 ID、集合配置历史等，仍会增长，并非无限压缩方案。
- 生成快照会消耗资源，并暂缓该 Peer 对对应通道新块的提交；需保持其他运行节点承接业务。
- 快照加入节点的恢复方法与全历史节点不同，不假设其可以执行依赖完整区块的 reset/rollback/rebuild 操作。

Orderer 的公共区块存储独立规划，不能靠 Peer 快照释放；预留扩容和备份，不手删 orderer 数据。归档减少运行节点负担，但历史总量仍需要实际存储预算承担。

## 14. 容量监控、背压与历史代际管理

监控各节点/卷的公共区块、私有存储、状态库/索引、证据库、outbox、日志及备份占用，结合增长速度预测写满时间。告警同时考虑百分比、绝对剩余空间和完成快照/导入/恢复所需的余量，不只使用一个磁盘百分比。

优先清理可重建缓存和已过期日志，再处理满足保留规则的私有资料、扩容或运行 Peer 替换；不得把未上链证据、活跃额度或未恢复验证的唯一备份当缓存删除。

达到风险阈值时限制新增负载，并为已接任务的结束回执、取消和恢复保留空间。异步存证模式只在预先定义的容量/信用边界触发接单背压，不因一次链超时同步失败。

异步存证的业务边界可由双方在执行协议中签署 `attestationLimits`：限制仍有未结算或未完成存证义务的执行尝试数、原预留额合计及最老待办年龄。按 reservation 去重，免费任务同样受次数/年龄限制；本地结算不代表证据已上链。此边界只控制新接单，保留已有任务继续收尾的权利，不代替节点磁盘容量保护。旧协议未配置时须明确显示；新调整重新计入时从其未完成义务创建时刻计时。

若完整历史与当前状态仍持续超出可承担预算，可采用经联盟批准的新通道代际承接，但不是按年自动换链或删除旧账：旧通道停止新增协调业务、完成在途任务/争议/余额核对，形成共同认可的结转凭证，再在新通道唯一导入新额度 epoch。旧状态必须失去继续花费资格后，新状态才能启用。

跨通道不具备天然原子性，代际切换必须有明确停止点、核对和恢复流程。未完成的异步存证义务按原通道补齐，或双方明确批准新的补交位置并保留旧引用；不能因迁移丢失或伪造证据时间。旧历史按约定保留并可查询。

## 15. 部署按所选能力启用

| 部署对象 | 必需组件 | 不要求的组件 |
| --- | --- | --- |
| 仅双边直接机构 | KQ、联邦模块、机构 PKI、独立数据库/存储、Agent/调度器 | Fabric Peer、orderer、Fabric Adapter |
| 双边异步存证机构 | 上述组件＋存证 worker/adapter、自己的链身份和有权访问 PDC 的 Peer 服务 | 不要求成为 orderer 运营者 |
| 链上市场参与机构 | 上述链能力＋市场/商业链码与完整提交门槛 | 不把普通用户迁移成链钱包用户 |
| 联盟排序运营者 | 独立 orderer、证书、存储、监控 | 不自动获得商业 PDC 明文 |
| 历史归档责任方 | 全历史存储/Peer 或可恢复归档及授权查询 | 不自动获得其他机构私有证据 |

“机构独立参与链”与“运行共识节点”分开；参考 SmartBFT 四个独立 orderer 由约定的联盟成员承担，不要求每个新伙伴新增一个 orderer。

直接模式通过 Compose 的联邦能力启用即可；链相关服务独立 profile、独立卷和 secret。各机构根据自身任务接入需要配置 Slurm/PBS 等 Agent。腾讯云现有小 VPS 不自动承担整个联盟。

私有交易接口只允许本机构 KQ 调用，链码服务不挂宿主 Docker socket，机构间端口均按 TLS 信任边界开放。授权、业务签署、数据解密与联盟管理密钥分离。

## 16. Web、CLI 与可审查配置

合作协议页用明确业务选项呈现三种模式：

- **双边直连**：按双方协议自动执行，保留签名回执。
- **双边直连＋存证**：执行照常，证据自动补交联盟链。
- **联盟链协调**：执行前确认共同认领与额度。

每项展示需要的机构权限和保证范围，不使用一个含糊的“启用区块链”开关覆盖全部行为。协议详情集中列出可读取机构、业务批准角色、背书模板、额度、自动验收和存证/保留规则。

任务列表分别展示执行结果、业务对账和存证状态。例如“成功｜账单已确认｜待存证”；直接模式显示“不要求存证”，不能显示“存证失败”。异常显示真正原因，如授权过期、私有数据缺失、证据存储不足或链交易无效。

运营页面提供待存证数量/最老记录时间/待存证业务风险量、缺失序列、失败批次、证书与集合状态、账本增长和容量预测。商业金额指标只供被授权机构查看，不进入联盟公共监控标签。

CLI 支持协议检查、回执查询/导出、待存证核对/重试、包导入导出、快照与归档状态检查。重试复用原业务 ID，不提供“一键把所有失败标记成功”或绕过签名的修复入口。

## 17. 数据对象、代码与交付责任

主要对象包含 Agreement/revision、DelegationGrant、BudgetDomain/epoch、DelegationRequest、AcceptanceReceipt、Task/Attempt、ExecutionPermit/Gate、Usage/Approval/Invoice、SignedEvidence、EvidenceBatch/AnchorOperation、EventCursor、ArchiveManifest、SnapshotApproval、DeliveryPackage/Replica。

主项目负责：

- shared：模式、协议、签名信封、状态和回执 schema；Node 链码只复用无 Bun 依赖的纯契约。
- db/server：双边授权与额度、任务唯一性、业务审批、事务 outbox、存证状态机、跨模式投影和恢复。
- fabric-adapter：官方 SDK、机构身份、transient/组织限制、提交 VALID 与事件补读。
- contracts/fabric：`kq-market`、`kq-commercial`、`kq-evidence`，集合及原生策略模板。
- agent/registry：复用本地调度、数据和软件环境；补充安全包处理与必要证据，不接管联盟财务。
- web/cli/deploy/docs：完整交互、按能力启用、备份/恢复、存储监控和验收资料。

本仓库 kq-bundles 负责真实与轻量验收软件材料、工作流、SHA-256、许可证/provenance、初始化与交付清单。通用包不携带机构私钥、真实合同、生产数据或自动授权。

软件启动 seed 与启动后导入沿用现有兼容路径；协议、机构信任和链治理配置必须经过对应机构批准，不能由离线软件包越权生成。

## 18. 完整验收要求

| 场景 | 必须证明 |
| --- | --- |
| 直接合作不依赖链 | 不启动 Fabric 组件，A→B 自动接单、准备环境、执行、回传和对账完整成功 |
| 存证不阻塞 | 在链不可用时启动新双边任务并完成；回执可靠落盘，任务不等待链；恢复后补交且业务只记账一次 |
| 提交不确定 | VALID 后响应丢失、worker 重启、事件重复都不重复存证/扣额；错误摘要同 ID 被拒绝 |
| 双边失联与额度 | B 已接单但 A 未收回执时不再次向 C 派发；并发请求不突破协议额度；恢复不重置余额 |
| 无人值守边界 | 允许模板自动执行；超资源、过期授权、未许可软件、越权数据和异常验收转等待/拒绝，不越权自批准 |
| 异步证据完整性 | 双方签名、记录类型、序列范围可核对；单方报告不被误写成已共同接受；更正保留原证据 |
| 链上模式仍严格 | 链断开、锁额未确认或许可撤销时不能新激活；不得自动降级使用同一额度 |
| 私有数据与背书 | C/G 无 AB 商业明文；普通参数/事件/日志无泄漏；缺少指定机构背书无效 |
| 模式切换 | 只影响新 revision；旧 outbox 不被删除；预算域不复制余额；历史补交有真实时间标记 |
| 容量与恢复 | 存储不足时不丢证据，按协议停止新接单；快照新 Peer 私有数据补齐后才接流量，历史查询仍可用 |
| 数据与 Workflow | 加密包损坏/错误密钥/越权不能使用；A→Slurm→PBS→A 依赖与结果一致；不同模式节点状态正确 |
| 商业与审计 | 慈善、额度置换、收费账单及指定争议处理均闭环；存证、账单确认、额度结算和实际支付不混淆 |

验收用小数据和确定性轻量任务。模拟科学软件独立安装前缀、可恢复；保留至少一个真实执行的小任务证明调度和文件链路，不将模拟结果当成科学有效性验收。

### 收尾预算回收约束

收尾预算按完整任务身份持久保留。执行结束不能单独触发回收：必须联合确认结算、执行终态、网络回执、存证待办和文件清理，且后续更正、导入、取消或自动结算能够按原分配字节重新占额。回收只改变逻辑可分配预算，不能删除账务凭证、私有档案或应急物理预留。无法证明结束的早期市场/提案意图继续占额；链故障不会把待存证任务变成已完成。当前实现及未验收边界见[容量配置](../../../deploy/federation/storage-capacity.md#自动回收条件与边界)。
