# 联邦协同：页面操作与权限

入口为侧栏“联邦协同”。先选择当前机构；切换机构会重建页面状态，查询及写入均绑定该机构。人员权限在“系统设置 → 安全 → 联邦权限”显式配置，平台角色不自动获得联邦业务权限。

用户入门及角色流程见[联邦协同使用指南](../../federation-collaboration.md)。

## 页面布局

“联邦协同”（Federation Collaboration）集中提供联邦任务、任务市场、合作协议、联邦资产、商业合同、介质交付、仲裁案件和介质运输。当前机构选择放在页首，与全部页面共用同一机构上下文。

宽屏使用可随页面滚动保留的侧边导航；窄屏改为可横向滚动的导航，方向键随布局切换。合同及其他子页采用独立横向标签，完整保留原有权限和业务入口。操作栏、列表、空状态与详情字段采用统一布局；状态始终保留文字，不依赖颜色区分。长摘要、标识和表格在所在内容区换行或滚动，不撑宽整页。


## 用户提交与取回结果

在“联邦任务”点击“提交任务”，选择已生效并由双方批准的执行合作、模板、输入快照和软件环境锁，填写 CPU、内存、GPU、时限及费用上限，核对后确认提交。资源和额度不得超过协议；金额始终按整数字符串传递。

| 操作 | 人员权限 |
| --- | --- |
| 查看任务、主动查询执行机构 | `delegation.read`，提交或取消权限也隐含此读取权限 |
| 准备页面表单 | `delegation.submit`、`agreement.read`、`asset.read` |
| 取消原任务 | `delegation.cancel`，提交权限也隐含此取消权限 |
| 查看结果、取回云盘、确认交付回执 | `result.read` |

任务送达与计算状态分别展示。对方接收任务不表示已执行完成；远端状态显示观察时间，未取得状态时显示“尚未获取”。页面周期刷新本站持久记录，主动点击“查询执行机构”才请求即时远端查询；后台标签不持续轮询，切回标签不触发额外刷新。

取消是永久停止请求，只有对端确认后才显示“已确认停止”。响应未知时重试原委派或取消记录，不能用新编号重新派发。已完成的计算不再提供首次取消操作。

结果需先查看授权范围内的清单，再独立确认“取回到云盘”。复制、校验、可用及对端交付确认分别展示；文件只有发布可用后才提供下载。重新进入页面会按当前用户查询已有结果传输，不依赖浏览器保存导入编号；其他机构或同机构其他用户的传输不会被返回。取消传输与取消计算是两项独立操作。

输入快照、环境锁和本地资产映射可在“联邦资产”导入或登记；原件的制作、实际数据准备、软件安装和双方受限执行身份仍沿用现有工具。当前新任务表单为网络交付且不附带仲裁政策的独立委派，不自动替用户选择仲裁授权。需要原签名仲裁绑定、物理介质或 Workflow 节点编排的请求沿用现有 CLI/API/Workflow 执行路径，完成后的任务同样可以在列表跟踪。

## 管理员准备联邦资产

在“联邦资产 → 输入与环境”点击“导入材料”，填写已经登记并生效的来源站点 ID，选择或粘贴现有协议 JSON。页面接受 `inputs` 输入快照与 `environment-lock` 环境锁，限制 1 MiB；本地校验格式与深度，并计算规范化 JSON 的 SHA-256。核对弹窗展示来源、摘要、参数/数据集/绑定数或目标平台/软件数/原生依赖锁，还可展开完整原件。独立确认后保存，任务表单的材料选项随之更新。响应未知时保留同一原件重试。

材料列表只读摘要，点击后才读取正文并重新校验摘要；校验成功后可导出 JSON。参数值不会预先加载到清单。原件不可覆盖修改，内容变化须导入新的摘要；保存原件不表示数据已到达、软件已安装或取得使用许可。环境锁中的 native lock 必须来自实际准备的环境，页面不生成模拟锁。

在“资产映射”点击“登记映射”，填写来源站点、类型、资产 ID、不可变版本、内容摘要及本地不可变版本 ID，核对后登记。数据集使用本地 data version ID，其他类型使用 software revision ID，不使用 `latest`。服务端复查本地版本状态、摘要和人员访问权；登记本身不授予执行许可。明细保留两端绑定，可单独确认永久撤销。原来源版本的映射撤销后不可恢复或改绑，需要变更时使用新的来源版本。

| 操作 | 人员权限 |
| --- | --- |
| 列表、查看和导出材料，查看映射 | `asset.read` |
| 导入材料、登记或撤销映射 | `asset.map`（现有权限规则隐含读取） |

切换机构/身份会重置资产页面；撤权关闭写入确认并隐藏相应内容。读取失败或权限刚被授予时可点击“刷新”恢复，所有资产接口使用 `Cache-Control: no-store`；页面不在切回浏览器标签时额外刷新。

## 管理员处理争议与裁决

在商业合同内，从用量、账单、结算、调整或付款原件的详情点击“发起争议”。填写原因与诉求，先生成草稿，核对后独立确认。争议保留精确的原件类型、编号与摘要；付款使用回执编号 `receiptId`。响应未知时保留原案件编号重试；确认并核验返回原件后进入新案件。

案件页分别展示对方收件、账目冻结、裁决收件、本站执行及链存证进度。收到 R 裁决不自动执行；执行者先审阅原裁决的结果和精确金额，再确认“批准执行裁决”。增额历史占额与当前可用额度不同，页面保留批准时占额，入账后不会把历史数值改为零。

| 操作 | 人员权限 |
| --- | --- |
| 读取商业合同 | `agreement.read` 或其现有隐含授权 |
| 查看案件 | `dispute.read`，开案或和解权限也隐含此读取权限 |
| 发起争议、重试送达与符合条件的冻结同步 | `dispute.open` |
| 查看本机构收到的裁决 | 案件读取权限，加 `arbitration.approve` 或 `arbitration.execute` 任一 |
| 批准本站执行、重试该裁决存证 | `arbitration.execute` |
| 通用和解及永久退出后协商和解 | `dispute.resolve`；涉及财务时仍另需结算或调整批准权限 |

执行者不必获得仲裁政策批准权，也不能凭执行权修改政策。手机沿用商业管理只读策略，撤权会关闭可写确认。状态接口不返回机构内部签名、执行回执或恢复密文。

直接模式本地执行不等待链；异步模式本站应用后继续跟踪独立存证；协调模式按后台规则等待链确认后应用。存证失败只重试既有队列编号，不创建新裁决或再次扣款。通用和解由服务端 context 判定能否草拟及协议版本；永久退出后的 v1 原流程保留。v2 支持三模式，不要求为了和解先签发 R 裁决；已有 R 执行意图时仍阻止新通用和解。协调金额按链授权、独立财务、最终结案分别显示进度，不能在双签后提前显示结案。

## 管理员配置自动授权

链上协调商业合同内新增“自动授权”页签，分别管理“预约与执行”和“执行终态”。必须先完成双方合同签署；直接和异步合同不显示该入口，原有财务自动收尾继续使用“自动收尾”页签，不因此扩大授权。

预约授权可设置单任务金额、累计金额、累计任务数、到期时间及自动签署步骤。发布需求和激活执行只向具有 `market.publish` 的需求方开放；认领只向具有 `market.claim` 的提供方开放。终态授权选择允许签署的成功、失败或取消结果。写入和撤销均需 `agreement.approve`，清单读取沿用 `agreement.read`；手机只读，撤权会关闭编辑和确认。

页面先核对精确范围与额度，再独立确认提交；金额按整数字符串传输。执行授权消耗与市场授权消耗分别展示，不把重叠阶段相加。单个合同、单类授权只允许一份未撤销策略，过期或耗尽后也须先明确撤销，再新增替代。撤销只停止该授权的新签署，不抹除既有承诺、历史记录或财务义务。

授权编号由 Server 生成，新增响应未知时不自动重试；先刷新并核对原持久结果，再决定下一步。撤销始终绑定原授权编号。清单和返回结果校验机构、站点、合同版本、合同摘要及权限/额度/计数，异常数据不提供可执行确认。切换合同、机构或登录身份重建页面状态，切回浏览器标签不额外刷新。

此入口只管理既有链上协调授权，不代替资源开放协议、实际链确认或本地调度许可。仲裁政策、字段披露政策及 R 取证裁决工作台见下文；自动授权页本身不构成完整无人值守联邦验收。

本轮新增 3 项共享协议检查、9 项页面组件检查通过，原商业页面 47 项回归通过；最后两处显示调整只复验受影响的未知响应场景。类型检查首轮发现测试夹具的终态数组推断过宽，修正后 Web 定向复验和独立 Fabric 类型检查通过，其余 workspace 使用同轮已通过结果。全仓 lint 保留既有 47 warnings／1 info，无新增错误。真实 Chromium 使用合成 API 验证新增、未知结果查询、撤销和终态授权，并检查中英文、深色及手机管理限制；九张最终截图无溢出或页面错误。原页面布局、控件和主题沿用现有系统，没有增加新的设计体系。未运行环境检查、数据库或链网络、真实调度器任务、远端发布；不等同正式跨机构验收。

## 用户查询与操作任务市场

“联邦协同 → 任务市场”区分联盟公开的“需求目录”和按当前机构隔离的“本机构操作”。目录使用链提供的 bookmark 分页，显示查询时间；点击需求读取最新正文与资源范围，摘要异常、目录故障或找不到原件均显示错误，不显示为“暂无需求”。无链模式不请求链上目录，仍可查看本站历史。

发布需求只公开标题、描述、目标平台、架构和资源需求，不包含私有脚本、数据、价格、合同原件或个人身份。核对后独立确认，本地 `pending` 仅表示受理；链上 `committed`、需求认领／执行授权、真实作业状态分别判断。需求方可取消本站已发布且尚未认领的需求，已过期但仍开放的需求也可关闭。

认领选择当前机构已双方签署的协调合同，并分页查找已送达本站、绑定该需求的私有原请求；没有原请求时等待，不生成新的预约编号。认领使用原 `reservationId`、合同域、需求版本和到期时间；最终提交前重新读取需求、合同及请求状态，检查机构、站点、合同摘要、资源上限及完整有效期，避免人工操作与自动接单使用不同编号。认领不授予私有预约、预算、执行或实际调度权。

| 操作 | 人员权限 |
| --- | --- |
| 目录、本站上下文、操作与交易历史 | `market.read`（发布／认领沿用服务端的隐含读取权限） |
| 发布及取消本站开放需求 | `market.publish` |
| 认领原请求 | `market.claim`，另需 `agreement.read` 查看对应私有合同与请求 |
| 恢复待复核的公开发布／取消／认领交易 | 原操作对应的发布或认领权限 |

新增 `GET /federation/market/context` 只提供本站标识和链市场启用状态，检查人工登录、活动机构及 `market.read`，不要求额外读取合同的权限。手机沿用管理只读策略；切换机构／登录身份重建页面，离开页面会使尚未完成的预检查失去写入资格。页面显式刷新，不在切回浏览器标签时重新加载。

每次意图仅生成一次编号。提交结果未知时保留原请求，可查询原操作或用相同编号和相同正文恢复；重试前若已查到原持久操作，仅展示它，不重复写入。返回的编号、需求绑定及正文摘要均需核对。`needs_review` 的公开操作需独立确认后恢复原交易，历史分页展示原交易 ID、阶段、区块和验证代码，不创建替代交易。

任务市场目录页不直接创建私有 `MarketRequest` 或配置 Workflow 市场节点，也不直接激活执行、停止计算或处理私有账务。私有请求现可从下节的商业合同入口创建，后续步骤继续由既有后台协议处理。普通公开需求的登记不等于已具备可执行材料；仲裁与披露配置、R 案件工作台见下文。

本轮沿用既有 Operate 界面的 `Button`、`Input`、`Dialog`、`Tabs`、`AgreementFact` 及语义主题色，不创建或改写 `DESIGN.md`、`.impeccable/design.json`。新增 13 项组件检查、2 项人工 context 路由检查（mock 服务，非 PostgreSQL 集成）及原 FederationPage 5 项、手机策略 2 项回归通过；数量按独立用例统计。全仓类型首轮仅新 Web 测试的可空索引报错，修正及两项恢复修复后 Web 定向类型检查通过，其余 workspace 沿用首轮通过结果，独立 Fabric 类型检查通过。lint 为 0 errors、既有 47 warnings／1 info，设计 detector 无发现，文档链接检查通过（101 文件、1162 目标）。

Chromium 使用静态构建与路由拦截的合成 API，完成中英文、深色、桌面／手机及发布、确认、未知结果、交易、认领视图，共十张截图；未启动监听服务、Server、链、容器、真实作业或远端写入。两项恢复补验无页面错误：原操作未落库并返回 `409 ASSET_UNAVAILABLE` 时以同编号、同正文重发；`/retry` 已受理但响应丢失时查询到原 `pending` 操作后直接展示，无第二次 POST。评审以原八张截图和指定实现为范围，两个恢复问题修复后均已解决，结论为 pass／ship；补验不等于重新完成整套真实验收。真实 SSO、市场 context 的 PostgreSQL 集成、跨机构链部署及实际调度仍未在本轮验证，未提交、合并或部署。

## 用户创建与查询私有市场请求

在双方已签署、当前生效的链上协调商业合同详情中打开“市场请求”。源方可选择允许市场发布且尚未撤销、过期或耗尽的预约授权策略，选择本站输入快照、环境锁和合同内模板，填写公开标题、描述、目标平台、架构、资源需求及私有费用上限。公开目录只接收公开需求字段，模板引用、材料绑定及金额留在私有请求中，合同原件不进入公开目录。金额使用整数字符串，保留超过 JavaScript 安全整数范围的精确值。

接单窗口须在一小时内；页面按本地时间默认填写约十五分钟。执行截止时间按接单截止加作业时限计算，必须同时落在合同和授权策略的有效期内。资源、单任务金额、累计金额及任务数均受既有合同和策略约束，公益合同金额须为零。页面先展示待提交内容，再独立确认；提交前重新读取合同并核对双方签署及原合同绑定。后台沿用既有自动市场发布与私有交接流程，交接 `complete` 不表示计算作业已经执行完成。

双方可分页查看当前机构、本站及该合同的收发记录，按预约编号读取私有原件。列表展示方向、预约编号和进度；详情展示错误、到期及下次尝试时间，并可展开私有原件。读取详情时核对预约、需求、合同摘要、域及两端站点绑定。`pending`、`needs_review`、`complete`、`closed` 分别保留后台状态，恢复待复核记录仍使用原编号并独立确认。

| 操作 | 人员权限 |
| --- | --- |
| 分页查询收发记录及读取私有请求原件 | `agreement.read` |
| 创建私有市场请求 | `delegation.submit`，页面另需 `agreement.read`，读取材料另需 `asset.read` |
| 恢复 `needs_review` 的原请求 | `agreement.approve`，页面另需 `agreement.read` |

创建权不扩大策略签署权限；后台继续校验既有授权与签署规则。手机只读；切换机构、登录身份或合同重建页面状态。撤权关闭创建和确认，异步预检查期间撤权或页面卸载会阻断后续 POST。页面显式刷新，切回浏览器标签不额外读取。

进入确认时生成一份请求、预约编号、需求编号及 salt。提交结果未知时保留完整意图，恢复先按原预约编号 GET；读到匹配原件就直接展示，仅在 GET 返回 `404` 或 `409 ASSET_UNAVAILABLE`、确认原件缺失时，才用相同编号、正文和 salt 重发。只有首次 POST 本身明确返回 `400`、`403` 或 `409`，才可视为确定拒绝并放弃。先前 POST 结果未知后，后续 GET 返回 `403`／`409`，或确认缺失后同编号重发返回 `403`，均保留未知意图，不允许丢弃后重新创建；其他读取或恢复失败也不证明原请求未受理。`/retry` 响应丢失后，若查询已是 `pending`、`complete` 或 `closed`，直接显示原记录，不再次 POST。

## 查询接口与交付边界

- `GET /federation/assets/materials?limit=20&offset=0`：当前机构的快照类型、摘要、来源及创建时间，不返回正文。
- `GET /federation/commercial-agreements/:revisionId/market-requests?limit=20&offset=0`：当前机构、本站及该合同的私有市场请求进度。
- `GET /federation/commercial-agreements/:revisionId/market-requests/:reservationId`：同一隔离范围内、精确预约编号的进度及私有请求原件；不返回内部签名或工作租约。

## 仲裁、披露与 R 案件操作

商业合同详情的“仲裁与披露”包含仲裁政策、披露政策、单次披露和案件存证授权。沿用既有后端的草拟、签署、对方签名关联、永久撤销接口；政策不代替单次披露授权，披露授权不代替案件 PDC 发布授权。字段选择来自共享 schema 白名单，必需证据只能取允许披露字段的子集，金额始终使用整数字符串。导入对方条款须先核对合同、域及两端站点，再由本站独立签署。条款原件可展开复制，签署后可复制本站签名，供对方确认。签名交换、案件链提交和撤销通知分别显示状态，待复核记录恢复既有队列；仲裁政策撤销在非 direct 模式下可单独提交撤销存证。

| 操作 | 权限 |
|---|---|
| 查看仲裁／披露政策 | `agreement.read` |
| 签署、关联、撤销仲裁政策 | `arbitration.approve` |
| 签署披露政策、创建单次披露及关联／撤销 | `disclosure.approve` |
| 案件持久存证授权、存证恢复 | `case.publish` |
| R 登记、收取和重新授权读取证据、关闭案件 | `disclosure.receive` |
| R 查看裁决、核对双方当前状态 | `arbitration.read` |
| R 签发裁决、恢复送达 | `arbitration.decide`；签发还需要 `disclosure.receive` |
| R 裁决承诺上链与恢复 | `arbitration.read` + `case.publish` |

“仲裁案件”是接收机构 R 的工作台，使用自身机构会话。登记现有案件范围后，填写双方已批准的授权 ID、政策摘要和披露摘要获取限定字段；选择材料核对双方状态与财务目标，填写裁决理由、处理方式及收费金额，预览后独立签发。每次查看证据重新调用后端授权读取接口，历史缓存不代替当前授权。签发确认直接展示案件、处理结果、收费金额/单位及理由，完整原件可展开核对；政策金额上限与裁决实际收费分别标注。裁决原件、送达双方、案件链承诺分别跟踪；送达不表示双方已经执行，实际执行继续由双方合同争议页完成。关闭案件不结清双方账目，也不删除历史记录。

签署或裁决提交结果不明时保留原编号、条款和 salt；恢复先查原记录，查读失败不当成不存在，找到原件后核对完整意图，避免重复签发。登记案件同样重用原范围。机构、身份和合同切换隔离页面状态；所有新查询关闭窗口聚焦刷新。手机遵循平台高风险操作策略，只读查看。

## 历史存证恢复与重新批准（研发候选）

异步商业合同的存证明细可按原提交建立历史恢复草稿，核对原操作／编号、原摘要、完整原提交摘要、恢复理由，再独立批准。原业务已成功或交易结果未知时不能切换协议；先恢复原 transactionId。批准仅承认历史事实，不重做作业、扣款或解冻，也不把新归档回执显示为原业务成功。

具有独立 `attestation.recover` 的人员可导出恢复文件交给原对方。对方从合同存证入口导入，核对本机构已有事实和同文原件后独立批准；当前双方签名分别显示。文件含敏感原件及签名，应通过受控方式交给 A/B。若导入建立本站缺失的原提交，它只成为不可执行的 `HISTORY_ARCHIVE_ONLY` 归档，不进入原业务重试。

签名轮换后，服务端允许时可确认“重新批准”。它保留原恢复正文、编号、摘要和旧批准历史，清除当前对方批准并等待新对签；已提交、租约有效或未知交易均拒绝。页面按机构／身份重建状态、手机只读，响应未知保留原意图；完整规则和接口见[历史恢复](history-recovery.md)。链端信任另经各机构批准并显式更新，页面批准不能替代全组织原生背书。
