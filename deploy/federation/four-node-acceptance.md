# 四节点 SmartBFT 运行

四个 Orderer 分布在三个机构主机与一台独立排序主机。A/B/C 各自保有平台数据库、登录、Registry、对象存储、Peer 和 Adapter；第四主机只运行独立 Orderer 项目。平台组件更新不重建账本、机构 MSP 或通道。

## 网络与身份

机构 Peer 与四个 Orderer 使用可达的内网地址、正确 SAN 和双向 TLS。管理员端口仅容器网络可访问。通道 consenter、endpoint 和 Peer anchor 配置不能使用其他主机无法解析的容器名称。

叶证书有效区间应位于签发 CA 有效区间内。CA、叶证书和机构密钥分别保管，不关闭 MSP、TLS 或主机名校验来绕过身份错误。业务 JWS 身份与 Fabric MSP 身份分别配置。

链码名称以交付配置为准；生命周期定义、CCAAS package ID 和 Adapter 必须一致，例如证据链码为 `kq-evidence`。各机构独立批准通道和定义，启动容器不会自动获得治理批准。商业集合保留指定机构的读取和 `AND(A,B)` 背书边界。

## 正常运行

运行状态分别观察进程、通道参与、区块高度和业务交易。`active` 或 TCP 可达不能代替交易 `VALID`。三个 Peer 在追平后应有相同高度和区块摘要；私有数据还须按各自成员权限确认完整。

业务提交、响应未知和恢复均使用原 transactionId 与 sealed checkpoint。配置或恢复密钥变更前先处理在途交易；不清理原队列或创建另一交易掩盖未知结果。

## 停机与追平

四节点配置容忍一台排序节点停机；其余节点继续按原共识策略工作，恢复节点从原账本追平。停机容忍不等于已经覆盖恶意消息、审查攻击或跨地域容灾。

Fabric 3.1.5 的双向 TLS 拉块配置及 `simple` 的使用边界见[排序节点追平](fabric-evidence.md#fabric-315-排序节点追平)。不要在恢复中删除区块、重建通道或降低机构背书策略。

## 平台维护

维护前固定提交、镜像、配置和备份。每次只替换受影响的平台组件，保留各站数据库、权限和对象数据；具有旧联邦分支迁移历史的库使用[保留数据升级规则](aio/main-upgrade.md)。

三机构平台保留聚合内存保护与容器限额。空闲占用不代表峰值容量；启用调度器、软件安装或 R 前重新核算完整预算。当前调度器、Agent、R 和 C 站 Runner／DinD 保持关闭，数据保留。

日常人员操作见[平台使用准备](aio/trial-readiness.md)，协议与恢复要求见[行为契约](../../docs/design/federation/acceptance.md)。
