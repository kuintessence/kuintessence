# 任务私有输入与结果的介质交付

任务介质将原工作流的私有输入和结果打包为加密文件。来源机构批准并导出，接收机构校验导入后，将文件发布到原任务的输入或结果位置。任务在交付和授权条件齐备前保持等待。

## 任务交付方式

任务介质包括准备、导出、接收批准、私有导入、自动上传派发及原输入/结果校验发布。每个步骤都保留原任务、文件版本和当前授权绑定。

已有网络任务输入来自 `federationWorkflowInputExports` 的不可变快照，绑定 Workflow invocation、文件所有人及对象版本；结果清单来自原执行绑定及已持久化产物。常规网络传输具有独立源授权、接收配额、Agent 复制/校验和原子发布。现有数据集介质导出则只读 `cp-local` 受管目录，任务介质不能伪装成临时公共数据集来绕过这个差异。数据库结构已将出口选择器区分为数据集版本/位置与原任务引用，任务源绑定只保存在本站。

- `FederationMediaObjectBindingSchema` 固定包、导出代次、清单摘要、文件序号/路径、大小、SHA-256 和非空、非 `null` 的对象版本。对象键与短期 URL 不进入可携带清单。
- `readFederationMediaObject` 在 Agent 读取获批 HTTPS 对象，使用现有严格 Range 读取器，每个窗口最多 1 MiB。每次响应核对版本，拒绝重定向、非准确范围、压缩响应、截断、额外字节和最终摘要不符。
- 短期 URL 只接受本机配置的存储 origin，许可最多 30 秒且不超过操作期限；临近到期重新领取，读取完强制重新核对授权。等待许可最多 10 秒，读取受许可到期和取消信号约束。空文件同样执行版本化 GET、确认零字节及重新授权，不能用预签名 GET URL 发 HEAD。
- 受管目录与对象流共用 `exportMediaArchiveFromFiles`。归档器只向读取器传递验签清单中的文件，核对准确大小和 SHA-256，保留许可证及完整 provenance；本地文件仍拒绝硬链接、目录内符号链接及读期间变化。

对象读取器仍是内部能力。Server 已接入下述任务包准备、密钥重新授权及 Agent 对象导出命令/下载许可；没有增加可由普通用户传 URL 或磁盘路径的接口。数据集的生产导出入口继续使用受管目录；任务输入/结果分别沿下文专用入口准备、导入和发布，不能绕过类型检查套用数据集流程。

## 来源清单准备与密钥重新授权

`POST /api/federation/media/exports` 保留原数据集正文，另接受任务正文：

```json
{
  "packageId": "11111111-1111-4111-8111-111111111111",
  "agreementRevisionId": "22222222-2222-4222-8222-222222222222",
  "recipientSiteId": "33333333-3333-4333-8333-333333333333",
  "kind": "task-input",
  "operationId": "44444444-4444-4444-8444-444444444444",
  "agentId": "local-storage-node",
  "expiresAt": "2026-12-01T00:05:00.000Z"
}
```

`kind` 可为 `task-input` 或 `task-result`。字段只选择原任务和本站组织 Agent；不接收调用者提供的 taskId、attempt、文件列表、对象键、版本、下载地址或目标用户。缺少文件的任务不创建空介质包。

输入准备要求原 outbound 已签名接受、没有取消，并重新核对原工作流所有人、运行状态、delegation.submit、输入快照及双方协议；原请求和接单回执重新验签，不能仅信任数据库中的已接受状态。结果准备复用已有结果披露策略、原执行身份、完成工作流和持久产物检查。结果可在计算协议截止后、独立 resultPolicy 截止前交付。两类都要求当前人员 media.export 和当前 Agent 的组织归属。

准备事务先取快照，事务外生成实际 age 包身份并签名，提交事务再次检查；期间文件版本/归属或授权变化不能保存旧批准。数据库约束保证存储选择器互斥；同一包 ID 只重放原选择器、清单及版本，不能更改期限或换文件。人用 API 保留清单、签名和批准记录，不返回对象键、文件私有 ID、包私钥及其密文。

密钥响应先校验 mTLS 对端和签名查询，再在数据库锁外做需要的资产/链授权预读，事务内复查原批准、任务和文件绑定；重放也复查。批准期限最长七天且不超过业务交付期限；短期解密许可另受当前协议/请求签名密钥及协调模式确认期限限制，不把短期链确认当成整个物流包的有效期。直接合作无需 Fabric，协调模式缺少有效确认时不放行。

对象任务的 `/exports/:id/run` 现已接通下述来源导出。目标任务已绑定交付方式并接通对象上传及原子发布服务；准备成功不等于已生成加密文件，来源导出成功也不等于已解除 DATA_WAITING。

## 必须保持的任务与授权绑定

| 方向 | 源端依据 | 接收端归属 |
| --- | --- | --- |
| 任务输入 | 本站原 outbound、双方协议、原委派请求及 requestDigest、对应 invocation 的输入快照；当前原文件所有权与版本 | 原接单 reservation 的执行身份及 input import；只供该 taskId/attempt |
| 任务结果 | 原 reservation / workflow binding、双方 resultPolicy、真实完成产物及其签名结果清单；当前可交付期限 | 原 outbound 的本地请求人、结果 import 与原 workflow invocation |

输入包的 `contentDigest` 必须等于原委派的 inputFilesDigest；结果包必须绑定接收方验签认可的原结果清单摘要，并核对 template、输入摘要和环境锁。两端机构随方向固定；输出不能被包装成新的输入授权，也不能换 taskId、attempt 或机构复用。包 ID 仍为随机值，不具备授权能力。

操作人员需要 `media.export` / `media.import`，但这些机构权限不隐含读取其他用户私有输入的能力。输入准备还需原文件所有人/原工作流授权；结果执行机构需在原协议的明确结果披露范围内操作，结果接收对象从原 outbound 推导，不接受调用者指定任意目标用户。

每次准备、开读、续期、发放解密材料、导入发布都复查原归属与当前授权。接口只接收受控 ID，不接受调用者自报文件列表、摘要、绝对路径、对象键或下载 URL。原始文件已经不存在、版本改变、授权失效时拒绝；不回落到“最新版”或同名文件。

## 存储与数据流

任务成员按已验签清单的原数组顺序编号，以固定 `objects/000000` 等名称进入包，避免不同描述符/输出具有同名相对路径时互相覆盖。原 descriptor/outputId、路径和数组次序由原输入/结果清单恢复；接收方必须用同一清单重新计算成员映射，并逐项核对包内文件。不存在的许可证/provenance 显式保留为 null；已存在的来源元数据不能被丢弃或重新编造。

源 Agent 从本机构对象存储直接按版本读取并流式传入 age，密文写入本机介质 outbox。源端不增加明文整包暂存，也不让 Server 传文件内容。读取器授权回调现由机构内受认证 AgentStream 连接提供，固定原对象版本；普通 HTTP 不返回文件读取许可。

接收 Agent 完成 age 认证和全部文件校验后，文件仍在私有隔离目录。后续由 Agent 将其写入接收方受版本管理的对象存储，复用既有 multipart、代次隔离、容量预留和实际重读校验。导入所有成员完成并重新核对源端许可后，复用原输入/结果 import 的原子发布；不得逐个向用户或作业暴露已复制成员，也不能直接把隔离路径填成普通 netdrive file。

交付方式需持久绑定原任务，使用介质时保持 DATA_WAITING，输入复制 worker 不能同时偷偷启动网络复制，失败也不能自动改成网络交付。数据完成与授权有效同时满足，才解除等待。结果侧同样保留原 invocation 的等待和结果回执，避免“结果已产生”被误认为“结果已收到”。等待交付不是计算失败，也不增加计算用量。

物流、解密许可、任务使用权、结果回执和副本删除仍独立。运输“已收到”不解除等待；原导出批准撤销也不能被运输记录覆盖。真正的任务使用/执行检查沿原委派的持续授权机制处理。副本删除需等持久停止/收尾证据，不能因为介质返还就删除已使用数据。

## 控制面与文件传输

- 目标审批服务：已沿原输入/结果 import 核对任务、接收归属、配额和介质清单，并限制当前密钥请求；上传/发布操作继续核对这些绑定。
- 接收侧对象上传/校验/发布：绑定完整任务包、原配额和原输入/结果 import，持久记录代次与方式并自动派发。
- Web/CLI：在原任务中选择并查看交付，按原记录执行准备、导出、登记、批准、导入与查询；不增加可绕过业务归属的原始 URL 表单。

## 诊断入口

对象读取器的单元诊断使用受控版本化 HTTP 服务和授权回调，检查版本、范围、大小、摘要及授权失效。双平台流程另见[私有任务介质运行](../../../deploy/federation/execution-lab.md)，需实际存储、Agent 与控制面连接；介质文件搬运不替代这些运行条件。

## Agent 实际来源导出

Server 配置 `FEDERATION_MEDIA_OBJECT_DOWNLOAD_ORIGINS`，源 Agent 在 `AGENT_FEDERATION_MEDIA_EXPORT` 中配置 `allowedSourceOrigins`。两边默认空，不继承网络输入/结果复制设置。生产初始化复用 NetDrive 的 MinIO 后端；Agent 与 Server 新增 `federation_media_object_export_v1` 协商，受管目录命令格式保持兼容。旧 Agent 不接对象任务；未配置允许来源的 Agent 不宣告对象能力。

`/exports/:id/run` 持久排队，沿原 generation、lease、report 通道派发。命令只含固定成员序号/路径、大小、SHA-256、对象版本，不携带源文件 ID 或对象键。Server 对每次逐文件请求复核原任务、当前操作人和 Agent、包/代次/清单/成员，在事务外按原键和版本 HEAD/presign，之后再复查；版本、大小、签名 URL 的版本参数、origin、真实 URL 到期与任务许可均须匹配。连接被替换后不向旧连接返回 URL。

Agent 验签清单后核对完整成员顺序和内容，直接按版本 HTTPS 读取并流式进入 age，源端不落整包明文。完成文件与目录同步后、原子发布前重新授权；错许可、取消或最终撤权不发布完成包。既有完成包的回执摘要额外固定对象版本，恢复或新导出代次复用原密文字节，仍需当前授权。读取实际遵守完整 TLS 信任链，不关闭证书验证。原容量检查、内核工作目录锁和遗留临时目录恢复逻辑继续共用。

## 签名固定任务文件交付方式

委派和 Workflow Federation 节点新增可选 `inputDelivery`、`resultDelivery`，分别接受 `network` 或 `media`。两方向可独立选择。省略表示原网络路径，解析旧签名时不补字段或默认值，避免改变摘要。输入选择 `media` 必须同时绑定 `inputFilesDigest`；Workflow 先按原文件槽生成不可变清单，再签署委派。交付方式参与原 invocation 快照和请求摘要，重试不能更换；不提供运行中自动回退或切换接口。

数据库结构为原输入/结果 import 添加 `delivery`，已有记录默认 `network`。新导入从原请求保存模式，重启后继续使用；领取复制许可时核对原任务模式，缓存字段被改为 network 也不能放行。输入和结果网络 worker 均排除 media；来源文件下载接口也检查已接受请求，不签发网络数据凭据。任务元数据和授权仍通过原受控接口交换，介质交付不意味着完全断开控制面网络。

来源介质导出只接受原委派选择的对应 media 方向。接收 inventory 和配额继续由原 import 管理，未到齐时保持 pending，取消后按原存储清理规则释放配额；无上传副作用时可立即释放。结果保留原 resultPolicy 独立交付期限。media 任务在全部材料发布且授权有效之前保持等待，单独取得批准或密钥不会解除 DATA_WAITING。

## 接收任务清单与批准

接收机构先具有原任务的输入/结果 import，再登记来源签名包。输入 inventory 由原 preparation worker 自动获取小清单并预留原执行身份配额；结果由原任务所有人通过既有结果导入接口获取签名清单并预留自己的配额。media 方式不会因此触发网络数据复制。没有原 inventory 时登记返回 DATA_WAITING；不从介质清单凭空创建工作流、接收身份、配额或结果文件。

输入包核对原接单、请求签名、持续授权、执行身份、交付方式、完整输入摘要和按原顺序对应的对象成员。结果包反向绑定原委派所有人及已签名结果 report，核对原请求和回执、工作流/输入/环境锁、完整结果清单、当前 resultPolicy、配额和独立结果期限。两方向均按 objects/000000 等固定序号核对 SHA-256、大小和完整数量，不能换任务、尝试次数或部分清单。

数据库结构为接收包增加私有 input/result import 外键并限制方向互斥。结果返回来源机构时使用原 source approval，因此删除了只指向执行方 agreement 表的错误外键，分别由原任务授权服务验证方向。注册原文重放必须保持同一个 import；取消后新建的 import 不能接管旧包。已有未绑定任务 inventory 保留历史，不自动推断或回填关系，也不能新获批准或密钥；新登记必须具有当前原任务绑定。

任务清单的列表、详情、批准和撤销仅对原登记人员开放，结果登记还必须是原委派所有人；数据集保留既有组织权限。运维物流页仍只显示运输摘要，不提供文件清单、密钥或使用权。Agent 与受管根必须属于接收组织，批准期限不能超过原业务期限。协调模式预取在事务外进行；原任务/import 先锁定，再锁包与批准，避免相反顺序造成竞争。业务批准不持久保存短期链/签名许可，每次密钥请求前后重新核对并受当前最早期限约束，许可在网络往返中缩短也不能返回旧长效密钥响应。

JWS 原始字节摘要与规范化内容摘要分别核对，避免把相同 JSON 的不同序列化顺序误判为内容变化；包保留来源签名、许可证和 provenance，内部 import ID 不进入公开摘要。登记、批准、内部密钥请求、自动上传派发和整包发布均保留这些绑定。批准或密钥响应只允许推进对应步骤，不表示任务文件已发布。

## 隔离任务文件的 Agent 上传器

新增内部 `FederationMediaUploadTask`，同时携带接收包/批准/导入代次、原任务传输代次、成员序号和输入/结果绑定。Agent 核对来源签名、原 operation/content digest、固定成员路径、大小和 SHA-256；完整原 inventory 与目标任务槽的映射仍由 Server 决定，不接受任意本机路径。

上传使用已解密包的私有受管目录和原内核工作目录锁，检查目录归属、文件权限、单链接及常规文件类型，以 O_NOFOLLOW/O_NONBLOCK 固定文件句柄。上传前流式校验内容，随后复用原分片上传器直接读取同一文件句柄；不再复制一份完整明文，不读取同名替换文件。读取期间按当前期限刷新来源许可，每片重新核对来源密钥授权与目标上传许可；目标许可不能晚于来源许可，PUT 受最早到期时间和取消信号限制。结束后再次检查来源授权、路径和文件元数据，仅返回未提交的分片回执。失败保留已校验包；未完成目标分片仍需后续 Server 清理，不在 Agent 端猜测完成或发布。

数据集导入与任务上传共用来源授权校验，修复原 15 秒固定缓存可能超过实际短许可的问题。来源密钥自身到期时间也限制许可；取消或超时不返回迟到成功。原网络输入/结果复制继续使用相同分片逻辑和独立目标验证，调用方持有的文件句柄不会由上传器关闭。

## 原任务领取与私有导入运行

数据库新增 `federation_task_media_claims`。每条记录绑定原输入或结果 import、接收批准和介质导入代次；两个方向互斥，同一原 import 同时只能有一条未释放领取。历史记录只追加释放时间，不覆盖旧代次。原配额仍由原 import 持有，领取、解密和私有校验不新增任务、不生成 NetDrive 文件，也不返还原配额。

现有 `POST /api/federation/media/packages/:id/import-authorizations/:authorizationId/run` 可对任务包排队私有导入。登记和批准仍先核对原签名任务、接收所有人、完整清单和交付模式；启动、派发、密钥响应前后及 Agent 报告均重新验证当前原任务与领取。协调授权预取在事务外完成；锁顺序为原任务/import、包/批准、操作、领取。重复启动复用同一代次，竞争包或竞争批准返回冲突。原有介质导入命令负责私有解密校验，`verified-private` 回执只表明隔离导入完成，不代表原任务文件已经发布或可执行。

失败后重试创建新代次。更换包或批准时，旧操作须失败，或旧批准/包已经撤销、批准到期；并且原 import 的所有旧存储尝试都已达到 `cleaned`。即使上传进入 `cleanup_pending` 也不能更换。检查、旧领取释放、新领取及审计在同一事务中；审计失败保持旧领取不变。旧代次或旧批准的迟到报告/密钥请求不能覆盖当前操作。已经领取的同一代次可以继续原有传输，不能据此收养别的代次文件。

派发租约和密钥响应受当前原任务授权期限限制。收到来源响应后再次检查；处理 verified 报告时还检查来源 grant 的当前签名密钥期限，防止独立轮换密钥被缩短后继续使用旧长许可。输入保持执行授权限制，结果保持原独立结果交付期限。

任务专项使用进程内签名来源请求和注入的 Agent 报告，来源准备使用实际 age。它验证 Server 生命周期，不等于真实两平台任务介质执行；原数据集回归包含生产 Agent 客户端的实际 age 导入。后续上传续租不得覆盖私有导入操作的 `latestGrant`，该字段参与既有历史导入回执的内容绑定；新上传授权须独立核对当前领取及来源许可。领取机制不代替目标版本、全量成员、SHA-256、配额和当前授权的发布检查。

## 上传来源授权与历史回执隔离

接收端沿既有 Agent 密钥请求消息接受可选 `purpose: "task-upload"`。省略仍为原私有解密请求；只有已完成私有校验、仍持有原任务活动领取的 Agent 能请求上传来源授权，数据集与未校验任务包均拒绝该用途。此处只授权读取隔离文件作为上传来源，不创建对象上传、不签发目标 PUT，也不发布任务文件。

领取记录保存独立 `uploadGrant` 和请求令牌。它们是短期授权缓存，领取归属与历史代次保持不变。每次刷新先清空旧上传许可并记录新令牌，再在事务外请求来源；返回后重新验证原任务、接收批准、领取代次及令牌，迟到响应不能覆盖较新的请求。来源不可用或拒绝时不会继续使用已清空的旧许可。原私有导入操作的 `latestGrant`、`receipt` 和时间戳完全不被上传续租修改。

新增内部上传任务快照与事务授权读取器，调用方须在自己的事务外准备读取器。使用缓存时重新核对包/批准/代次、来源与接收站点、原任务、Agent/root、字节上限、批准期限和来源签名密钥当前状态；来源许可失效或本地撤权后不能继续使用。除签名本身，还重算原密钥查询的字节摘要。PostgreSQL JSONB 会重排字段，因此先按协议 schema 恢复签名时的字段顺序，再计算 SHA-256；不能直接对 JSONB 读出顺序哈希，也不能改用规范化内容摘要代替原 JWS 字节摘要。

上传尝试固定这条领取，复用原存储准备/完成/验证/清理和配额路径；发布必须重新检查当前来源许可。

## 输入介质的目标尝试与原子发布

发布先确认当前来源许可和全部成员的领取归属，检查固定对象版本后再次请求来源授权；原清单、所有成员、配额转换及文件登记仍在同一事务完成。等待数据库锁不能跨过签名有效期，历史私有导入回执不变。迟到的 multipart ID、完成版本及撤权后的清理不依赖来源恢复，未完成清理不释放原配额。旧网络 worker 继续排除 media，输入网络下载读取器也明确拒绝介质方式。

## 结果介质的目标尝试与原子发布

目标校验续租/报告与发布分别刷新来源许可。发布在来源 I/O 前先检查原机构、原任务所有人和 result.read；HEAD 后重新确认包授权，并在事务内检查全部成员所属领取、固定版本、原结果报告和当前期限。原文件、结果回执与配额一起提交，私有介质导入回执保持不变。结果交付继续采用独立于计算期限的有效期，已发布摘要可幂等读取。

存储返回 multipart ID 后新增一次当前授权检查，撤权期间生成的上传 ID 仍被记录并保留清理责任，但不会派发任务。失败后只有完成旧代次清理才能重试，沿用原预留配额。取消、迟到 ID 记录和清理均不依赖新的来源许可；原网络 worker 仍不派发 media，来源下载接口仍拒绝介质方式。

## Agent 上传命令与能力协商

来源授权复用原介质密钥请求（task-upload 用途），目标授权及复制报告复用原输入/结果消息。客户端按请求 ID 和消息通道分流，分别核对介质代次和目标代次；错通道不能消费待处理请求，重复命令不能替换活动任务，断线取消读写及挂起授权。来源刷新同时获取目标第 1 分片许可以续租现有上传尝试，允许长文件预哈希持续运行；这一步不发送 PUT。实际分片仍逐次检查正确绑定、分片号和来源/目标最短期限。报告只返回原目标的未提交分片，随后仍由原独立校验流程检查目标对象。

后台上传候选扫描、派发及断线清理重试已接通，见下一节。

## 任务介质自动上传派发

主 Server 启动 `FederationMediaUploadTransport`，每十秒从原任务 import 的待传成员中选择工作。必须同时满足私有包已 verified、领取未释放、批准及包未撤销、Agent 在线且组织匹配；同一 Agent 的原输入/结果活动尝试继续共享持久传输槽。输入和结果轮换优先顺序，每轮最多四个 Agent，尝试后的扫描时间持久保存，重启后沿原记录恢复。

派发前按原清单数组顺序计算成员序号，并重新向来源申请上传许可；仍使用同一领取的原 import 创建 multipart。创建后重查当前授权及连接，再发送上传命令。来源代次与目标尝试代次分别绑定，不能用一个覆盖另一个。Agent 的完成报告继续经过原输入/结果 transport 的存储完成、独立校验和原子发布；网络 worker 不接管介质任务。

断线或创建期间撤权会将已分配上传记录留给原清理流程；只有确认旧存储清理且当前许可有效，才创建新的目标代次。旧隔离导入回执不会被上传续期改写。客户端仍沿用原传输配置格式；只配置目标 origin 时可使用下述独立上传/校验能力，不启用网络复制。

## 纯介质目标配置与版本兼容

Server 在本地目标 origin 齐全时装配传输、校验和发布服务，不再要求远端来源 origin。存储服务显式区分 `canCopy`；没有来源 origin 时，网络扫描和派发关闭，来源 GET 许可在外部请求前拒绝，目标 PUT 与版本化校验 GET 继续沿原授权。

Agent 的 `allowedSourceOrigins` 可为空或省略；仍必须配置目标 HTTPS origin。输入/结果客户端独立声明目标校验能力，不宣称可以网络复制，直接收到网络复制命令也不会开始。新增 `federation_target_transfer_v1` 和独立 verify 支持响应，保证旧 Agent 不会收到无法处理的纯介质命令。旧 Server 的复制支持响应仍可用于完整网络配置的兼容协商，纯介质客户端不会据此开启网络复制。

配置示例见[部署说明](../../../deploy/federation/README.md#纯介质任务接收)。授权、私有包/原任务绑定、短期租约、独立存储验证、整包发布和控制面网络要求均保持原规则。纯介质配置不改变输入就绪、执行授权和结果发布的判断条件。

## 私有任务介质双平台运行

隔离样例使用两个轻量 Kubernetes Job，分别产生 `42\n`（3 字节中间文件）和 `verified:42\n`（12 字节结果）。结果仍按原 Workflow 建立 media import，由执行机构导出，再反向搬运、私有校验、上传和发布。原远程节点和下游消费节点只有在全部文件就绪后继续。

该样例使用同机隔离的直接合作和轻量脚本，不包含实际邮寄、跨主机部署、完全断网、Fabric 协调介质矩阵或科学软件安装。控制面保持在线，持续核对来源授权。

## CLI 操作入口

`kq federation media exports` 已支持分页查询、详情、批准、运行、状态、登记清单文件保存、来源回执查询及撤销。`media imports` 已支持分页查询、批准分页、登记、批准、运行、状态、回执查询/重试、包与单项批准撤销。命令复用原生产 API，固定当前机构，不额外要求运输权限；写操作不自动重试，批准不隐含运行。共享响应 schema 过滤内部字段，核对包/原任务/批准及回执关系；状态将私有验证和原任务完成分开。清单文件以 0600 新建、不覆盖已有文件，原签名、SHA-256、license/provenance 保留在受控视图中。

## Web 介质交付入口

联邦页面新增“介质交付”，与介质、运输批次及交接记录的“介质物流”分开。按当前机构查看“发出／收到”，进入包详情后分别批准、运行或撤销；导出签名清单下载为原 `senderSiteId + signedManifest` JSON，接收方选择该文件登记。登记本身不解密，也不授权运行。

导出支持任务输入、任务结果和共享数据集。合作协议、Agent、接收目录使用机构内分页选项；任务输入／结果从原工作流绑定中选择，自动带入委派、协议和接收站点；共享数据集按名称、版本、Agent 和目录名称选择，版本与副本编号由同一候选带入。接收批准明确 Agent、受管目录、字节上限和期限，再单独运行。包撤销与接收批准撤销使用不同文案，批准／排队／私有校验／回执确认分别展示；私有文件校验不代表已发布或任务成功。

包详情保留各文件的 SHA-256、许可证与 provenance，缺失项明确标记。签名清单及双方回执按需展开；回执与包、站点方向、摘要、导入代次绑定，来源分页查询不下载原科研文件。页面没有文件系统路径、密钥或对象存储凭据输入。

选项接口 `GET /api/federation/media/options` 要求当前人类成员的 `asset.read`，支持 `kind=agreements|agents|roots|datasets`、`limit=1..100`、`offset>=0`；目录额外要求 `agentId`。只返回当前机构、本站的双签活动协议摘要，或当前机构所属 Agent，以及双方归属匹配且启用的受管目录名称。协议执行期届满后仍可能有独立结果交付期，因此候选同时返回两个期限，不以列表代替实际授权检查。合同条款、签名、密钥、Agent 拓扑和目录真实路径不进入选项响应。

网页查看需要 `asset.read`；登记及包撤销需要 `asset.map`；导出批准／运行／撤销需要 `media.export`；接收批准／运行／撤销及回执补报需要 `media.import`，不要求 `media.logistics`。原 Server 授权、归属、有效期和业务校验不变。切换机构或登录会话清空选择；首次读取失败时显示重试入口；同一机构的后台刷新失败保留已读内容，权限被拒绝时隐藏旧记录并禁用写入，未知写入保留原编号与正文，不自动重试。登记后回读原签名清单，不能仅凭另一包的成功响应结束表单。

## 原工作流与交付记录

工作流页面提供“介质交付”入口。来源工作流按原运行编号查看发出和收到的包；执行机构的已完成工作流进入结果交付。列表、分页和新登记请求保持该工作流筛选，包详情继续复用原接口。完成或取消后的工作流仍可查询历史，历史记录不重新授予导出、导入或使用权。

任务输入／结果导出表单改为选择已有任务：`GET /api/federation/media/tasks?kind=task-input|task-result` 支持 `workflowRunId`、`limit=1..100` 和 `offset>=0`，要求当前人类成员的 `asset.read`。输入候选只包含原提交人、本机构、本站、已接单且原工作流仍运行的介质任务，并核对执行日志与 outbox 的同一请求。结果候选只包含本执行机构已完成的原工作流及介质结果声明，核对原接单、执行身份和工作流绑定。候选不返回价格、合同原文、签名、身份凭据或对象存储路径；最终批准仍执行原授权检查。

`GET /api/federation/media/exports` 和 `GET /api/federation/media/packages` 可使用 `workflowRunId`，按原委派／接单绑定与双端站点关系筛选，保留原机构和私有包所有人限制。`POST /api/federation/media/packages?workflowRunId=...` 在登记前额外核对签名包与所选工作流；错工作流、错机构或不匹配的原绑定不能写入。筛选不依赖当前运行状态，过期或撤销后的历史也不会因此消失。对未建立本地工作流的执行方 DATA_WAITING 输入，仍由全局“收到”入口登记与批准，不伪造占位工作流。

页面从任务带入的用途固定，切换用途或工作流会清除旧选择和草稿；接收的清单仍由原 Server 验签。单独打开全局交付页时，可在任务候选中选择工作流／节点调用，不再手填委派或合作协议编号。工作流权限与材料权限彼此独立，原工作流可见不代表自动拥有材料操作权。

## 共享数据集的导出选择

`kind=datasets` 从本机构 Agent 和启用的受管目录中分页寻找可用本地副本，复用导出准备的同一披露授权检查，只返回已发布、不可变且就绪的原始数据集。仅有公开可见或使用权不足以导出；下载、再分发及跨中心复制限制、过期／撤销和联邦导入数据的禁止转交规则继续生效。候选不包含真实路径、文件清单或合同原文。

页面用一个选项同时带入版本和副本，不再手填两个 UUID。切换用途清除旧选择，加载失败不能提交；实际导出仍重新核对协议、授权、完整清单、许可证和 provenance。为限制查询开销，分页先截取至多 100 个本地存储候选，再核对披露授权；因此可能出现空页而 `hasMore=true`，可继续下一页，不代表已无其他候选。此接口不下载或读取科研文件字节。
