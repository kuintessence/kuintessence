# 平台与联盟链人工试用

本说明记录 main `90a4eaa` 的人工试用准备范围。三机构使用独立平台、数据库、对象存储、登录与权限；调度器、Agent 和仲裁方 R 不启用。试用准备不能代替 [38 项完整验收](../../../docs/design/federation/acceptance.md)。部署方应单独提供受控入口、测试账户、材料原件与证据，不把凭据、内部主机清单或业务签名提交到仓库。

## 应用层跨站通信

Fabric 连通不代表平台间协议能够交换。每站还需要：

1. 网关绑定经过批准的内网地址；Server 能解析对方的 HTTPS 主机名。不得公开数据库或绕过机构网关直接调用 Server。
2. 通过平台管理 API 登记站点、精确 HTTPS origin、业务签名公钥、用途和 TLS 证书指纹。平台管理员的管理权限不等于机构签约权。
3. Server 客户端和网关使用包含各合作方公共根证书的信任集合，各站私钥仅留本站。机构独立 CA 使用不同 issuer 名称，CA 和叶证书保留正确的 SKI/AKI；多套同名且缺少标识的独立 CA 可能导致 TLS 库选择错误签发者。
4. 新证书先追加登记，再逐站轮换联邦客户端和网关的证书、信任集合；保留必要的旧指纹历史和回退配置。联邦传输证书、网页登录证书、业务签名身份与 Fabric MSP 分别管理，不关闭证书或主机名校验。

只重建受影响的 Server／网关，使用 `--no-build --pull never --no-deps`，核对链节点身份及资源限制不变。网络恢复后查询原协议交换和原交易，不通过重签协议、重发新需求来掩盖原记录未恢复。

## 账户与可操作范围

原签约使用独立测试审批员，通过真实 SSO 登录，以普通平台用户身份取得机构成员关系和显式 `agreement.approve`、`asset.map`、`market.publish`、`market.claim`。后续内网试用的五类登录账户与既有主服务对齐，各站仍独立保存用户与权限；机构管理员获得原审批员的四项业务能力，普通用户保持读取权限，不开放任务提交。平台管理员和超级管理员不自动取得机构签约权。停用旧测试登录并撤销旧平台会话时保留历史用户、审批人和业务签名，不重签旧协议来替换历史身份。

每站以一个 HTTPS 域名分流平台、`/sso/` 和对象存储，配置见 [AIO 私有配置](README.md#私有配置与正式身份)。浏览器只需要本站平台域名；OIDC issuer、授权入口、令牌端点与回调须保持一致，不能只验证首页可达。对象存储保留原生桶路径及签名查询参数，用小文件实际上传、下载并核对 SHA-256。内网人员登录凭据可按部署要求与主服务对齐，数据库密码、OIDC 客户端 secret、机构私钥和 Fabric MSP 仍各站独立。

受限执行身份是独立服务账户，不能代表人员签署机构协议。创建身份时产生的临时 API token 在准备完成后撤销；服务身份保留不代表存在有效 token、已注册 Agent 或已准备执行环境。

建议人工按顺序操作：分别登录三机构，核对当前机构；查看双方已签的直接／异步存证协议及商业条款；暂停并恢复测试协议；查看与导出输入快照；发布公开测试需求、从另一机构查看，再取消；最后切换到只读用户确认写入口与 API 权限均受限。测试账户双签不代表真实合作机构正式签收。

## 科研与恢复边界

输入快照、已签条款或镜像携带 Spack，都不能证明脚本已经发布、软件已经安装或环境锁有效。调度器与 Agent 关闭时不提交计算任务，不把零价格合同、市场状态或合成材料当成科学计算结果。真实任务需要按最终调度器镜像准备受批准脚本、runtime profile、recipe、源码、许可证、provenance 和目标 native lock，再通过平台完成安装和作业执行。

隔离数据库物理副本的启动与同次逻辑备份内容核对，只证明该数据库备份范围可恢复；不能据此认定整个平台启动、Peer/PDC 恢复、账本归档或代际迁移通过。上述项目及完整仲裁分别记录，缺陷修复只重跑受影响场景。
