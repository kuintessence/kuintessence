# 加密介质包：格式与 Agent 底层

当前已接通来源 Agent 实际导出、机构间独立密钥交付和接收 Agent 解密校验。接收端将完整文件保存在私有目录，Server 记录为 `verified`；Data Market 数据集发布和接收方授权检查已通过独立步骤接通，**签名导入回执及跨主机作业恢复仍待完成**。准备批准不自动生成文件，登记或本地批准也不自动解密；双方都需要显式发起操作。`verified` 不代表数据可供作业使用，不解除 `DATA_WAITING`，这仍不是完整硬盘交付。

## 来源方数据集导出准备

Server 配置 `FEDERATION_ENABLED` 及既有站点/签名配置后，同时配置：

| 配置 | 含义 |
| --- | --- |
| `FEDERATION_MEDIA_AGE_DIRECTORY` | 官方固定版本 age 和 age-keygen 所在绝对目录；工具摘要见下文 |
| `FEDERATION_MEDIA_WRAPPING_KEY` | 至少 32 字符的独立高熵密钥，不得复用 JWT/SSO 密钥；仅通过部署秘密配置注入 |

两项缺一时启动校验拒绝；均未配置时可使用接收登记，但来源导出接口返回 503 `MEDIA_EXPORT_UNAVAILABLE`。Server 镜像尚未包含 age，需要由部署方提供经 pin 校验的工具。托管密钥依赖 wrapping key 恢复，必须独立安全备份；当前无在线轮换工具，直接替换会使历史包密钥无法解密。

以下 API 均以 `/api/federation/media` 开头，要求当前组织的人工会话：

| 方法与路径 | 作用 |
| --- | --- |
| `POST /exports` | 以独立 `media.export` 权限准备指定不可变版本的签名清单及独立包身份 |
| `GET /exports?limit=50&offset=0` | 以 `asset.read` 权限查询当前组织摘要 |
| `GET /exports/:id` | 查询原签名、公钥和批准/撤销记录，不返回私钥及其密文 |
| `POST /exports/:id/revoke` | 以 `media.export` 权限撤销来源批准，保留历史；正文为 `reason` |

准备参数为 `packageId`、`agreementRevisionId`、`recipientSiteId`、`versionId`、`locationId`、`expiresAt`，有效期最多 7 天且不超过合作协议与数据授权的有效期。文件列表、大小、摘要、许可证和完整 provenance 从已发布资产的 ready/不可变版本读取，不接受调用者自报路径或清单。当前只接受本组织 Agent/启用受管目录中的 available `cp-local` 位置；不支持对象存储位置、任务输入包或结果包的来源准备。

必须存在对当前用户/组织适用、有效的显式 export 数据策略，且 download、redistribution、crossCenterReplication 三项均为 allow；兼容原来同时允许这三项的显式 download 策略。适用的禁止/限制优先。公开可见、资产所有权或普通 use 权限不能代替跨机构披露许可。CP 数据页面已有按版本配置 export 策略的入口，见下节。

每包由真实 age 生成独立身份；私钥使用现有 AES-GCM/HKDF 加密，派生域绑定本站、包编号及原清单摘要。数据库只保存密文，普通 API/审计不返回或记录密钥。签名及生成在事务外执行，落库前重查授权、源数据和签名信任；同编号并发重试只保留原签名、公钥、密文与一次审计，修改参数或重放已撤销批准被拒绝。内部使用 guard 再检查原批准人权限、有效期、当前数据策略/位置、协议和原签名密钥。机构间密钥交付端点见后文；批准后可显式发起下述 Agent 导出操作。

## Agent 实际导出操作

在来源批准已就绪后，以当前机构人工会话调用 `POST /api/federation/media/exports/:id/run`，要求独立 `media.export`；该接口返回 202 并持久排队。`GET /api/federation/media/exports/:id/operation` 以 `asset.read` 查询 queued/exported/failed、当前代次及成功密文的 SHA-256/字节数。queued 表示尚未确认导出，可能正在等待 Agent 或当前授权；应结合原批准的期限/撤销状态判断。重复发起 queued/exported 不创建新操作；failed 可显式重试，新代次拒绝旧回报。原包批准被撤销后不能借重试恢复。

来源 Agent 增加可选 JSON 配置：

```json
{
  "mediaDirectory": "/var/lib/kuintessence/media",
  "ageDirectory": "/opt/kuintessence/age/1.3.2"
}
```

该对象作为 `AGENT_FEDERATION_MEDIA_EXPORT` 环境变量的值，默认 null、不启用。mediaDirectory 必须为本机 Agent 拥有的私有目录，不能与数据集、Job 或受限材料根目录重叠；ageDirectory 提供上述固定版本官方二进制。未配置的旧 Agent 不宣称支持导出。Server 只向已验证证书、已协商 `federation_media_export_v1` 的当前连接发送命令，人工 HTTP 接口不能指定 Agent、源路径或目标绝对路径。

产物固定为 `<mediaDirectory>/outbox/<packageId>/bundle.age`，同目录 `receipt.json` 只含绑定摘要及密文 SHA-256/大小，不含完整清单或私钥。已批准清单与来源路径从 Server 原始记录读取；公钥、来源/接收站点、包和签名摘要在 Agent 核对。命令不包含解密私钥。介质、物流及接收端导入须分别执行，导出完成不自动发货或授予接收方使用权。

Server 每 30 秒轮询持久待办，按 Agent 选择任务；断线/权限暂不可用保留待办，已撤销或过期来源不新派发。Agent 的介质导出与既有联邦文件传输共用单操作槽位；忙碌返回失败，可在空闲后显式重试。执行租约最长 30 秒且受原批准和签名密钥到期限制，每 15 秒的流处理及最终发布前重查；接收不匹配的授权、明确拒绝、断线或到期会中断本次操作。授权不是瞬时召回：最后一次有效许可窗口内可能继续处理，Server 记录成功时再次检查当前权限。

加密文件先写独立临时目录，流式验证源文件、同步文件与元数据后再整体 rename 到固定包目录，最后同步父目录。已有完成目录只在原绑定及密文校验一致时复用，保留原密文字节；不同包身份或被改动的产物拒绝覆盖。空间预检包含加密/归档余量及 64 MiB 余量，不代表实际预留；实际写入/同步失败仍清理本次临时目录。普通异常与断线已验证清理，SIGKILL/宿主掉电遗留临时目录的自动回收、真实 ENOSPC 和大包吞吐尚待专项完成；不要将 `.export-*` 当作可交付包。

Drizzle 生成 `0159_secret_crusher_hogan.sql`，记录当前操作代次/状态/密文摘要。启动、重试及结果与审计同事务；普通列表/API 不保存数据字节。Server 重发待办会重新授权，Agent 可校验并复用已完成的原文件。Server 重启和跨主机真实 AgentStream 的联合恢复尚待验证，当前完成目录重用测试不等于进程崩溃验收。

## Agent 实际接收与私有校验

接收 Agent 配置 `AGENT_FEDERATION_MEDIA_IMPORT`，值与上面的导出 JSON 结构相同，默认 null。可与导出共用同一个私有 mediaDirectory；受限根目录会去重，仍禁止与数据/作业目录重叠。接收 Server 必须配置本站签名及既有机构 mTLS 发送通道，否则运行接口返回 503 `MEDIA_IMPORT_UNAVAILABLE`。接收方不需要来源 wrapping key。

将完整密文放入 `<mediaDirectory>/inbox/<packageId>/bundle.age`。inbox、包目录与目标受管根目录须属于 Agent 且为私有目录；不能以符号链接、硬链接或特殊文件代替密文。目前人工转交密文，尚无发货或物流自动化。

登记原签名清单、批准本地 Agent/目录/容量后调用：

| 方法与路径（以 `/api/federation/media` 开头） | 作用 |
| --- | --- |
| `POST /packages/:id/import-authorizations/:authorizationId/run` | `media.import` 人工会话排队；返回 202 |
| `GET /packages/:id/import-authorizations/:authorizationId/operation` | `asset.read` 查询 queued/verified/failed、代次、校验字节数和时间 |

当前运行仅支持数据集包，任务输入/结果包拒绝运行。一个授权保留一个当前代次；queued/verified 重试不重复创建，failed 显式重试生成新代次。queued 可能等待 Agent 或授权恢复；failed 需要核对原批准及磁盘状态后重试。普通 API 不返回密钥响应、明文文件或绝对磁盘路径。

后台每 30 秒扫描，要求当前 Agent 连接有已验证证书及 `federation_media_import_v1` 能力。Agent 为每次运行生成不可导出的 RSA 临时私钥，仅将公钥送入机构密钥通道。接收 Server 在网络请求前后复查本地授权，来源 Server 独立检查来源披露许可。Agent 验证来源签名、查询摘要、包/协议/授权/目录/容量及自己的公钥；解密密钥不经过普通用户 API，也不写入 Agent 磁盘。

导入与其他联邦传输共用单操作槽。租约最长 30 秒，流处理每 15 秒及最终 rename 前重新获取授权；断线、到期或拒绝中断。逐文件校验 SHA-256/字节数并 fsync，完整认证通过后整体 rename 到 `<managedRoot>/.federation-media/<packageId>/`，内含 `files/` 和原 `manifest.jws`。随后同步父目录，向 Server 报告校验结果。Server 校验当前代次、本地权限及最后一份有效来源授权，状态与审计同事务保存。

已有完整目录须与原签名清单、文件集合和摘要一致，再获取新授权才可复用；原 inbox 密文此时可以不在。篡改或额外文件拒绝覆盖。普通异常删除本次隔离目录；SIGKILL/掉电遗留、真实满盘和跨主机重连恢复尚待验证。完成目录与 Server 状态之间不是单一文件系统事务，回报失败后需要重新授权校验并回报。

Drizzle 生成 `0160_stiff_jack_flag.sql`。数据库仅保存操作状态、校验结果和最近一次 Agent 公钥加密的授权；不创建 Data Market location、资产使用许可或签名导入回执。来源使用审批与短期签名端点现已独立接通，见[跨机构数据集使用许可](dataset-use.md)。后续发布及运行仍须同时满足该许可和接收方本地策略，不能将导入/披露许可当作作业运行许可。

## 在线配置数据披露策略

在“算力提供方 → 数据管理”选择资产与版本后，可查看“跨机构数据授权”，填写有效期和原因后批准、续期或撤销。授权绑定**当前机构与所选不可变版本**，不是对所有机构的公开授权。页面保留其他适用策略及其限制；本策略显示允许，不代表其他限制失效。手机端遵守平台只读策略，中英文同步。

`GET /api/cp/data/versions/:versionId/disclosure-policy` 返回当前机构的版本策略、是否可编辑/批准、其他适用策略摘要。其他策略最多返回 100 条，`hasMorePolicies` 标识省略；实际导出校验不截断。`POST` 同一路径提交：

```json
{
  "expectedUpdatedAt": null,
  "enabled": true,
  "expiresAt": "2027-01-01T00:00:00.000Z",
  "reason": "机构间科研合作的数据披露许可"
}
```

首次批准使用 null，修改使用 GET 返回的 `policy.updatedAt`。机构由当前会话及 CP 机构选择绑定，不能在正文指定其他机构或用户。现有资产 manage 权限（含 enforce 模式的外部鉴权）仍适用；事务内重查真人、成员身份、资产归属和机构管理角色。平台角色不能越过当前机构或替代成员身份。新增/续期要求已发布、ready 且不可变的版本；撤回资产后仍能撤销原许可。已撤销策略可由管理者读到最新版本后显式重新批准；旧请求不能自动恢复许可，包自身的撤销仍不可逆。

新策略只含独立的 `export` 能力，不增加本地下载、作业使用或接收方使用权；数据使用继续走原授权系统。普通数据授权 schema 不接受 export，只有数据策略 schema 接受它。新入口不覆盖含 download/manage 等其他能力的既有策略；完整通用数据策略编辑器与私有用户数据的独立页面仍待补齐。

策略写入和审计同事务，版本/资产锁与来源导出检查串行化；相同内容重试不重复审计，不同并发修改使用 `expectedUpdatedAt` 拒绝覆盖。表单在首次编辑时固定版本，后台刷新不能将旧草稿自动套用到新策略；提交结果未知时先刷新核对。撤销移除本策略的披露许可；其他独立许可仍可能有效，不等于召回已交付数据或停止已运行任务。介质命令现通过短期租约复查权限，作业使用授权仍需单独接通。

## Server 包登记与本地授权

启用 `FEDERATION_SITE_ID` 后，已登录用户可在当前组织范围内访问以下 API；自动化身份不可使用这些人工批准入口。`asset.map` 用于签名包登记/撤销，`asset.read` 用于查询，新增独立 `media.import` 用于接收方本地批准/撤销。平台管理角色不自动获得这些能力；管理页面的权限选择已有中英文标签。

| 方法与路径（均以 `/api/federation/media` 开头） | 作用 |
| --- | --- |
| `POST /packages` | 提交 `senderSiteId`、`signedManifest`，登记接收清单 |
| `GET /packages?limit=50&offset=0` | 查询本组织包摘要，不载入/返回整份清单签名 |
| `GET /packages/:id?authorizationOffset=0` | 查看原始清单/签名、撤销记录与授权历史；每页最多 100 条，`hasMoreAuthorizations` 表示后续记录 |
| `POST /packages/:id/import-authorizations` | 明确批准指定 Agent/受管目录的本地导入 |
| `POST /packages/:id/revoke` | 撤销包的本地接收资格，历史与原签名仍保留 |
| `POST /packages/:id/import-authorizations/:authorizationId/revoke` | 单独撤销本地授权 |

登记核对当前可信来源密钥及签署用途，接收机构必须为本站，合作协议双方必须匹配且属于当前组织。包编号在本站唯一，同编号只能重放同一清单；换签也不覆盖最初原件，内容变化必须使用新编号。登记可以保留已暂停/过期合作的库存历史，但不授予任何导入权。来源密钥已过期/撤销时不能新登记，后续使用原登记包也会被阻止；旧签名历史信任迁移尚未实现。

本地批准参数为 `authorizationId`、`agentId`、`managedRootId`、`expiresAt`、`maxBytes`。有效期最多 7 天，字节上限不能小于清单总量；受管目录必须启用，并与 Agent 同属当前组织。相同授权编号重试不续期、不改目录或限额；已撤销授权不能恢复，需要显式创建新的授权编号，已撤销的包则不能借此恢复。

每次使用本地授权前，内部 guard 重新检查包/授权撤销、有效期、原批准人的组织成员身份与 `media.import` 权限、合作协议当前有效性、双方站点、原签名密钥及用途、Agent 和受管目录归属。批准/撤销与审计在同一事务内提交；并发重试不重复创建记录或审计。包撤销与授权撤销均保留原件，拒绝后续操作；正在运行的导入通过下述短期租约复查，撤权不保证瞬时停止。

这些 API 不包含密钥、密文内容或本机绝对路径，不替代来源方的当前披露授权。独立密钥通道同时检查来源方授权与这里的接收方许可；之后发布和每次作业使用仍各自检查权限。本地批准不会直接给调用者密钥。

## 机构间独立密钥通道

来源 Server 已在联邦专用 mTLS 网关提供 `POST /federation/v1/media-keys`，正文与响应均为 `application/jose`，响应禁止缓存。它不属于普通用户 API；公网应用路由没有私钥下载入口。未配置来源托管服务时拒绝发放。

接收方使用独立 `media-key-query` 签署用途，来源方使用 `media-key-grant`；已有 `media-manifest` 权限不会自动获得这两种用途，需管理员在信任配置中明确授予。查询绑定双方站点、协议、包及原清单摘要、接收批准编号、实际 Agent、受管目录、限额和临时 RSA 公钥，最长有效期 60 秒且不超过本地批准期限。来源响应还受来源批准、双方当前签名密钥和原清单签名密钥有效期约束。

内部 requester 在发送前及收到响应后重查接收方当前批准、Agent/目录和签署权限；目的地址只来自信任登记。来源 responder 核对已登记 TLS 证书、查询签名及专用用途，再查当前来源批准、数据披露政策和原清单。来源无法直接查询对方私有数据库，依赖接收机构签署声明，并由接收方服务执行本地校验。

包身份使用 RSA-OAEP-256/A256GCM 封装给查询所绑定的 Agent 公钥，再签署响应；接收 Server 得到的仍是密文。响应绑定原查询摘要与全部作用域，不接受替换目录、公钥或过期响应。RSA 仅接受公开参数、2048–4096 位和指数 65537。明文缓冲在使用后清零；JavaScript 加密库及字符串内存不提供可证明的完全擦除。

Drizzle 生成迁移 `0158_safe_tag.sql`，持久保存查询摘要及原加密签名响应。同编号重放必须使用原查询，仍重查当前来源授权和签署用途，不能借重试绕过撤权；新响应与脱敏审计在同一事务提交，审计失败不会留下可领取响应。当前未配置历史响应自动清理，过期后拒绝使用但保留记录。

requester 已连接接收 Agent 的临时密钥和导入操作；实际落盘与 Server 确认均检查授权，副本目录发布和使用许可仍待接通。合法 Agent 一旦获得密钥，撤权不能在密码学上召回该密钥，也不能收回已复制数据；只能拒绝后续受管操作与使用，不能把短响应期限当成密钥自动失效。

## 包格式

每个包对应一个不可变数据集版本、一个任务输入包或一个任务结果包。完整重制应生成新的随机 `packageId` 和独立 age X25519 身份；复用版本不复用包身份。持有包编号、清单签名或解密密钥均不等于取得导入及使用授权。

外层使用 age v1 文件格式；内部是未压缩的受限 tar 流：

1. `manifest.jws`：现有联邦 RS256 紧凑签名格式，专用 `media-manifest` 签署用途。核对来源机构、接收机构、当前密钥有效期、撤销状态与签署用途。正文仍受现有 256 KiB 签名上限约束。
2. `files/000000` 等按清单顺序编号的普通文件。原始相对路径仅存在于加密后的签名清单中；接收方验证路径后才在隔离区重建目录。
3. 两个 512 字节零块结束，不接受尾随数据或第二份归档。

清单包含来源/接收机构、协议 revision、创建时间与数据集的联邦不可变引用，或者任务 operationId、taskId、attempt、请求摘要和输入/结果内容摘要。逐文件保留相对路径、字节数、SHA-256、许可证与 provenance；许可证或 provenance 缺失时显式为 `null`，不会补写假值。后续授权服务仍须核对这些引用与实际交付单，而不是仅验证签名。

本地扫描版本保存 64 位十六进制 SHA-256，联邦数据集引用使用 `sha256:<hex>`。材料映射同时识别这两种等价表示，保留原数据库摘要和签名引用；不同摘要、重复前缀和非法表示仍拒绝。工作流本地投影使用已验证的本地版本摘要，以通过原有本地数据规划和派发校验；该兼容处理不改变数据使用许可或位置可用性检查。

当前每包最多 1000 个文件、总计 5 TiB；清单签名大小可能更早触及上限。常规 tar 八进制大小字段无法表达 8 GiB 以上文件，因此大文件使用 GNU base-256 大小字段。接收端只接受本格式的固定普通文件头；拒绝 PAX、GNU longname、软/硬链接、设备、FIFO、重复/覆盖路径、额外文件和非规范 padding。它不是通用 tar 导入器。

## 读写与隔离

导出只从已初始化的 `AgentDataRoots` 受管目录读取，拒绝链接、特殊文件、文件大小变化或摘要变化。输入使用固定大小的分块读取，输出接入 age 标准输入，不先生成完整明文归档。

导入只向当前 Agent 拥有的私有目录新建随机隔离子目录。读取清单后按本地字节限额、可用空间、文件系统块和 inode 做预检；不把预检当作容量预留，实际写入仍可能失败。逐文件流式核对大小与 SHA-256，成功后 fsync 文件。异常、取消、末尾认证失败或流关闭失败会删除本次隔离子目录；不会发布资源位置或创建计算作业。

解密输出即便已产生若干完整文件，也必须等 age 退出成功、tar 结束及所有摘要一致后才能返回隔离结果。返回隔离目录仍不是副本发布：接收操作随后复查授权并同步/整体发布私有目录，独立数据集发布再检查来源使用许可和本地策略并登记受管位置；Server 签署导入回执仍待实现。进程强制退出后的隔离目录回收及发布恢复还未接入。

age 子进程与归档流使用调用方的取消信号；生产服务需要传入操作期限/撤权信号。私钥通过 age 标准输入传递；命令参数、环境变量、介质文件和日志不包含私钥。加密用的随机包公钥保存在本机私有临时目录，操作结束删除。stderr 不向用户透传。未引入插件身份或口令交互。

## 当前验证

无需外部工具的针对性验证：

```bash
bun test packages/shared/src/federation/media.test.ts packages/agent/src/data-market/media-archive.test.ts
```

准备上述官方二进制后显式运行真实加解密验证：

```bash
KQ_MEDIA_AGE_TEST_BIN=/absolute/path/to/age-directory \
  bun test packages/agent/src/data-market/media-age.test.ts
```

未配置二进制目录时，真实工具测试明确跳过；普通单测不会下载程序。当前真实测试为 256 KiB 合成数据，覆盖真实签名、独立包身份、加密后清单不可见、完整导出/隔离导入、错误私钥、最终认证标签损坏、截断、可执行文件篡改，以及运行中取消后关闭输入流/停止子进程。TB 大小只验证 tar 编码，并由 Python 标准库独立解析 1 TiB 文件头，没有读写 TB 文件或测量吞吐。arm64 的发布资产摘要已核对，没有在 ARM 主机执行。

新增 `packages/server/src/federation/media-packages.pg.test.ts` 在独立 `kuintessence_unit_*` PostgreSQL 数据库运行：验证真实签名/HTTP 登记、组织隔离、并发幂等、独立导入权限、限额/到期/目录约束、当前权限重查、撤销后重放、审计失败回滚、数据库约束和授权历史分页。迁移 `0156_many_shiva.sql` 由 Drizzle 生成，两张表只保存清单和接收方批准，没有存储密钥或发布数据位置。
