# CI 编排与镜像交付

PR 的检查围绕同一提交运行，部署始终等待所选检查全部成功。改变测试编排不会改变软件安装、授权或生产服务的运行方式。

## 数据库测试

`bun run test:unit` 保留本地完整运行入口。CI 使用 `--shard 1/4` 到 `--shard 4/4`，按完整文件集合计算四个互斥分片。分配依据 `scripts/unit-test-durations.json` 的历史耗时，较慢文件先分配；没有历史记录的文件按一秒估算。该文件只影响分配，不决定是否发现或跳过测试。

历史数据来自 2026-11-14 的成功运行。每个成功文件会输出 `UNIT_TEST_TIMING`，可据此更新耗时；新增文件会自动进入某个分片。分片保持每文件一个 Bun 进程，片内串行，避免 mock 和模块缓存互相污染。每个 Actions job 都有独立 PostgreSQL 和 Redis，测试脚本创建随机数据库、迁移一次并在结束时删除，不连接业务数据库。

四片全部成功后，`Unit + integration tests` 汇总入口才运行一次 seed 数据库测试和 Agent 集成测试。Slurm 恢复文件包含在完整发现中，不再另跑一次。完整类型检查独立启动，不成为数据库测试的前置等待。

## 冷安装与浏览器检查

| 改动 | 检查范围 |
|---|---|
| 文档、导航、文案与 Web 源码 | 基础检查、完整 Web 单元测试、默认 Web 构建及软件门户浏览器交互，不自动触发冷安装 |
| recipe、材料、安装器、依赖锁、执行协议 | 对应冷安装、导入、环境加载、重启恢复及卸载组合 |
| Slurm/PBS 调度与作业派发 | 对应调度器和 CLI 到执行节点的运行组合 |
| 根依赖、共享执行契约、无法可靠分类的 CI 变更 | 保守运行完整相关组合 |

范围根据完整 PR diff 计算，重命名同时检查新旧路径，文件清单缺失或解析失败不会当作无改动。`workflow_dispatch` 可显式运行完整组合；`[full-workflows]` 保留完整工作流入口。

同仓库非草稿 PR 只在预览测试内执行一遍基础检查。fork 和草稿保留独立 CI。默认 Web 构建在同一 run/attempt 内作为 artifact 提供给软件门户浏览器检查；生产 Web 的 `VITE_PREVIEW_LOGIN=false` 与预览配置不同，二者不复用产物。

## 并行构建与部署

测试启动事件只允许默认分支控制器检查信任并构建六个预览镜像，没有集群凭据，也不部署。测试完成后，控制器再次检查必需 job、实时权限、标签、当前 SHA 和后续重跑状态，再读取提前构建的发布记录。

发布记录必须来自成功的默认分支 `Preview` 控制器，匹配同一测试 run、attempt、PR、SHA、控制器版本和原始镜像发布身份。镜像使用不可变 digest。记录不存在或已过期时重新构建；记录内容不匹配时拒绝复用。重试部署保留原始发布 run/attempt，不重新解释镜像身份。

## main 镜像传输

默认 `relay` 模式在 runner 启动临时 Docker Registry，先将已核对的生产镜像推入仓库，再通过 SSH 反向转发提供给目标 Docker。两端使用回环地址，目标机只访问隧道，不下载国外代码或依赖。Docker 根据本地层缓存只请求缺少的内容；首次交付仍可能传输全部层。

目标端在修改 Compose 前检查所有镜像的平台、提交、来源与层摘要。空间准备、业务部署与恢复仍由现有 `/opt/deploy/run.sh` 负责。结束或失败时关闭临时仓库和隧道。

目标 SSH 服务须允许回环地址的远程 TCP forwarding，目标机须提供 `ss` 检查实际监听地址；若监听到公网或内网通配地址，则拒绝传输。仓库 Actions variable `MAIN_IMAGE_TRANSPORT=archive` 可恢复原整包传输，仍检查归档 SHA-256 和镜像身份；失败时不自动切换模式掩盖原因。

SSH 镜像传输另有一次独立运行检查：在临时 runner 上启动受限的 SSH 端点，使用真实 Docker Registry、反向转发和镜像拉取，检查层复用和镜像身份；业务部署命令仅写入临时标记，不连接任何云站点。

耗时以 Actions 的实际 job 时长为准。分片受到最慢单个文件的下限约束；冷安装矩阵和首次镜像传输仍可能成为最长路径。
