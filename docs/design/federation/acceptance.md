# 算力联邦 V2：完整验收契约

这是实现后的验收要求，不是已执行结果。对应 [实现方案](implementation.md) 和 [评估](assessment.md)。全部必需项共同构成交付，不按阶段缩小范围。

## 验收环境与记录

使用 A、B、C 三个独立 KQ 实例与独立数据库/存储。A 发起，B 接 Slurm，C 接 PBS；另以治理身份 G 检查非成员访问。Fabric 使用真实 Peer、Orderer、PDC、Gateway 和链码，至少能验证组织之间的隔离。模拟多机构容器只能证明协议流程，不能宣称具备真实独立信任。

先使用小文件、固定输入与输出摘要、低并发和明确 CPU/内存/时间上限。简化科学软件安装在独立前缀，记录恢复命令与原路径，不覆盖真实 Spack 安装。至少一个小任务使用真实软件和调度器完成计算，另一个在空软件前缀下从离线材料安装，确认环境准备和执行均遵循声明的软件修订及目标依赖锁。

每项保存：配置与版本摘要、脱敏操作 ID、故障位置、预期与实际状态、任务/额度/证据查询结果。隐私测试的敏感探针值只进入受控测试记录，不进入公共 CI 日志。保留实际调度器 Job ID 和文件摘要；页面显示“成功”不足以证明通过。

## 协议、权限与接单

| 编号 | 操作或故障注入 | 通过标准 |
| --- | --- | --- |
| A01 | 不安装、不配置、不启动任何 Fabric 组件，A→B 执行双边直接任务并对账 | 全流程成功；Server 无链依赖导入、连接/健康探测及上链 outbox；存证状态 NOT_REQUIRED |
| A02 | B 与链断开时，A→B 发起异步存证任务；完成后恢复链 | 执行和账单不等链；证据持久化；恢复后补交且只记账一次；执行、对账、存证状态各自准确 |
| A03 | 链上模式缺 VALID、锁额未确认、gate 过期或已撤销 | 不产生新的实际执行；不自动降级为双边模式；已有有效许可任务仅在原授权范围内继续 |
| A04 | 并发重发同请求；同 operationId 换正文；B 提交接单事务后丢响应 | 原请求只有一个 attempt/预留；同 ID 不同摘要拒绝；A 保留待核对并查询，不盲目转派 C |
| A05 | 预算边界并发接单；预留后进程崩溃；账单重复回调 | 可用/冻结/已记账金额守恒，不超额、不负数、不重复扣款；单位和价格 revision 固定 |
| A06 | 在创建 Job 与绑定 attempt 的每个持久化边界终止进程 | 两者同时存在或同时不存在；恢复无游离 Job、重复派发；外部提交未知时先核对 |
| A07 | 过期/撤销证书、伪造代理头、绕过 mTLS 代理、JWS 发送方与证书不匹配 | 拒绝且无业务副作用；远端不能指定本地管理员、任意用户或组织 |
| A08 | 超限资源、未批准脚本/软件、越权数据、失效租期、未批准 URL/重定向 | 自动化不越过协议和本地权限；拒绝或等待有权审批，不以机器身份绕过 |
| A09 | 撤销未送达、接单后授权过期、取消回执丢失 | 区分已申请与已确认；提交调度器前再检查；租约/超时不被当作已停止证据 |
| A10 | direct/attested/coordinated 之间续签新 revision | 旧任务按旧约收尾，旧存证义务保留；无余额复制、跨域双花或虚构历史上链时间 |

## Workflow、软件与数据

| 编号 | 操作或故障注入 | 通过标准 |
| --- | --- | --- |
| W01 | A Workflow：B/Slurm 生成文件 → C/PBS 处理 → A 验证 | 调度器实有对应作业；依赖按顺序满足；跨站文件摘要与固定预期一致，输入/输出归属清楚 |
| W02 | 节点分别处于数据等待、软件准备、远端运行、已完成未回调时重启 Server/worker | 从持久状态续跑；不重新执行已完成脚本；完成早于订阅也不会永久等待 |
| W03 | ForEach/While 重复节点、Switch、嵌套子工作流各自在副作用前后崩溃 | 不同动态调用有独立 invocation；已选分支和修订固定；不从头执行整个 run |
| W04 | 同一 Workflow 同时含直接节点、异步存证节点和链上协调节点，随后断链 | 仅链许可依赖路径等待；无关双边路径继续；父状态不把“执行完成”当成“全部已上链” |
| W05 | 多 executor 争租约、旧 executor 恢复、checkpoint 缺失或矛盾 | 版本/fencing 防止旧执行者推进；不确定进入 RECONCILING；原 legacy run 维持原恢复语义 |
| W06 | 空安装前缀离线准备软件；缺 recipe、材料、许可证或目标依赖锁 | 完整材料能安装并按软件声明运行；缺项明确失败/等待，不隐式下载或使用未声明系统二进制 |
| W07 | 加密介质包输入错误密钥、损坏文件、路径穿越、链接、超大条目、空间不足 | 隔离区不发布半成品，无越界写入；DATA_WAITING 不计计算用量，不创建占位计算作业 |
| W08 | 同版本副本复用、包重复导入、导入后授权撤销、完整重制新 packageId | 版本和摘要一致，导入幂等；使用仍重新检查权限；介质回收与副本删除独立记录 |
| W09 | 简化软件运行后恢复真实环境 | 模拟前缀可移除，真实安装未改动；工作流重新选择真实修订可执行小任务，不把模拟结果当科学验收 |
| W10 | Agent 在调度器接受后、响应返回前立即退出；恢复时暂时阻断查询，再撤销另一任务 | 原 UUID/ID 接回作业，未确认时不重提或清理；撤销后等停止证明，恢复状态确认原收据；真实 Slurm/PBS 均验证历史记录与输出规则 |
| W11 | 准备或运行中撤权；取消成功但进程仍在、清理失败、tombstone 落库后退出、旧 epoch 撤销延迟送达 | 真正停止并完成清理前无成功确认；原命名空间的 Pod 不遗漏，重启/心跳可重试，旧轮次不杀新任务 |
| W12 | 运行中撤销协议、机构/签名密钥、身份或材料，或跨越签署执行期限；随后重启 Server、禁用联邦 | Server 自动写入取消原因并停止后续节点；未确认停止前维持 cancelling，重启继续补投；暂时后端故障不误撤权，普通任务不受影响，Fabric 故障不阻塞取消 |
| W13 | 软件在另一 Agent 安装、排队等待许可或已进入编译时取消 Job/撤销数据；Server/Agent 分别重启 | 取消送达原安装 Agent，队列不得再启动；所有安装 worker 停止获证前不提前完成 Workflow；原材料、锁与恢复记录保留，其他 Job 安装不被终止；覆盖真实 Apptainer 子进程和源码审计 |

| L03 | 单方报告、双方接受、更正、减免、争议、支付分别输入并重放 | 保留不可变原记录；各事实独立；慈善不增发积分，置换遵循封顶额度，付款不由存证代替 |
| L04 | 在 AB 的价格/用量/合同中放唯一探针值，C/G 检查公开块、args、response、event、日志、导出和查询 | 非成员没有任何明文；transient 仅到指定组织；PDC 备份同样受限；记录仍可见的交易关系元数据 |
| L05 | 缺 A 背书、仅 B 两台 Peer 背书、改变集合或机构策略；使用未获授权业务签名 | AND(A,B) 不能被单机构替代；业务批准与背书分别检查；不自动扩大集合或降策略 |
| L06 | 并发激活/退款/撤销/重新开放预留，延迟旧许可提交；用真实链观察 VALID/INVALID | 同通道跨链码读集使冲突交易失效；旧 gate 不可复用；无未锁额执行、ACTIVE 资金提前释放或双 attempt |
| L07 | 同一公共需求由 B/C 并发认领，随后撤销/重试 | 只有有效认领者能取得对应许可；无跨机构重复激活；历史 attempt 与当前状态可核对 |
| L08 | Node/Bun 用同一固定信封验签，修改字节/算法/重复字段/金额编码/过期时间 | 两个运行时判断一致；不支持的编码拒绝；旧生态包签名行为不被改变 |

## 完成判据

每个编号提供可重现步骤及通过记录，失败项注明影响并修复后仅重跑受影响范围。修改代码后按仓库约定执行 lint/typecheck 与相关测试；链隐私、提交有效性和恢复必须使用真实组件。无需用高负载科学计算代替协议验证，也不能用 SDK mock 代替真实 Fabric 保证。

通知功能不在本次范围。已执行验证见 [实现进展](progress.md)；模块测试通过不代表本清单对应的端到端场景已经完成。


## 执行 gate 的当前验证覆盖

[真实 gate 验收入口](../../../deploy/federation/fabric-execution-gate.md)覆盖 L06 的激活/激活前释放双向并发、延迟旧许可拒绝，以及私有预算并发锁额；通过实际 VALID/MVCC_READ_CONFLICT 和私有区块写入核验。C 能读取 gate 哈希但不能读取正文，A/B 原生 AND 背书缺任一方时 INVALID。另已通过生产 Node Adapter/Server Unix 客户端验证预留、释放、激活跨进程及提交响应丢失恢复，预留还覆盖 Orderer 中断；查询核对 gate 哈希和 ACTIVE 状态。Server 预留/释放的持久双签审批及源站公开激活待办已通过独立 PostgreSQL 检查（Adapter 替身），追加真实数据库/Fabric 联合入口已验证双方业务审批、私有预留/释放及公开激活的 Orderer 中断和响应丢失恢复；尚未覆盖到实际 Job/Agent 的完整流程：L06 的终态释放、重新开放和第二 attempt 尚未完成，A03 的 Server/Agent 无未授权实际执行仍须联合验证，不能将整行标记完成。市场浏览及旧唯一认领由独立入口覆盖，PR 预览仍未发布。

追加覆盖：真实 PostgreSQL/Fabric 联合入口验证 Server 执行确认待办、只有 VALID 可消费及本地暂停覆盖链确认。独立数据库测试已贯通协调源站提交、提供方接单、固定商业预留 ID、材料准备、工作流绑定及派发期限；覆盖并发不重复预留、不生成本地预算、过期拒绝与断链续期仅复用有效旧证明。后一组使用测试 Adapter 和进程内传输，并未运行 Agent 作业，不能据此将 A03、W01、W04 或 L06 标记为完成。

## 新任务预授权专项

- 默认不自动批准，两个机构各自明确授予同一已签合同版本下的策略；策略不能串组织、站点或修订，也不能改变原模板、资源、目标与数据范围。
- 任务金额、任务数和有效期边界拒绝越权；零金额任务仍计数；金额保持字符串/BigInt/numeric(38,0)，没有浮点运算。
- 两个不同任务竞争最后额度最多批准一个；同一任务并发或丢响应重试只保存一份原签名并消耗一次；正文变更拒绝。
- 提供方在无源方原签名、错签名、正文不一致或信任失效时拒绝；双方本地市场意图和实际链状态均需有效，链故障不放行。
- 市场查询期间撤销策略或签名用途，签名落库前再次拒绝；审计失败回滚签名及计数。已批准记录不因策略撤销被抹除，授权人的个人角色撤销不等于机构策略撤销。
- 人工批准保持独立归属；策略累计签署额度不代替资金账户，也不随释放或终态回补。替代策略不得重置原链上预算。
- 当前专项数据库测试不替代跨站提案投递与整条无人值守联合验收。后者须证明源方真实任务触发、提供方自动批准、双签交换、链 VALID、独立执行准入、作业与结果回传和终态收尾。

## 新提案传输专项

- 两边事先分别配置机构策略，源方仅提交一次真实任务意图；无需逐笔人工预留批准或搬运签名，生产后台完成双方签署与原签名交换。
- mTLS 接收回执只表示原提案持久保存；在提供方后台批准前，不存在提供方业务签名、不消耗提供方策略额度，不能据此执行。
- 错机构、错正文/回执、撤销证书/用途和网络期间端点变化均拒绝；提供方保存的原源方签名及接收证书可审计，策略和用户信息不传到对方。
- 丢回包、进程重启与并发只形成一份提案/批准；签名、策略计数、队列进度和审计失败必须一起回滚。租约到期后的成功或失败不能覆盖新租约或人工重试。
- 禁用发送不新签源方排队任务，仍允许提供方处理已接收提案；组织进度接口不泄露原签名/证书/token。接收、批准、双签交换和链确认分别有真实证据。


## 自动激活和首次执行确认专项

- 旧策略默认关闭；源方激活需当前市场发布权限，提供方不能获此权。仅适用于同一策略实际批准的原预留，替代策略和人工预留不能追溯升级。
- 只开启激活不生成执行确认；只开启确认须等待独立激活。双方各自取得原提交的 VALID 后才能标记初始推进完成，不把队列 committed 文本当链证据。
- 撤销、到期、原执行身份停用或停止防线阻止新动作；链查询期间撤销/租约过期不能保存迟到确认。个人授权人角色变化不撤销机构策略。
- 已有人工激活幂等复用且保留人工归属；未知或 INVALID 提交不能用新交易绕过；审计失败回滚，新动作不再消费预留额度。
- 组织 HTTP 重试要求当前人工审批、空正文和原 revision，不能抢占活租约或重置完成进度。
- 真实两站验收移除逐笔人工激活/执行确认，验证生产 worker 自动推进、各策略归属、实际 Fabric VALID，再完成轻量 Job、结果实读和终态收尾。该专项不替代市场自动发布/认领、真实科学软件或完整 Web/CLI 验收。


## 基础执行同意自动交换专项

- 两机构独立批准同文；只批准一边时等待，不产生对方签名、执行身份安装或预算。人工角色变化不撤销原签名，协议暂停/撤销和执行账户停用则阻止安装。
- 三种模式均可交换；直接/异步存证不依赖链，只有提供方一次性建立原预算；协调模式仍要求商业双签，不生成本地可花费预算、市场待办或执行 gate。
- 错机构、摘要、正文、用途、证书或等待回执绑定拒绝；网络期间状态/用途/端点变化在落库前再次核对。
- 丢响应、并发、重启和人工补入签名只保留原同意与一次安装。过期租约的成功/失败均不能覆盖新进度；审计失败回滚对签、执行同意、预算和 complete。
- GET 仅当前组织可读且隐藏租约/签名；重试仅当前有审批权真人可用，严格空正文，不能抢租约或重置完成。
- 真实双 Server/mTLS 验收移除基础执行协议的人工对签搬运，保存双方自动 complete，再验证后续自动预留/许可、轻量 Job、结果实读和终态关闭。尚不能将其等同市场全自动、科学软件或完整 UI 验收。

## 自动市场请求专项

- 发布、认领分别由各自机构明确授权，默认关闭；有委派提交权的用户可创建任务，后台按原机构策略推进，不冒充授权人的当前个人权限。
- 同一 operation 绑定同一预留与不可变公开需求；价格/合同/私有额度不进入公开市场。公开需求和私有请求的源机构、资源、期限必须一致。
- 每个策略的市场任务数/最大金额累计受限，并发或重放不重复占用；计数与预留签署权限、链上资金分开。不同请求复用需求 ID 返回冲突，保留原意图。
- received 只证明持久接收；claimed 必须来自提供方原认领 VALID，源方仍独立查链。伪造 claimed、只有 committed 文本而缺原 VALID 尝试、他人认领或需求变化都不能创建预留提案。
- 网络和链查询前后复核机构授权、原证书、端点与租约。未知/INVALID 不换交易；审计失败回滚交接和完成状态，迟到结果不能覆盖新租约。
- 真实验收只提交一次源方任务，后台完成公开发布、私有投递、认领、提案与后续自动许可。保存原策略归属及实际 VALID 尝试，再验证真实轻量作业、文件回传和终态关闭；完整 Workflow 协调编排、自动发现匹配和科学软件需另行验收。

## 普通 Workflow 协调编排专项

- 通过普通 Workflow API 提交 Federation 节点，显式选定机构策略和公开文案；平台/架构来自固定环境锁，不能把私有字段作为市场配置传入。
- 原动态调用、参数/文件快照、市场选择和准入窗口固定；重复/重启复用原操作、需求与预留，旧租约或变更原文不得新增任务或消耗授权。
- 原市场与初始许可未完成时 LEDGER_WAITING，不产生 outbound；完成后仍须真正有效链许可，不能仅用队列状态授权。之后自动委派、结果导入及下游 File 消费沿用原持久执行器。
- 父取消发生在发布前、链查询期间、签署后但尚无 outbound 时，分别阻止新发布、迟到提案或激活；已有商业批准记录本地停止意图，无需额外审批或链在线。链上资金与退款/结算状态保持独立。
- 真实验收通过普通 Workflow API 启动完整流程，保留原市场 VALID、双方执行确认、真实轻量 Jobs、自动结果导入、下游节点完成与实际下载证据；不得用手动 outbound/结果导入代替节点自身推进。

## 相同商业意图的 MVCC 恢复验收

- 确定两份已背书的相同原意图产生一笔 VALID、一笔校验码 11 的 INVALID；原失败交易和区块号保持不变。
- 只通过固定的成员 PDC 回执查询核对 recordId/digest；第三方、任意集合/记录类型、未知字段和私有字节缺失不能取得虚假成功。
- 没有人工作业或重试调用时，生产 worker 核对原回执后申请一次原意图的新 proposal；必须重新原生背书并取得新 VALID，不能只把 query 成功当成提交成功。
- 断链、进程重启、旧租约、查询或准备期间撤权与审计失败不丢失原 INVALID、不留下未授权检查点。新的检查点与核对审计同事务提交。
- 原记录缺失/不一致、非 MVCC INVALID、未知提交结果和第二次冲突不自动更换交易。显式人工复核仍可走原接口，不能更改原业务正文或复制预算。
