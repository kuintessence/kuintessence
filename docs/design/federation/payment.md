# 外部付款凭证

付款记录与用量、账单确认、合作额度结算分别保存。平台不接入银行转账，不因记录付款而增发积分、释放预留或修改余额；双方签名表示双方认可该收款声明，不能仅凭签名证明外部银行确实入账。

## 记录与更正

`commercial-payment` 绑定双方已确认的有偿合同和账单的原始 ID／摘要、原付款机构与收款机构、单位。`paymentId` 标识双方共同分配的一笔外部付款；`receiptId` 标识一次不可变声明。金额使用最多 38 位的非负整数字符串，沿用合同单位，不用浮点数。初始凭证必须为正数。支持部分付款，也保留双方确认的超额付款事实；超额不能转化为新增合作额度。

`occurredAt` 是双方声明的外部入账时间，不能晚于签署时间 `issuedAt`。`evidenceDigest` 指向双方受控保存的证明材料；协议只保存摘要，不把银行账号、流水、凭证文件或个人信息放进公共链。`salt` 为每次声明的随机盐，降低公开承诺被枚举的风险。附件的授权、保存和核验仍是双方责任，摘要本身不构成银行核验。

更正必须使用新 `receiptId`，保持原 `paymentId`、合同、账单、机构及单位，引用当前上一条凭证 ID／摘要并填写原因。新金额替换这笔付款的当前声明值，不与旧值累加；纠正误报允许新值为零。旧凭证与签名不删除、覆盖。多个真实分笔付款使用各自 `paymentId`，每笔只取当前最新凭证进行汇总。此处的更正不代表银行退款，预算退款和实际对外转账不得由它推导。

原账单及合同到期后仍可以记录历史付款；签署时须具备当前有效的机构密钥和明确的 `commercial-payment` 用途。管理员身份不自动获得签署权。单方填写／签署、双方确认、链上存证是独立状态；不能把待签记录显示为已付款。

## 私有链记录

商业链码新增 `RecordPayment(domainId, receiptId)`。完整双方签名信封仅通过 `commercial` transient 字段交给指定机构，普通参数只含随机业务编号；按合作域 PDC 和原生机构背书政策写入。链码读取已确认的私有合同和账单，核对有偿类型、摘要、单位、双方与时间，再保存原信封、凭证及当前 head。链响应仅含记录编号和摘要。

`payment-head(domainId, paymentId)` 将付款绑定到唯一账单，原生读集使并发更正竞争同一个 head。旧凭证完全重放返回原回执，不把 head 回退；同 receiptId 不同内容拒绝，过时的更正引用拒绝。私有 head／前驱缺失不能当成首次付款。`GetRecordReceipt` 支持 `payment`，仍限定集合内的商业身份，不向其他机构返回正文。

此入口不读取或修改合作预算、预留、用量、账单、结算与执行 gate。链故障也不能改变已发生的外部付款事实。Server 接线时，direct 只保存双方记录，attested 和 coordinated 对付款凭证异步存证；coordinated 的任务认领／额度锁定仍遵循原同步链许可规则，不能因付款凭证代替锁额。

## 平台审批与交换

每个机构独立授予 `payment.approve`；该权限包含合同查看，但不包含账单、结算、额度或执行审批。密钥也须明确具有 `commercial-payment` 用途。平台角色不隐含这些权限，已有密钥不自动扩权。

API 位于 `/api/federation/commercial-agreements/:revisionId/payments`：`GET` 分页查询并支持 `billId`、`paymentId` 筛选；`POST /draft` 从本站已双签的原合同／账单补全固定字段与当前前驱；`POST /approve` 批准完整同文声明；`POST /:receiptId/counterparty` 核验并保存对方原签名。请求使用人类会话和当前机构，响应禁止缓存。历史查询分别返回付款记录及本站链待办；需求方没有本站待办不表示提供方已存证。

数据库保存每次声明、双签和确认时间；`current` 只标记每笔付款的最新双方确认声明。单方审批不计为已确认。按 `paymentId` 的事务锁与唯一约束阻止本站签署竞争分支，确认、更换当前标记、审计及异步待办一起提交。旧原文和签名不覆盖；旧确认重放不恢复旧标记。待签声明不能直接改写；当前接口尚无撤销单方声明、另换正文的流程，双方需交换并核对同一份原文。

现有商业审批后台发现付款待签记录，通过双方已信任的传输身份交换已存在的签名，不代替另一机构审批。有效签名、当前密钥用途、请求有效期及 worker 租约在确认事务内复核，失去租约不能确认。直接模式无链待办；存证和链协调模式的外部付款由提供方异步存证。提交前必须确认原账单及更正前驱的私有链回执，未到达时保留待办，不能越序提交。付款存证不重新占用任务额度，也不改变执行许可。

迁移 `0173`–`0175` 由 Drizzle 生成，新增付款记录和独立权限，扩展商业审批交换与提交约束。没有银行接口，不支持凭银行回单自动批准付款。

## 当前实现与验收边界

共享格式、纯校验、私有链码、生产 Adapter、Server 审批／交换／查询和组织权限入口已实现。链码验证原签名、隔离、重复、追加更正、缺前驱和不改预算；真实商业链已验证付款和更正 VALID、同 head 并发只有一笔 VALID／另一笔 MVCC INVALID，旧凭证重放不回退。实际 PDC 写集仅含 payment/payment-head，公开区块和进程日志不含付款探针。

平台验证覆盖独立权限、原始绑定、不可变历史、并发审批、零额更正、审计失败回滚、自动交换、私有 HTTP 查询以及链回执依赖。链协调付款确认使用预签原始合同／账单的隔离数据库夹具，仅验证付款事实与链状态分离，不替代真实执行 gate 验收。Web 付款操作页面、CLI 和真实双平台付款全流程仍待完成；没有真实银行转账或生产部署。存储压力／保留删除也仍须纳入全蓝图验收。

真实链复验入口为 `KQ_FABRIC_TOOLS=<已校验的 Fabric 3.1.5 目录> bun run test:fabric:commercial`，复用已有三 Peer、Orderer、双向 TLS 和受控临时凭据。入口增加付款 Unix 客户端／Adapter 的断链和进程恢复检查；具体执行结果见[进展记录](progress.md)。
