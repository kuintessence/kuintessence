# 跨机构数据集使用许可

来源机构现可独立批准某个不可变数据集版本供合作机构计算，并经 mTLS 发放有期限的签名使用凭证。许可与具体介质包分开，因此同一版本重制介质不必复用旧包密钥，也不必把导入批准当成使用批准。直接合作和异步存证都不需要等待 Fabric 才能检查这份许可。

**来源审批/签发、接收方发布/续期和数据访问/派发限制已接通；签名导入回执也已接通，跨主机作业及运行中撤权尚待联合验收。** 新许可不会自行创建副本、解除 DATA_WAITING、发放下载凭据或启动作业。完整数据交付仍须满足来源使用许可和接收方本地策略两者，详见[介质导入](media-package.md)。

## 来源审批

在既有联邦权限管理中，向本机构真人成员授予独立 `dataset.use.approve`。导出、导入、资产映射和平台管理角色都不隐含这项权限；中英文权限名称和说明已接入现有选择器。

审批人同时必须是版本当前的资产所有者，或资产所属机构的管理者，并通过既有 Data Market `manage` 检查（包括启用 enforce 时的外部鉴权）。通用 manage 授权不能替代资产归属。离开机构、停用账号、撤销能力或失去资产管理权后，原审批不能继续签发使用凭证。机构有该独立能力的其他成员仍能撤销历史审批，避免原审批人离开后无法收回授权。

以下 API 沿用当前组织的人工会话，以 `/api/federation/media` 开头：

| 方法与路径 | 作用 |
| --- | --- |
| `POST /dataset-use-policies` | 明确批准数据版本供指定合作机构使用；要求 `dataset.use.approve` |
| `GET /dataset-use-policies?limit=50&offset=0` | 以 `asset.read` 分页读取本组织审批及撤销历史 |
| `POST /dataset-use-policies/:id/revoke` | 撤销本组织审批；正文为 `reason` |

批准正文示例：

```json
{
  "policyId": "00000000-0000-4000-8000-000000000001",
  "versionId": "00000000-0000-4000-8000-000000000002",
  "recipientSiteId": "00000000-0000-4000-8000-000000000003",
  "agreementRevisionId": "00000000-0000-4000-8000-000000000004",
  "expiresAt": "2027-01-01T00:00:00.000Z",
  "reason": "授权合作机构进行约定科研计算"
}
```

来源站点和组织从本站配置及当前会话确定；数据资产 ID、版本名称和摘要从当前不可变版本读取，不接受调用者自报摘要。协议必须属于当前组织，双方站点必须匹配且处于 active，版本须 published/ready/immutable。许可有效期不超过协议期限；没有额外七天限制，长期合作可明确批准较长期限。

同 policyId 只能重复同一审批人、范围、期限和原因；不会通过重试续期或修改。续期/改变范围须生成新 policyId，并按需要撤销旧许可。撤销保留原始记录，不能重新启用。批准和撤销与审计同事务；审计写入失败不留半成品。

使用许可只针对计算使用，不授予下载、转交或第三方再分发权。受许可材料保留原 entitlement 检查：资产所有权不代替有效使用授权，签发期限也不超过现有 entitlement 期限；撤销 entitlement 后原请求亦拒绝重放。审批不要求重新批准导出；当前适用的 use/download/derive/manage 禁止策略仍会阻止签发。文件披露和每次导入继续走各自独立的授权，不能相互代替。当前只接受有明确用户/机构归属的资产；平台公共资产没有因平台角色而获得隐式跨机构授权。

## 机构间短期使用凭证

来源 Server 在既有专用网关提供 `POST /federation/v1/dataset-use`，请求与响应为 `application/jose`，只经验证的 mTLS 通道接入，不在普通公网用户 API 提供签发入口。启用联邦和本站签名后接通，不需要 age 或 wrapping key。

在两端信任配置中分别明确授权：

- 接收机构签名密钥：`dataset-use-query`。
- 来源机构签名密钥：`dataset-use-grant`。

原 `media-key-query`、`media-key-grant` 或清单签署用途不隐含以上用途。查询绑定双方站点、policyId、协议版本、不可变资产引用，以及接收方 replicaId、Agent 和受管根目录。请求不含真实用户姓名、邮箱或原平台账号；来源依赖对方机构的签名声明，不直接读取对方私有数据库。

来源在发放和原请求重试时复查当前审批、原审批人权限、资产归属、版本摘要、禁止策略、合作协议和签名信任。响应最多 60 秒，同时受查询、政策、协议和双方签名密钥有效期限制。相同 queryId 必须保持同一请求摘要及副本范围，返回原签名且只记一次审计；变更副本、目录、摘要或过期请求被拒绝。收短密钥有效期后，不能通过原响应重放继续使用更长窗口。

短期凭证不是永久许可，也不意味着撤销能瞬时召回已经复制的文件。接收端现将来源截止时间纳入数据访问与派发租约，凭证过期后拒绝使用；现有派发和运行授权复查会取得该期限。跨主机运行中任务的撤权、调度器停止确认与副本删除仍需联合验收，当前不声称能瞬时停止所有运行中作业。

## 数据与验证

Drizzle 生成迁移 `0161_silly_living_mummy.sql`：保存来源审批和按查询编号固定的签名发放回执，保留组织归属及审计。审批人账号和原因只在来源管理 API/数据库中，不写入对机构签发的使用凭证。当前无历史凭证自动清理；归档/保留期管理仍需随完整联邦治理实现。

隔离 PostgreSQL 测试覆盖独立审批、HTTP 权限/严格正文、重复签名、作用域、撤销、权限变化、资产归属变化、禁止策略、密钥用途/期限、外部鉴权、审计回滚、密钥寿命上限和受许可材料 entitlement。提取了与数据披露共用的资产归属检查，并对原披露管理约束做针对性回归。真实 Node TLS 验证新路径、客户端证书及查询参数拒绝；共享 schema 验证凭证字段绑定。接收方真实作业和完整跨机构数据集使用尚未验收。


## 接收方发布与续期

完成介质私有导入后，接收机构的真人成员还需 `asset.map` 能力，通过以下 API 将已校验的数据登记到 Data Market：

```http
POST /api/federation/media/packages/<packageId>/datasets
Content-Type: application/json

{
  "replicaId": "66666666-6666-4666-8666-666666666666",
  "authorizationId": "77777777-7777-4777-8777-777777777777",
  "sourcePolicyId": "88888888-8888-4888-8888-888888888888",
  "name": "合作机构观测数据"
}
```

调用者不能自报磁盘路径、文件摘要或来源。Server 读取原已签署清单及 `verified` 导入代次，在机构网络请求前后复查本地导入批准、当前权限、协议、Agent 和受管根目录；取得来源独立使用凭证后，再将资产、不可变版本、文件清单、位置、结构化来源关系和审计一起提交。审计失败全部回滚。已撤销的副本不能复活，同 replicaId 重试必须保持原导入批准、政策、名称及代次。

唯一来源关系为“接收站点＋接收组织＋来源站点＋来源资产”。同一来源的版本共享本地资产；同版本只有摘要、清单及许可证/provenance 全部一致才复用，不重建版本。不同包可以登记不同受管副本；每个位置固定为原批准 Agent/根目录下的 `.federation-media/<packageId>/files`。首次提供的名称作为资产名称，后续版本不会更名已有资产。原清单及签名仍保存在介质登记中；版本和条目保留原 SHA-256、许可证及 provenance。

发布为机构内可见、受限、需要申请使用的 provider 资产，**不自动为发布人、组织成员或平台管理员授予使用权**。接收组织仍需通过现有 Data Market 申请及批准明确本地使用权；只有活动组织为接收组织的成员可申请。发布复用既有资产权限投影待办，机构管理关系与资产一同提交。结构化来源表独立于可编辑 metadata/accessMode，移除 metadata 或改为 public/open 不能绕过来源授权。普通上传、扫描导入和版本导入不能向此资产写入内容；来源披露、介质再导出与再次跨机构使用审批也不会把它当成本地自有数据。

查询和本地撤销：

- `GET /api/federation/media/datasets?limit=50&offset=0`：需要 `asset.read`，仅返回当前机构的发布编号、资产/版本/位置、续期时间、错误码和撤销状态；不返回原签名凭证。
- `POST /api/federation/media/datasets/<replicaId>/revoke`：需要 `asset.map`，正文为 `{"reason":"停止受管使用"}`；清除本地凭证并保留不可逆撤销记录及审计。此操作不删除磁盘文件，不等于介质销毁。

接收 Server 启用现有联邦签名和 mTLS 出站后自动启动续期任务，不引入 Fabric 依赖。通常每 20 秒重新申请最多 60 秒的来源凭证；临近到期时提前续期。每次领取持久化 30 秒工作令牌，进程重启可重新领取；迟到响应只有令牌仍一致且副本未撤销才可写回，提交前复查完整本地范围。网络故障只允许旧签名用到原截止时间，不能在本地延长；失败记录错误码并退避。首次发布仍要求导入批准有效，已发布数据后续使用不因导入窗口自然结束而失效，但显式撤销该包或批准会阻止使用。

单对象权限、批量候选、可用版本、可用位置及最终派发均使用同一来源校验。当前站点/密钥用途/密钥期限、协议、资产状态、版本、原导入代次、受管根和位置必须有效；派发还绑定当前组织与实际位置。数据以受限只读方式装配，派发租约不超过来源凭证及信任有效期，签发时已过期则拒绝。

Drizzle 生成迁移 `0162_lazy_wong.sql` / `0163_known_nick_fury.sql` 保存结构化来源、副本、续期令牌和原发布名称；未修改历史生成文件。签名导入回执独立记录 verified 私有接收事实，见[回执说明](media-receipts.md)；任务输入/结果介质、跨主机 DATA_WAITING 恢复和运行中撤权仍属于后续完整验收。

普通 CP 扫描也拒绝 `.federation-media` 保留目录：Server 拦截直接路径，Agent 拒绝扫描该目录、包含它的父目录或指向其内部的受管根别名，避免把外来数据重新登记为本地自有资产。正常的独立数据目录扫描和已授权只读派发仍可使用。


### 运行中的本地副本

导入数据通过签名 Sandbox 只读输入参与联邦作业，准备和运行租约都绑定实际位置；续租不允许切换同版本副本。`assertRunningDataBindings` 返回实际来源许可期限，Server 将其纳入执行许可上限；位置停用/改写、Agent 不符、来源许可到期或副本撤销均不再发放执行许可，既有独立 watchdog 负责停止并确认调度器作业。详细接线、部署要求和当前验收边界见[Sandbox 输入](media-package.md#导入数据作为-sandbox-输入)。普通非联邦作业尚不能使用该受限本地输入，不会借旧派发路径绕过持续授权。
